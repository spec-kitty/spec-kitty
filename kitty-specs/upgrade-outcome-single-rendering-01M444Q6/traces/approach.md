# Approach

- 2026-10-04 — Starting point from the kickoff steer: one exit-status authority for `upgrade`. Grounding found the exit code already has one (`UpgradeOutcome.derive_exit_code`); what is missing is ownership of the messages and the closing line. The approach became "extend the existing outcome", not "add an authority".
- 2026-10-04 — Sequence: tidy-first removal of the unreachable legacy surface-repair branch, then the outcome model, then presentation, then gate + ADR + changelog.
- 2026-10-04 — Post-spec review showed the first spec could be satisfied by one guard in the no-migrations renderer. Folded: the kind is exposed in JSON and asserted through the command entry point, and the gate forbids closing-line text and error-list assembly outside the outcome.
- 2026-10-04 — WP02 review cycle 1 rejected on one regression introduced by a planning amendment: giving commit-recovery failure its own reason stopped it flipping `result.success`, and the mission-state repair gate was still keyed on that flag, so it would run after a failed staging restore. Lesson: when a flag stops being set, list every reader of it in the work-package prompt. Fixed red-first with a positive control.
- 2026-10-04 — Closeout: a boundary-lens second opinion over the integrated diff found a text regression the per-package reviews missed (the auto-commit line vanished from text on a non-success run while JSON still reported it) and a missing exhaustiveness guard. Both folded with red-first tests; the gate was hardened against five ways around it.
- 2026-10-04 — Assessment. What worked: grounding before the spec corrected the brief ("add an authority" became "extend the one that exists"); each adversarial pass found something real (spec fakeability, an unlisted test file, the repair-gate regression, the commit-line regression). What cost time: one rejection cycle caused by a planning amendment that changed who sets a flag without listing who reads it.
