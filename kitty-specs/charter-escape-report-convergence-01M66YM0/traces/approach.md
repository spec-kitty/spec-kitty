# Approach — charter-escape-report-convergence-01M66YM0 (#6733)

- **[2026-10-30][planning] Grounded before scoping: the three-surface disagreement was reproduced live on `4.0.0rc8` (`main@512567ee`), not inferred from the issue.** One throwaway pack (one escaping `body_path`, one escaping asset `path`) showed `doctor charter-packs` reporting both, `charter status --json` reporting neither, and `charter org validate` reporting only the asset half. That table became the acceptance target (SC-001/SC-002: 1-of-3 and 2-of-3 surfaces become 3-of-3).

- **[2026-10-30][planning] Chose convergence through the existing predicates over a shared reporting helper.** A helper that formatted one finding for three commands would have been a fourth authority on "what an escape is". Instead each surface calls the predicate `#6418` already built and prints the predicate's own message, so the wording cannot drift even if the surfaces change shape.

- **[2026-10-30][planning] Kept `charter status --json`'s schema fixed (NFR-003).** The tempting move was a structured `org_layer.body_path_escapes` list to mirror the doctor. That would add a payload slot nothing renders (the defect this collector's own docstring ratchets against), so the findings ride `errors` — the channel status already prints and already uses for dangling endpoints.

- **[2026-10-30][planning] The conformance case went into a new additive table, not into the activation corpus.** `tests/charter/conformance/activation_ledger_cases.yaml` is `activation-ledger-conformance/1`, has no pack-validation section, and is owned by #6534/#6099 (on hold). Extending its schema would have been a contract change on someone else's surface; a sibling table with the same plain-data + adapter-runner discipline states the rule without touching it. Open question for the operator: fold the two tables into one file in the #6099 harness.

- **[2026-10-30][implement] Red-first was measured per surface before the production change, and re-proved half-by-half on the table afterwards.** Status: 7 failed / 2 passed (the two are the contained control and the schema ratchet). Validator: 5 failed / 4 passed (contained, empty `body_path`, discovered node). The table then showed 3 status cases red when the status fix was reverted and 2 validate cases red when the validator fix was reverted, with the contained case green both times — so the convergence claim is not carried by one half.

- **[2026-10-30][implement] The validator's finding reuses the predicate message but its own category vocabulary.** `body_path_escape` sits beside the existing `asset_path_escape` instead of adopting the doctor's `ORG_FRAGMENT_BODY_PATH_ESCAPE`, because the validator's `category` field is a snake_case vocabulary with documented, consumed values and changing the asset category for symmetry would break readers for no gain (C-002). The *rule* and the *sentence* converge; the identifier vocabulary stays native to each channel.

- **[2026-10-30][closeout] Kept the negative-space tests.** "A check that cannot run is not a check that passed" and "a refused merge must not hide the finding" are cheap tests that would have caught the two most likely regressions of this fix (a silent `except: pass`, and moving the checks after the merge for tidiness).
