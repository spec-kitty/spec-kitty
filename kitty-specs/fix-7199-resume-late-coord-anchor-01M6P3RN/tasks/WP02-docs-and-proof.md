## Objective

Make the operator-facing surface match the new rule and keep the real-CLI resume proof honest:
the recovery guide no longer frames the approved-tip advance as a first-run step, the real-CLI
resume test still drives a full refusal→resume cycle green, and the changelog fragment exists in
the shape `check_changelog_style` accepts.

## Context

- `docs/guides/how-to/recovery/recover-from-interrupted-merge.md` has the section
  `### What a first run lands before it tears down`. Its closing paragraph explains why a resume
  window is wider; it does not yet say that the proven tip becomes the tip teardown approves on
  both run kinds, which is what #7199 changes.
- `docs/api/cli-commands.md` already describes `COORD_LATE_PROJECTION_REFUSED` for both run kinds;
  no change expected. Verify, do not rewrite.
- `tests/consolidation/test_late_teardown_projection.py` drives the real CLI
  (`test_resume_projects_a_verdict_recorded_after_the_teardown_refusal`). Its resume runs a
  short-circuited phase list, so its anchor comes from the claim-time checkpoint and the test
  cannot produce the concurrency window deterministically. Keep it green; strengthen what it can
  observe.
- The changelog is assembled from `docs/changelog/unreleased/<pr>.<kind>.md` fragments since
  #6988. Read `docs/changelog/unreleased/README.md` for the required shape, and see
  `7124.fixed.md` for the house style (bold impact-first lead, issue refs, **Before:** /
  **After:** / **What to do:**, under 1,200 characters).

## Subtasks

### T006 — Strengthen the real-CLI resume proof where it is observable

In `test_resume_projects_a_verdict_recorded_after_the_teardown_refusal` (or a sibling case in the
same file, not a new module), add the assertion the change makes meaningful: the resume that
lands the window leaves **exactly one** projection commit on the target (the helper
`_RefusedRun.projection_commits()` already counts them) and the target's matrix equals the
coordination copy byte for byte. If the existing case already asserts part of that, extend it
rather than duplicating.

Do not assert anything the real CLI cannot produce deterministically (the anchor advance itself
needs a commit landing inside the run's own capture→teardown window; WP01 covers it in-process).

### T007 — Guide wording

Update the section so it says what is true after the change:

- the merge captures the coordination tip it verified; anything after it is late;
- before the branch is deleted the run projects that window, commits it and proves it landed;
- once proven, that tip becomes the tip the projection teardown gate and the branch delete
  approve — on a first run and on `--resume` — so a resume that lands a commit made after its own
  capture finishes instead of refusing a landing it just completed;
- keep the existing statements about `COORD_LATE_PROJECTION_REFUSED`, the anchorless first run
  (#7121) and the wider resume window.

Renaming the heading away from "first run" is allowed and probably right; if you change a heading,
the docs index row may be regenerated by the `ci/regen-docs-index` bot post-merge — say so in the
PR rather than hand-editing `docs/api/cli-commands.md`'s unrelated rows.

### T008 — Changelog fragment

Add `docs/changelog/unreleased/<pr>.fixed.md` once the PR number exists. Shape:

```
- **A `spec-kitty consolidate --resume` finishes after landing a coordination commit it never received instead of refusing a complete landing** (#7199, #6871). **Before:** ... **After:** ... **What to do:** ...
```

Under 1,200 characters; `uv run --frozen python -m scripts.docs.check_changelog_style` must report
0 errors. Never edit `docs/changelog/CHANGELOG.md`.
