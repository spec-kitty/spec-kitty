# Tracer: Tooling Friction

Mission: `mission-status-health-drift-ops-01M464D3` (#5776).

Append friction encountered during the mission; assessed at close. Numbering restarts at F-1 for this Mission (the previous slice's tracer has its own F-1 to F-43).

## Plan phase (2026-10-06)

- **F-1 `setup-plan --json` prints absolute host paths and commits nothing.** The JSON carries the plan, Mission and spec file paths of this host (a leak hazard if pasted into a public artefact). It scaffolded `plan.md` (`scaffold_only: true`, `plan_substantive: false`) and appended a lifecycle event to `status.events.jsonl` without committing it, so the status log is a modified tracked file until the orchestrator commits.
- **F-2 The checkout `.venv` is hand-built and incomplete.** It lacks `ruff`, `mypy` and `respx`. Consequences: `ruff check` and `ruff format --check` cannot run locally; 17 tests of the two registration gates error at collection (the test universe cannot import `respx`); four home-pin tests fail (`No module named mypy`). `make lint` runs `ruff check src/` only and `make test-fast` runs `uv run --frozen`, which re-syncs; neither is a safe local substitute. Class 4 of the baseline-red rule (stale venv); the repository's own remedy is a full sync into a scratch environment.
- **F-3 A stray `.git` at the system temporary root is still there** (the previous slice's F-34 class). Any pytest or replay run whose `TMPDIR` is below it risks the tamper check and placement tests resolving to that repository. Every command of this phase ran with `TMPDIR` in a directory whose ancestors hold no `.git`; the agent scratch directory is itself below the system temporary root.
- **F-4 `citation_check` and `event_mapping_check` print failure-shaped lines and exit 0.** `CITATION_REUSE` (a symbol cited by more than five properties) and `LIFECYCLE_TYPE_NOT_FORWARDED` are notes; reading only the text of a run, not its exit code, mistakes them for failures. New properties citing `materialize_snapshot` or `StatusSnapshot` add reuse notes.
- **F-5 `git fetch --dry-run origin` shows the tip moved without moving the ref;** the GitHub compare API gives the 133 commits and their files without fetching. Fetching moves the local `origin/main` that the cut-over guard and every merge-base use as the base (the previous slice's F-38), so it is left to the orchestrator at D-0.
- **F-6 `breaking_check.py` wants a particular layout and a lowered baseline.** The baseline root must hold `mission-status/` and `_shared/` side by side, the candidate `--root` must be a root of the same shape (a scratch copy for a spike), and a baseline of the same version refuses any bundle change (`BUNDLE_CHANGED_VERSION_SAME`). The pinned `oasdiff` comes from `install_tools.py` into a scratch directory.
- **F-7 The router `contract_tools` group is pinned by an import scan over `tests/contract/*mission_status*.py`.** A new helper module is only covered if its file name contains `mission_status`, and every new `src/` import needs a `**/<path>` entry in `ci-router.yml` in the same change; the failing test names the missing paths.
- **F-8 A registry row for a module that does not exist yet fails the corpus-trigger test.** Registrations therefore ride in the commit that creates the module, which forces every module-creating package into one dependency chain (the `built-in-corpus-suite` command in `packs.yml` is one physical line).
- **F-9 `spec-kitty glossary list` has no search flag** and prints a wide table; finding a term means filtering its output. The glossary has no entry for invocation, drift or health; the spec defines them.
- **F-10 `finalize-tasks` hazards to carry into the tasks phase** (ledger classes, no ids): owned files are filled only when empty; later manifest edits do not propagate and the command still reports success; `tasks.md` is regenerated wholesale; a literal path to a file that does not exist yet needs `create_intent` in the package frontmatter.
- **F-11 `compute_lanes` needs `PYTHONPATH=src` and an `OwnershipManifest` per package** to be run as a scratch check of the expected lanes; with explicit file lists and no directory-wide glob it reproduces the previous slice's shape.
- **F-12 The spec's own wording hid the single-listing rule in four places.** A grep for the old phrase found it in a clarification, in FR-012 step 4, in a table row that read like a heading, and in the tracer; a closing sentence of the tracer quoted it too and failed the grep until reworded.
- **F-13 `test_same_tier_uniqueness.py` and `test_corpus_blocking_home.py` are the gates that matter most for this Mission and the ones blind in this checkout** (F-2): a missing registration is first visible in CI unless the environment is synced first.

## Close-out assessment (IC-10, pre-rebase)

Written 2026-10-07 by WP10. Pre-rebase. Friction observed during the implementation, each with its remedy. Records cited are the hand-off records of `tracer-approach.md`.

- **F-14 Corpus runs from a lane worktree are wrong, not slow** (WP03, WP09). The drift read answers 500 (read directory outside the root) and the Project read shows 516 fallbacks instead of 37. Remedy: run every corpus-sized case from a shared clone of the primary checkout; put the recipe in the package prompt of every reader package.
- **F-15 The known environmental red survives every battery run** (Step 0 record): the byte-identical accept-stamp rerun fails because a stray `.git` sits in the system temporary directory, so placement resolves there. It was binned correctly in four packages, at a cost of one comparison each. Remedy: remove the stray directory on the host (operator action), or have the battery runner set a clean temporary directory.
- **F-16 The router import scan names missing globs only after a failure** (plan F-7, confirmed at WP03, WP07, WP08 and WP09 with 5, 5, 3 and 1 globs). Remedy: a read-only listing of the imports of a new reader module, run before the first commit, compared with the `contract_tools` group.
- **F-17 An out-of-map edit of the 1.1 proof module recurs in each contract package** (WP03, WP04, WP05). Remedy: make the prefix tuple one list the package extends, or put the edit in the map of every contract package.
- **F-18 Carry-forward items travel only through hand-off prose** (WP04 to WP06: CHANGELOG assertions and heading scope; WP05 to WP06: the citation fix). They were honoured, but nothing checks them. Remedy: a checklist line in the next package prompt, written by the orchestrator at dispatch.
- **F-19 A planning-contract edit after approval needs a package rejection and a repeated J-1 replay** (WP04 cycle 2, 0d070a3a1). The replay was PASS twice with the same infidelities (hand-set PATH, out-of-tree venv, no download-artifact). Remedy: when a contract description depends on a measured behaviour, measure it before the package is approved.
- **F-20 Wrap-up campsite debts have no home** (WP02 and WP03 records: a test name, two docstrings). Remedy: one running list in the tracer, appended at each hand-off, read at W-1.
- **F-21 `cutover-guard` exits 1 on the Mission's own `status_phase`** with no package diff (IC-01 ruling record). It looks like a red in every package gate. Remedy: record it once as pre-existing Mission state, as done, and resolve it before the pull request.
