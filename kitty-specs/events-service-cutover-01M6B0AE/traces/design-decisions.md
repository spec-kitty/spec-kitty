# Design decisions — events-service cut-over

- **[2026-11-01][specify] dev-setup fetches extras only.** DM 01M6B0JYP9B0CMBWRQ7TR7GBVN; the 95 MB read-service binary is CI-only (ADR D-6).
- **[2026-11-01][plan] Unpack lives in `scripts/sync_services.py`, not `kernel`.** The dead-symbol gate needs `src/` callers for `kernel` exports; only scripts and tests unpack. Digest-keyed directories make stale trees unreachable after a pin bump.
- **[2026-11-01][plan] Tool and source-layout tests are deleted, not repointed.** They test code spec-kitty-events owns; the released tools differ and lack `tools/fixtures/`. Residual: port them to events.
- **[2026-11-01][plan] Oracle reads the bundle.** `resolve(bundle/<module>) == resolve(contracts/<module>)` for both modules, verified.
- **[2026-11-01][implement WP02] Golden generators keep `--write`, behind an explicit `--root`.** spec-kitty-events' `service/README.md` regenerates the conformance and artifact goldens with core's generators (`python -m tests.contract._mission_status_*  --write`), and the Python oracle stays in core (ADR D-7). So the generators default to reading the pinned `conformance-fixtures` (read-only cache) and write only into a tree named with `--root` (an events checkout). Supersedes WP02's "drop the rewrite mode".
- **[2026-11-01][implement WP02] The test reader resolves the cache from `XDG_CACHE_HOME`, else the real home.** `tests/conftest.py` redirects HOME per worker but records the real home in `SPEC_KITTY_REAL_HOME_FOR_TESTS` and leaves `XDG_CACHE_HOME` alone; `Path.home()` would point at the empty per-worker home.
- **[2026-11-01][implement WP04] `tests (contract tools)` fetches the extras inline, not with the composite action.** `tests/ci/test_contracts_workflows.py` allows only SHA-pinned external actions in that job, and the job already inlines the packs sync for that reason. The inline pair (an `actions/cache` restore keyed `services-${{ runner.os }}-${{ hashFiles('pins/*.source.yaml') }}`, then `scripts/sync_services.py --service all --extras-only`) matches the action exactly. `tests (corpus-blocking)` and `module-tests.yml` use `./.github/actions/sync-services` with `extras-only`, which satisfies the wiring ratchet. When WP06 deletes that test, the job can switch to the action.
- **[2026-11-01][implement WP04] `pins/**` joins the `corpus`, `contract_tools` and `glossary` groups.** The reality check and its payload helper (`tests (corpus-blocking)`), the other contract tests (`tests (contract tools)`) and the torn-tail goldens (glossary shard) read the pinned extras, so a pin bump must run all three. `corpus` keeps only `contracts/fixtures/**`.
- **[2026-11-01][implement WP04] Out-of-map edit: `tests/ci/test_contracts_workflows.py`.** Its router-group equality now excludes the two retiring workflow paths and lists the pins, the sync script, the action and the test reader as router-only extras (each with a rationale). WP06 deletes the module with the workflows.
- **[2026-11-01][implement WP04] The fleet-verdict inventory change is deferred to the WP that deletes the workflows.** `scripts/ci/fleet_verdict.py::applicable_workflows` fails closed ("PR workflow inventory changed") when `PR_WORKFLOWS` differs from the PR-triggered workflow files on disk. `contracts.yml` and `mission-status-api.yml` stay on disk until WP06, so dropping them from `PR_WORKFLOWS` (and `Contracts`, `Mission Status API` from `ci-fleet-verdict.yml`) in WP04 would turn every fleet verdict and `tests/ci/test_fleet_*.py` red until then. The fleet edits (T018 fleet half, T019 fleet tests) belong in the same commit as the workflow deletion.
- **[2026-11-01][implement WP03] Inlined schemas: `bundled_schema` keeps only keys every inlined use agrees on.** The bundle inlines a shared schema at each use with its own description/x-source; readers needing a per-use key fail with KeyError rather than pass vacuously.
- **[2026-11-01][implement WP03] Corpus script preflights both extras and exits 2 (cannot) on a missing one**, so a missing fetch never reads as "rows differ" (exit 1).
- **[2026-11-01][implement WP05] The nightly compare runs the pinned native binary** with no JDK/Gradle; it escalates nothing on red, as the retired `nightly-corpus` did (follow-up).
- **[2026-11-01][implement WP08] The frozen architecture page stays in core** (ADR D-1: corrections are made in spec-kitty-events); the ADR gets no confirmation note (no 4.x convention).
