# Design decisions — honest-consolidation-txn-start

- 2026-09-28 — **#5111: the marker is written with fresh state.** The marker is written before `save_state` on the fresh branch of `_load_or_create_merge_state`, so any on-disk `state.json` implies its marker, and an orphan marker without state is harmless. The loaded and legacy-migrated branches are never stamped, so FR-012 keeps refusing genuinely pre-fix state.
- 2026-09-28 — **#5111: `clear_state` is the single clear for the transaction record.** `state.clear_state(repo, mission_id)` removes the marker too, and the filename constant moves to `state.py`. `--abort`, the #4764 not-ready clear and finalize then drop the marker by construction, instead of every caller having to remember to.
- 2026-09-28 — **#5110: mirror the real path.** The dry run catches `CoordinationWorktreeUnmaterialized` and `CoordinationBranchDeleted`, the same pair `executor.py` handles on its STATUS_STATE read, and renders `str(exc)`, which carries the remediation. With `--json` it emits the stable `error_code`.
- 2026-09-28 — **#5111: a pre-mutation exit clears the fresh record.** `_clear_fresh_record_on_pre_mutation_exit` (a context manager, `BaseException`, fresh-only) clears a fresh run's own record on any exit before the first mutation. A re-run is then genuinely fresh. A pre-existing `--resume` record is never cleared.
- 2026-09-28 — **#5111: deletion mirrors creation** (review cycle 1, B1). `clear_state` deletes the state first and the marker second, so a kill mid-clear leaves an orphan marker and never a marker-less state. `clear_state` is the only owner of that clear: finalize's duplicate `clear_post_fix_marker` and the function itself were deleted.
- 2026-09-28 — **Residual, deliberately not done: post-crash zero-progress reset (squad F6.4).** A hard-killed fresh run leaves a marked, zero-progress record. The next run auto-resumes it, not refused, with attempt-1's target, strategy and push. Only the crash path is affected. It is noted in the PR as future work.
- 2026-09-28 — **#5044 drift B: stub the teardown gate.** The fixtures fake `run_command`, so the teardown reconciliation gate cannot attribute real history. It is stubbed, appended to the patch list and never prepended, because `mocks[10..12]` are positional. The claim capture still runs for real, and the gate is covered in `tests/consolidation` and `tests/terminus`.
