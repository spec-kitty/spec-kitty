# Design decisions — consolidation-claim-rollback-integrity-01M3PD1T

- 2026-09-29 — **Refuse at claim time, reusing the gate's refusal predicate** (not a second copy): the claim's refusal is already computed in `_capture_reconciliation_claim`; acting on it inside the existing pre-mutation fresh-record guard needs no phase reordering. Exempt the `_resume_reconciliation_already_passed` (#5021) path, which deliberately skips verify on torn-down lanes.
- 2026-09-29 — **Operator decision (DM 01M3PD3VP1YTQ4D17HT96JA0T2): CAS ref restore, not revert.** A forward `git revert` leaves lane tips ancestors of the mission/coordination branch, so the next run's authored range stays empty (#5318 persists). One persisted snapshot + one CAS rollback authority supersedes AC-B3 revert-only on the rollback path; ADR 2026-09-19-1 gets the amendment (single canonical authority — no parallel ADR).
- 2026-09-29 — **Operator decision (DM 01M3PD41NQ6J6EX8V2HYDDRGPZ): #5296 refuses** rather than teaching the gate to attribute pre-landed content (that would green-wash a bypass of the consolidation window). Guard at the caller of `_merge_dependency_lane_tips`, whose internals are pinned by the destructive-op census.
- 2026-09-29 — **Scope (DM 01M3PD3NAECRSVPYZ6J5KWDTDW):** fold #5332 as another caller of the rollback authority; R1/R2 resume residuals stay out (resume-side, adjacent).
- 2026-09-29 — Mission itself uses LANES topology; no planning_artifact WP may depend on code WPs, or this mission would trip #5296 on its own target branch.
- 2026-09-29 — **Post-tasks squad folds.**
  - **Per-attempt restore targets** (`begin_attempt`): restore to the snapshot only when the attempt started from the snapshot or from consolidation's own previous post tip; otherwise restore to the attempt-start tip. This keeps an operator's lane fix made between attempts.
  - **UNCHANGED_BY_RUN**: a branch with no recorded post tip is never restored, which stops a sticky `--abort`.
  - **Reset this call's own PASS anchor before rollback**, so FR-011 protects only landings verified by an earlier attempt. Without this, a fresh #5332 rollback would be blocked by the run's own anchor.
  - **WP04 red from a real in-phase exit** (the #5385 protected-target shape), not from synthetic state.
- 2026-09-29 — **Ownership.** `finalize-tasks` accepts `executor.py` being co-owned by WP01 and WP03 because WP03 depends on WP01. The lanes then collapse WP01, WP03 and WP04 into lane-a, so the executor edits are strictly sequential.
- 2026-09-29 — **WP03 review, cycle 1.** Post tips are no longer recorded when a phase fails with a CAS refusal (`RefAdvanceError`/`RefRestoreError`), since the new tip then belongs to another actor. Recording must never mask the original exception. Proposed SC-004 wording for `recovery_guidance` (#5359-owned, to apply at closeout): "Nothing was torn down. Branches this run moved are rolled back as reported below; any branch marked NOT restored still carries this run's commits — inspect it before re-running the merge."
