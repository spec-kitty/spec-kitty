## 2. The `contracts/` Gradle precedent — exactly how to mirror it

**Files:** `contracts/build.gradle` (2940 B), `contracts/settings.gradle` (638 B), `contracts/gradle/verification-metadata.xml` (1032 lines / 63517 B), `contracts/tools/pins.json`, `contracts/tools/install_tools.py`, `contracts/tools/gradle_pin_check.py`, `contracts/README.md` (25220 B). **No `gradle/wrapper/` dir, no `gradle-wrapper.properties`, no `gradlew`/`gradlew.bat`, no wrapper jar exist** (`find contracts -name "*.properties"` → empty).

### Distribution pinning + checksum (the mechanics to copy)
- Pinned in `contracts/tools/pins.json`, entry `name: "gradle"`, `kind: "archive"`, `version: "8.14.5"`, `url: https://services.gradle.org/distributions/gradle-8.14.5-bin.zip`, `sha256: 6f74b601422d6d6fc4e1f9a1ab6522f642c2fdcbc15ae33ebd30ba3d7198e854`, plus `published` + `advisory_feed_checked` provenance strings.
- `contracts/tools/install_tools.py` (stdlib only) downloads the zip, **refuses to unpack or execute until the bytes match the pinned sha256** (codes: `CHECKSUM_MISMATCH`, `CHECKSUM_MISSING`, `NOT_HTTPS`, `UNSAFE_ARCHIVE`, `UNSUPPORTED_INTERPRETER`, `BINARY_MISSING`), then appends the tool's `bin/` to `$GITHUB_PATH`. Invoked in CI as `python contracts/tools/install_tools.py --pins contracts/tools/pins.json --dest "$RUNNER_TEMP/tools" --only gradle`.
- `contracts/tools/gradle_pin_check.py` (stdlib + PyYAML) cross-checks that the versions the build USES equal the pins: the `id 'org.openapi.generator' version '...'` line of `build.gradle`, the plugin components of `verification-metadata.xml`, a `gradle-wrapper.properties` **only if it exists** (`_check_wrapper` early-returns when absent — so the no-wrapper pattern is a first-class supported state), and every `gradle-version:` input of `contracts*.yml` workflow steps. One failure code: `GRADLE_PIN_MISMATCH`.

### No committed wrapper jar
`settings.gradle` comment is explicit: _"Invoked ... with a pinned Gradle distribution; there is no committed wrapper jar (see tools/install_tools.py and tools/pins.json)."_ CI invokes the installed `gradle` binary directly (on `$PATH`), not `./gradlew`.

### verification-metadata.xml
- Stored at `contracts/gradle/verification-metadata.xml`, 1032 lines. Schema `dependency-verification-1.3.xsd`; `<configuration><verify-metadata>true</verify-metadata><verify-signatures>false</verify-signatures></configuration>`; one `<component>`/`<artifact>` per dependency with `<sha256 ... origin="Generated by Gradle"/>`.
- **Generated, never hand-edited** (build.gradle comment: _"generated, never hand-edited"_). The canonical generation command is documented in the supply-chain toolguide (see §4): `gradle --write-verification-metadata sha256 <tasks> --no-daemon` (plus `--write-locks` only when `dependencyLocking` is enabled). README line 243 references `contracts/gradle/verification-metadata.xml` and the `gradle-version` pin together.

### JDK
- ADR + spec require **Java 25** for `acceptance-jvm` (per the 2026-10-03 amendment of ADR 2026-10-01-2). **Note divergence:** `contracts.yml` currently pins `actions/setup-java@...v6.0.1`, `distribution: temurin`, `java-version: '21'`. So `acceptance-jvm` cannot copy the JDK version verbatim — it bumps to 25.

### Is `contracts/` run in CI today?
Yes — **per-PR**, via `.github/workflows/contracts.yml` (`on: pull_request` + `push: main`, path-scoped to `contracts/**`, `tests/contract/**`, the two contract workflows, `uv.lock`, `pyproject.toml`, `pytest.ini`, `tests/conftest.py`, `src/specify_cli/status/lifecycle_events.py`). It validates/bundles/cross-checks contracts; `gradle_pin_check.py` runs at L72; Gradle installed at L130; JDK set up at L124/L327. **This is the anti-pattern for `acceptance-jvm`:** the new runner must be nightly-only (NFR-004), so do NOT create an `acceptance-jvm.yml` per-PR workflow.

## 3. Invariants that must survive (with citations)

### Packaging (sdist/wheel)
- **Wheel ships only `src/` packages + `packs/built-in`** — ADR §Packaging ("The wheel ships only the `src/` packages and is unaffected"); CLAUDE.md "Pack Tiers"; enforced by `test_packaging_safety.py::test_wheel_contains_only_known_packages` (`known_prefixes = specify_cli/, doctrine/, charter/, kernel/, glossary/, mission_runtime/, runtime/, packs/built-in/`) and `test_wheel_config_only_includes_built_in_pack_skills` (config-only twin). **The runner/scenarios never touch the wheel** — they are top-level dirs outside `src/`, so wheel tests already exclude them; no wheel assertion change needed.
- **sdist exclusion is the FR-013 deliverable.** Current sdist `exclude` (pyproject L221–225) does NOT list `acceptance-jvm`/`tests/scenarios`. Must add both. The existing packaging test has **no generic sdist-exclude assertion** — only `test_sdist_contains_no_kittify_paths` (L~155). FR-013 adds a NEW `@pytest.mark.slow` test asserting both paths are absent from the built sdist AND a positive control (e.g. a `src/` package IS present — mirror the `test_wheel_contains_templates` positive-control style).
  - Exact assertion shape to mirror (quote, `test_sdist_contains_no_kittify_paths`):
    ```python
    with tarfile.open(sdist_path, "r:gz") as tar:
        all_files = tar.getnames()
    bad_kittify_files = [f for f in all_files if ".kittify/" in f and "/src/" not in f]
    assert not bad_kittify_files, ...
    ```
  - Positive-control style to mirror (`test_wheel_contains_templates`): `assert template_files, "Wheel missing template files"`.

### ci-router group→gate model (the "gates no job" mechanic)
- **Two authorities, one parser.** ci-router.yml header (L1–30): authority #1 = dorny filter block (group→globs); authority #2 = job `if: needs.changes.outputs.<group>` (group→job). `gate_selection.load_router` parses both; `_job_gates` (L108–115) maps each job→`frozenset` of the groups its `if:` references.
- **"Gates no per-PR job" = no job's `if:` references the group.** `select_gates` (L134–163): `gated_selected = {job for job,groups in router.job_gates if groups & selected_groups}`. A group that appears in no job `if:` contributes to nothing. This is exactly how `ci` and `any_src` work today. Reference comment in ci-router.yml for the `ci` group (L~262): _"No job gates on this group BY DESIGN."_
- **Workflow (never push main):** CLAUDE.md "Git Workflow" — `main` is integration-only; open a topic branch + PR into `main`; `spec-kitty consolidate` is local-only. Branch is already `cli-acceptance-bdd-nightly-01M4NZRJ`.

### Supply-chain pinning (NFR-003)
- 100% JVM deps in generated `verification-metadata.xml`; Gradle distribution checksum-pinned; 0 wrapper jars committed. Same model as §2.

  - **Note vs spec:** the packaging TEST uses `python -m build`; the spec/ADR's `uv build` requirement (C-002) is for the CLI-under-test wheel built by the **nightly JVM runner**, a separate context. No conflict.
