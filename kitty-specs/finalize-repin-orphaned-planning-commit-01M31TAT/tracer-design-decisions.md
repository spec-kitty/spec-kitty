# Tracer: Design Decisions — Finalize re-pins an orphaned planning_commit_sha (#4827)

Seed at planning (from research.md D1–D7); append during implement.

- **DD-1 (D1)**: orphan discriminator = reachability from the **target-branch tip** + object presence. NOT lane-HEAD reachability (that is the allocator's existing no-op gate for a different question — a fresh coord lane legitimately has no common ancestor with the primary-partition planning commit, #2993).
- **DD-2 (D2/C-004)**: re-pin target = target-branch tip (same as fresh-capture + `doctor mission-state --fix`). NOT content/patch-id match — adversarially confirmed the over-merge fear does not materialize on coord/lanes topology (WP code confined to lane branches), and content-match would only diverge the four writers.
- **DD-3 (D3)**: `--allow-orphaned` is a NEW flag defaulting False; it gates the orphan re-pin. Bare `--refresh-planning-commit` keeps #4141 advance-only refusal and the "not an ancestor" substring. Foreign objects refused even with the flag.
- **DD-4 (D4)**: default no-flag path fails closed ONLY on a proven orphan against a capturable tip; degrades to historical preserve on non-git / uncapturable-tip / foreign (protects `test_issue_3311_...`).
- **DD-5 (D5/C-006)**: `_merge_recorded_planning_commit` gains a target-branch ref arg so it can classify. Detection centralized there (covers worktree_allocator :419/:482/:562 + implement_support :352). `check_claim_ancestry` (:497) and `_mt_resolve_owned_review_base` (tasks_move_task :697) reconciled to the same classification.
- **DD-6 (D6/NFR-003)**: an already-allocated lane is NOT healed to a no-op by the re-pin; its next `implement` does a legitimate catch-up merge of the live planning state (genuine conflicts stay genuine). This is correct-by-design, documented, not a separate repair.
- **DD-7 (D7/FR-010)**: fold the #4178 preserve-WARN false-positive (fires on the tool's own bookkeeping commit) + print-before-write (report after the `lanes.json` write). Same code region as the FR-009 report.
- **DD-8 (contract)**: `PlanningCommitResolution.action` gains `repinned`; envelope `CONTRACT_VERSION` 1.5.0 → 1.6.0 (additive, not test-gated).
