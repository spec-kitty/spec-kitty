# Tooling friction

- **[2026-11-07][specify] `repo_root` in `branch-context` names the main checkout.** In a linked worktree the helper reports the canonical repo root, so `agent mission create` needs `--owned-checkout <worktree>` to write here. Workaround: pass `--owned-checkout`; the resume probe has no such flag and answers for the canonical root (worked, `not_found`). Candidate gap.
- **[2026-11-07][specify] `check-prerequisites --resume-probe --owned-checkout` returns `MISSION_CONTEXT_UNRESOLVED` without `resume_state`.** Workaround: run the probe without the flag. Candidate gap.
- **[2026-11-07][implement] Draft follow-up (not filed): the #6673 tracked-meta guard costs 4 git subprocess calls per real Mission per cutover walk.** A corpus of N Missions whose `meta.json` is absent on disk costs 2 + 4N calls (`rev-parse --show-prefix`, `rev-parse --verify HEAD`, `ls-tree`, `ls-files --error-unmatch`); #7183 node 3 now pins `2 + 4 x real`. Proposal: pass the walk's already-computed `tracked` set into the guard to short-circuit the `ls-files --error-unmatch` call. Candidate gap; filing is the operator's call.
- **[2026-11-07][implement] Process finding: out-of-matrix test drift.** Every one of the 19 nodes lives in a tree per-PR CI never runs (`tests/specify_cli/cli/commands`, `tests/specify_cli/upgrade`, `tests/orchestrator_api`, `tests/integration`, `tests/specify_cli/migration`), so each contract-changing PR stayed green and only the nightly caught it; near-duplicate pairs (#7183 node 1 vs its in-matrix twin) drift when only one side is re-pinned. Candidate gap.
- **[2026-11-07][implement] `agent action implement` and `agent tasks add-history` have no owned-checkout path.** In a linked worktree `implement` cannot find the Mission (it resolves the canonical root) and refuses `--owned-checkout` (`OWNED_ACTION_UNSUPPORTED`); `add-history` has no such flag. Workaround: `next --owned-checkout --result success` hands out the WP and `move-task --note` carries the evidence. Candidate gap.
- **[2026-11-07][implement] `move-task --to for_review` runs `make test-fast` twice (baseline and candidate) inside the call, about 8 minutes per WP.** Fine for the pre-review regression gate; plan for it (run in the background). Observation.
- **[2026-11-08][accept] `spec-kitty consolidate` has no `--owned-checkout` and answers `Mission not found` from an owned checkout.** A `single_branch` Mission whose work lives on an issue branch in a linked (owned) checkout cannot be consolidated there; it resolves the canonical repository root and does not see the Mission. Workaround: land through the pull request (`accept --mode pr`) and let the merge carry it. Candidate gap.
- **[2026-11-08][accept] The WP04 implement lifecycle record stays `started`.** `kitty-ops/lifecycle/01M6W0MVXS4H3A0GGQB4K4J8MG.json` is a lifecycle record, not a profile invocation: `profile-invocation complete -i 01M6W0MVXS4H3A0GGQB4K4J8MG --outcome done` answers `Invocation record not found`. The only writer of its `completed` partner is the next `spec-kitty next --result success` call (`pair_previous_lifecycle_record`), and that call also advances the loop to the `accept` step, which would open a new `started` record instead of closing the loop. `doctor invocation-pairing` only lists orphans. Candidate gap: a closing path for the last work package's lifecycle record that does not advance the loop. Left open on purpose.
