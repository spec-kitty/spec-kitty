- **[2026-11-11][plan] `spec-commit` refuses a whole batch when one listed path no longer exists.** I renamed `contracts/next-auto-remediate.md` with `git mv` and passed the old path too. Every path in the batch was refused (`PATH_UNROUTABLE` / `WRONG_SURFACE`, "Artifact(s) not present at resolved placement"), and the message did not name the missing path. A removed path cannot be committed through `spec-commit` at all. Workaround: re-run without the removed path, then commit the deletion with git on the topic branch.
- **[2026-11-11][analyze] `spec-commit` refuses planning edits after topology settlement.** Once `finalize-tasks` settled the default Mission to `lanes_with_coord`, the topic branch (now also the coordination branch) is checked out in the coordination worktree, and the repository root checkout went back to `create_return_branch`. `spec-commit` resolves the planning placement to the repository root checkout (`worktree=/home/user/spec-kitty`) and refuses with `WRONG_SURFACE`. `record-analysis` and `finalize-tasks` commit fine through their own paths. Workaround: commit the remediation edits with git inside the coordination worktree. Follow-up: file an issue (planning edits after settlement have no canonical commit path).
- **[2026-11-11][specify] `check-prerequisites` and `setup-plan` disagree on `branch_matches_target`** for a default-topology Mission before landing: `setup-plan` names the topic branch as the target (true); `check-prerequisites` names `meta.target_branch` (false). The prompt says to stop on false. It is expected here (CLAUDE.md: PRIMARY artifacts live on the topic branch until landing), but the prompt does not say so.
- **[2026-11-11][implement] `implement` refuses while a WP's `baseline-tests.json` is uncommitted (auto-commit off), and the remedy it prints cannot work after settlement.** The printed `spec-kitty safe-commit <mission dir> --to-branch kitty/mission-…` expands the directory against the repository root checkout (finding 0 changed files). Workaround: commit the per-WP bookkeeping (`baseline-tests.json`, `review-cycle-N.md`) with git in the coordination worktree. Same root cause as the `spec-commit` entry above.
- **[2026-11-10][op→specify] `spec-kitty dispatch` refused with `ROUTER_AMBIGUOUS`.** The token "fix" matched both `java-jenny` and `python-pedro`, although the repository is Python and the request named Python files. - **[2026-11-10][op] Op records are committed unsigned and without the co-author trailer.** `profile-invocation complete` commits `kitty-ops/<id>.jsonl` itself (`op(<profile>): <action> [<id8>]`), unsigned and with no trailer the project requires. - **[2026-11-11][implement] With auto-commit off, lifecycle commands leave Mission bookkeeping uncommitted.** `agent action implement` stages claim provenance (`meta.json` VCS lock, WP `base_commit`). `move-task --to for_review` writes `tasks/WPxx-*/baseline-tests.json`.
