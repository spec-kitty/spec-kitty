# Mission Specification: Documentation Project - Context docs refresh (audience profiles first)

**Mission Branch**: `kitty/mission-context-docs-refresh-01M7AN3N` (lands on `issue-7522-context-refresh`)
**Created**: 2026-11-13
**Status**: Draft
**Mission**: documentation
**Input**: Issue #7522, a section sub-issue of epic #3891: an editorial and content refresh of `docs/context/` (40 published pages), with the audience profiles done first.

## Documentation Scope

**Iteration Mode**: `gap_filling`. The section exists; the #7520 staleness audit lists what each page lacks. (Decision `01M7AN6Q8X5R06DY5G9KC48JVV`.)
**Target Audience**: Contributors and agents who write or review Spec Kitty documentation and code, and evaluators who read the concept pages. Each page names its own reader from `docs/context/audience/` in its `audience:` frontmatter.
**Selected Divio Types**: Explanation (persona and concept pages), Reference (glossary-convention and identity-field pages), How-To (the Contextive page), Hub (section indexes). The refresh keeps each page's declared type and removes mixed-type content; it adds no new page.
**Languages Detected**: Python (the CLI the pages describe). No API reference generator applies: the pages are hand-written prose checked against the CLI and source.
**Generators to Use**: None. Diagrams render at build time (Mermaid, PlantUML) through the docsite toolchain.

### Gap Analysis Results

**Existing Documentation**: 40 published pages under `docs/context/`, listed with their gaps in the #7522 audit comment (generated by `python -m scripts.docs.staleness_audit`).

**Identified Gaps** (from the audit, measured on the #7617 branch):

- 37 of 40 pages name no reader.
- 10 pages carry an `updated` date over 180 days old, 11 are 90 to 180 days old.
- 3 pages still name a retired surface the docs gate tracks (`identity.md`, `orchestration.md`, `team-kitty.md`: 11 burn-down pairs for #7522).
- 1 page has a text-drawn diagram (`contextive-glossaries.md`); 5 pages carry a missing path or command reference.
- The audience profiles predate 4.x (persona metadata says "architecture 2.x").

**Coverage Percentage**: 3 of 40 pages (7.5%) name a reader today.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - A doc author picks the right reader (Priority: P1)

A contributor or agent (for example `comms-cleo`) about to write or review any Spec Kitty page opens `docs/context/audience/` to choose the reader the page is for.

**Why this priority**: every other doc section writes to these profiles (#3891). A wrong goal or stale vocabulary in a profile spreads to every page written for it.

**Independent Test**: for each of the ten profiles, a reviewer can trace each goal, vocabulary item and question to how Spec Kitty 4.x is used today (current CLI commands and concepts), and finds no retired surface or 2.x-only term.

**Acceptance Scenarios**:

1. **Given** an author writing a page for evaluators, **When** they read `external/tech-lead-evaluator.md`, **Then** the profile's questions name 4.x concepts (Missions, work packages, lanes, review, `consolidate`) and no retired command.
2. **Given** the audience hub, **When** an author opens it, **Then** it lists all ten profiles, says how to name one in `audience:` frontmatter, and links each profile.

---

### User Story 2 - A reader resolves an overloaded term (Priority: P2)

A contributor or agent reading `CLAUDE.md` follows a link to `orchestration.md#primary-partition`, `#routing` or `#residue`, or to `execution.md` / `topology.md`, to learn which sense of an overloaded term applies.

**Why this priority**: these anchors are linked from `CLAUDE.md`, `AGENTS.md` and other docs; a wrong definition there misleads every agent session.

**Independent Test**: every linked anchor still resolves; every definition, command and code path on the four pages is checked against the current source and CLI.

**Acceptance Scenarios**:

1. **Given** a link to an existing anchor, **When** the reader follows it after the refresh, **Then** it lands on the same term (no renamed anchor without a redirect).
2. **Given** `team-kitty.md`, **When** a reader looks for the hosted commands, **Then** the page says they were removed from open-core in #6164 and names no retired surface.

---

### User Story 3 - A reader trusts the rest of the section (Priority: P3)

A reader opens any other `docs/context/` page (charter, governance, identity, mission types, testing taxonomy and the rest) and finds claims that match the code, a named reader and a current `updated` date.

**Why this priority**: lower reader traffic than the profiles and the footgun pages, but the same staleness.

**Independent Test**: the regenerated staleness inventory lists every page with a reader, no retired surface and no text-drawn diagram.

**Acceptance Scenarios**:

1. **Given** the regenerated audit, **When** it is filtered to `context/`, **Then** no row shows `**none**` as reader and no row lists a retired surface.

### Edge Cases

- A claim cannot be verified against the code: it is kept, flagged to the operator with what was found, and not rewritten.
- A profile looks obsolete or one seems missing: the change is proposed to the operator, not made.
- A heading change would rename a linked anchor: the heading keeps its anchor, or a redirect covers it.
- A page explains a retirement in prose (for example the Zeitgeist history): it may describe the retirement where the gate allows it, but names no retired identifier the gate tracks.
