# Design decisions trace: docsite-scaffold-01M6DGT1

Append-only, newest last.

- **DD-01 Native exclusion, no shim.** doc-kitty's `exclude` (doc-kitty #247/#252, ADR-0070) replaces the spike's `content.config.ts` filter. #6929 verified the excluded trees need no frontmatter backfill with it. The loader must not get `exclude`/`indexBasename` (it reads them from the integration).
- **DD-02 One exclusion authority.** `astro.config.mjs` reads `site/dockitty-contract.json`, generated by `scripts/docs/site_contract.py` from `_dockitty_contract.py`; a parity test fails on drift. Alternative rejected: a hand copy in the config (second authority, the #2476 hazard class).
- **DD-03 Diagrams off.** `diagrams: false` until #6936: doc-kitty's build mode fails without a PlantUML server and auto-detects build mode wherever Chromium exists, so `true` would make local and CI builds differ.
- **DD-04 No redirects.** No Astro `redirects` and no `legacyHtmlRedirects` (#6933); doc-kitty #253 makes `.html` keys fatal on static output.
- **DD-05 pnpm 10.28.** The toolchain the #6929 build used; the build-script allow-list is `pnpm.onlyBuiltDependencies` (`esbuild`, `sharp`). doc-kitty itself is on pnpm 11; a move is a later bump.
- **DD-06 Build only in CI.** The D-11 gates (`validate-frontmatter`, `check-links`, redirect coverage, broken links) are red on the tree today and owned by #6931/#6933/#6937. The `--astro-config` rule is pinned structurally so they cannot be added without it.
- **DD-07 Not required yet.** `docs-site` stays out of `router-gate.needs` (#6937).
- **DD-08 HTTPS lockfile repo.** `site/pnpm-lock.yaml` names `https://github.com/spec-kitty/doc-kitty.git` (what pnpm writes when its public-repository probe succeeds, as on GitHub's runners), so `pnpm install --frozen-lockfile` needs no SSH key or token (ADR D-2, NFR-001). See tooling-friction.
- **DD-09 Advisory to router-gate, not merely outside `needs:`.** Found in WP03: `router-gate` classifies every jobs-API row of the run (#4208), not only its `needs:`, and `test_dual_mode_contract.py` pins `needs == every non-gate job` for exactly that reason. A job merely left out of `needs:` would still block the gate on failure, and could read as incomplete while running (false red). Honouring #6930 ("not in router-gate's `needs:` yet") therefore needs `scripts/ci/router_gate.ADVISORY_JOB_NAMES` (one entry, the docs-site display name): the classifier skips those rows and the invariant subtracts the same set. Priced debt per Standing Order #5: issue #6937, owner the operator, exit when #6937 adds the job to `needs:` and deletes the entry; `test_every_advisory_name_is_a_router_job_outside_router_gate_needs` forces that. Alternatives rejected: putting the job in `needs:` now (makes it required, against #6930/#6937) or a separate workflow (against ADR D-11 and the single router authority).
- **DD-10 Advisory on both halves (WP03 review cycle 1).** DD-09 covered only router-gate. The CI Router *run conclusion* is read by the fleet verdict (`fleet_verdict.classify` reds any failed run), the main-branch P0 intake (`fleet_main`) and skip-if-green (`green_match`, success only); a failed docs-site build would turn all three red, and on `main` (full mode) file a P0. So `docs-site` carries job-level `continue-on-error: true` (the `ci-aggregate.yml` `sonar-pr` precedent), never step-level; `test_job_level_continue_on_error_is_exactly_the_advisory_set` ties it one-to-one to `ADVISORY_JOB_NAMES`, so #6937 removes both. Option (B), a deliberately red-visible advisory job, was rejected: it would file P0s on `main` for a job the operator ruled not yet required.
