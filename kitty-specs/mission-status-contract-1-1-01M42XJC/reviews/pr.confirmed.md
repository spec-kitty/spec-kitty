## PR-CONTRACT-001 - severity 3 - Root status records are excluded by exact-case name, so a case-variant path reads them on a case-insensitive host
- evidence: data-model.md 'Eligible file': eligible = not the root-level status.events.jsonl or status.json (exact names, root only); spec.md:165 states the case rule for listings only; contracts/mission-status/paths/missions_missionId_artifacts_content.yaml and responses/ArtifactNotFound.yaml: the two root records 'are not artifacts' and are answered 404, with no statement of how names are compared; tests/contract/_mission_status_artifacts.py:55 and :292 (ROOT_STATUS_FILES membership is a case-sensitive string compare on the request path); contracts/mission-status/CHANGELOG.md: 'Raw log rows are never forwarded' (the stream guarantee the exclusion protects)
- failure scenario: ArtifactPath accepts Status.Json or STATUS.EVENTS.JSONL. The eligibility rule compares the request path to the two names byte-for-byte, so such a path is eligible. The contract itself says several behaviours depend on the serving host. On a case-insensitive file system (macOS and Windows defaults) the open resolves to the real status record, and the raw event log is served as an ordinary artifact. Only host paths and e-mail addresses are redacted from it. That breaks the CHANGELOG guarantee that raw log rows are never forwarded and the 404 promise for the two records. The listing is unaffected because it shows real names. Linux CI cannot see this.
- remedy: State in the getArtifactContent description, the ArtifactNotFound response and the ArtifactPath description that the two root record names are matched without regard to case. Change is_eligible in tests/contract/_mission_status_artifacts.py to compare the single-segment path casefolded. Add a planted Status.JSON case to test_mission_status_artifacts.py that expects 404.
- R2: The contract and spec AD-5 say 'exact root-level file name' with no case rule; is_eligible tests `path in ROOT_STATUS_FILES` byte-for-byte and ArtifactPath accepts Status.json (read code and schema). Not reproducible on this Linux host (needs a case-insensitive FS), but the mechanism is concrete and breaks the 'raw log rows never forwarded' guarantee; no recorded ruling covers it.
