The plan therefore states the dependency per work package and the **expected computed outcome** (section "Lanes: the expected computed outcome"), names no lane letter and no manual merge, and leaves the final lane assignment to `/spec-kitty.tasks` (finalisation).

Deliver the additive slice ("1.1" is the working name of this slice, not a version) of the Mission Status contract: three new operations (`getWorkPackageDetail`, `listArtifacts`, `getArtifactContent`) and the schemas, parameter, responses and examples they use, all new files under `contracts/mission-status/`, plus the index entries, the path map, the unchanged version `1.0.0-SNAPSHOT` and the CHANGELOG additions in its existing section. Prove it three ways: a test-tree **reference reader** that implements the rules well enough to build all three reads over this repository's own Missions and over synthetic repositories; a **reality-check extension** that runs it over every Mission with examined-equals-discovered floors, controls and leak scans; and an **additive proof** against the contract tree on `main` (breaking check over a scratch baseline with a lowered version, byte identity, bundle comparison, scope function, planted negatives; no version-bump assertion). Extend the shared contract tooling only as FR-015 states. No file under `src/` changes.

Technical approach in one paragraph. The reader is two helper modules beside the #5581 projector (`_mission_status_artifacts.py`, `_mission_status_detail.py`) over public readers, with an injectable file-system seam and an explicit host capability so every failure and every git state is constructed, never discovered. The corpus run passes a host without worktrees, so `changeState` is `unknown` and `worktreePresent` is `false` by construction. The artifact-path rule is one predicate (`malformed_artifact_path`), stated in the spec, in the `ArtifactPath` schema pattern and in the scanner, and tested three ways against each other. The new tests run in the router job `tests (contract tools)`; the corpus extension runs in `tests (corpus-blocking)`. No new CI job. Where the work lands in lanes and wrap-up steps, and which evidence is final, is stated under "Lanes: the expected computed outcome" and "Wrap-up checklist".

## Upgrade chain, migration impact and reflexivity (d)

**Upgrade and migration chain impact: none.** No file under `src/` changes, so no migration, upgrade step, template, agent command copy, skill or schema version moves; nothing is installed into a consumer project (`contracts/` is outside the wheel).

**Reflexivity: Missions in flight when this lands.**

1. **Runtime.** Unchanged; the contract describes a service that does not exist yet.
2. **CI coupling.** The reality check already reads every Mission on every corpus-selected PR. After this lands it also builds the three new reads for every Mission and every work package, so a data defect in an unrelated Mission can redden a stranger's PR. Mitigation as in v1: a failure naming a Mission the PR does not touch is classified first (contract gap, reader defect or data defect); the output names the Mission, the work package or file, and the rule. Known data facts are handled by design, not by exclusion: duplicate work package ids (D-P6), 168 unparseable cycle files (null members by AD-13), the 7 refused files (named in the fixture).
3. **This Mission is part of its own corpus.** Its own directory (spec, plan, research, contracts notes, tasks, reviews, status log) is read by the new reads once merged. The plan therefore keeps this directory free of anything the reads refuse: no credential, no NUL, valid UTF-8, no file over 256 KiB, no symlink, no yaml-fenced block in `contracts/*.md` (the round-trip gate collects those), and no text the human leak patterns flag. That last claim is checked, not assumed: `leak_patterns.leak_codes(line, HUMAN)` over every line of every file of this directory (`reviews/`, written by the review phase outside this plan's edit scope, and the status log excluded) returns **zero hits** at this revision (13 files, the scan of the plan fix). The one example that used to trip the e-mail pattern, a retina-style image file name holding an at sign, is described in words in the Mission files, never typed as a literal; a scan fixture that needs such a name builds it at run time from fragments.
4. **Readers that write.** The corpus fingerprint (bytes plus, new, directory names) is equal before and after the run; the reader's file-system seam records no write mode (D-P12).
5. **Reader drift is not selected before merge** (accepted, as v1): a PR that edits a status reader selects module shards, not the corpus job; the push-to-`main` run catches it.
6. **History.** The branch head is a merge of `main`. The wrap-up rebases onto upstream `main` (W-6; no tag; the version line is not edited by this Mission, so the conflict of research R-7 is at most the CHANGELOG section); W-7 then re-verifies every cited symbol (research R-12 is a script-checkable list), re-measures the floors and repeats the comparison against the main tree. Evidence recorded before W-6 is pre-rebase evidence and is never cited as final.
7. **`kitty-specs/` is archive-frozen.** This Mission modifies no file already on `main`; its own files are add-only on the branch.

### Lanes: the expected computed outcome

**Lanes are computed, not chosen.** `compute_lanes` (`src/specify_cli/lanes/compute.py`) works in this order: work packages whose `execution_mode` is `planning_artifact` go to `lane-planning` (the repository root checkout); among the code work packages, **rule 1 unions every pair whose `owned_files` overlap** (`_globs_overlap`: equal globs, or the wildcard-stripped prefix of one glob is a string prefix of the other's, so a directory glob such as `tests/contract/**` overlaps every file under it); **rule 2** (shared surface keywords in the work package body) merges only pairs whose ownership is not provably disjoint, and `_are_disjoint` uses the same predicate as rule 1, so with an ownership manifest on every work package rule 2 adds nothing beyond rule 1; **dependencies only become edges between lanes** (`depends_on_lanes`), and the resulting lane graph must be acyclic (`LaneDependencyCycleError` otherwise).
