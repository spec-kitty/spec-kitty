# Contract: the tool extension (FR-015), the reference reader and the test map

Internal contract between the work packages of Mission `mission-status-contract-1-1-01M42XJC`. It fixes names, signatures and stable codes so every work package works from one agreed set. An implementer may refine a name but keeps every rule here, or report the change in the hand-off report; the orchestrator records it in `tracer-design-decisions.md` (a work package never writes under `kitty-specs/`: plan, "Record-keeping and write scope"). Plain text fences only (the corpus round-trip gate collects `yaml` fences of this directory).

## A. The four tool files of FR-015 (the whole edit set under `contracts/tools/`)

- `KINDS` and `_plant` gain 25 kinds, every plant built from fragments at run time (no leaking text in source), each next to a clean control on the same root, as today. **22 are red-first** (undetected by the unchanged scanner: run on the planning base for the ten strict-name plants, which need the new `STRICT_FIELDS` entries, and for all twelve artifact-path forms, none of which the human scan reports) and **3 are regression controls** (see the table; they pass on the planning base and are not counted as red-first):

  Why the third family is labelled this way (research R-15 measures which kinds the unchanged scanner already detects, which gives the split of 22 red-first kinds and 3 regression controls): a key named `content` or `title` is already human text, so a host path, an e-mail address or a token under it is found today by both passes of the unchanged scanner (run on the planning base: `EMAIL` and `HOST_PATH`, `SECRET`, `SECRET`). These kinds would still pass if the FR-015 edit were reverted. They are kept because the artifact-path edit changes how `path` and `artifactPath` are judged, and a wrong edit (one that applied the new class to every string, or masked a whole line) would blind the human scan for these keys: the three kinds fail then, so they guard the edit. The per-endpoint planted pair that **is** red-first lives at reader level (below).

  The control of every artifact-path kind holds the legitimate odd names of AD-19: a name with a `home/<x>/` directory segment, one with a space, one with an accented letter (all verified clean in both passes on the planning base), **and a name with an at sign built at run time (OD-4 is decided: the scoped text pass)**. No committed file under `contracts/`, examples and committed controls included, holds an at-sign path (a YAML file cannot be built at run time); under the option not chosen (OD-4 Y) the same would hold for every file, because the raw-text pass reports it as `EMAIL` (verified: the e-mail pattern matches a retina-style image name, a stem, an at sign, a scale factor and an extension; a scan fixture that needs one builds it at run time from fragments); the at-sign name is proved by the run-time-built scan tests (WP02) and at reader level. A scan that flags a control name fails its own control (`CONTROL_FLAGGED`).
- **Plant shape (changes `fixture_builder.py` beyond the kind list).** Today `_plant` returns one `(field, value, codes)` and `build` writes a flat mapping, so it cannot put a value under `entries[0].path` or give each kind its own control. The new contract: `_plant(kind)` returns a `Plant(fragment, control_fragment, field, codes)`; `fragment` is a nested document fragment deep-merged into the planted document (a top-level `id: <value>` and `entries: [{path: <malformed>}]` are both expressible), `control_fragment` is the clean fragment deep-merged into the control document of that kind (default empty; each artifact-path kind carries the odd names above), `field` is the dotted key path reported in `BuiltFixture.field`; mappings merge recursively and lists are replaced, not concatenated. `build` writes control = base control merged with `control_fragment` and planted = base control merged with `fragment` (the `forbidden-property` kind keeps its empty base). `BuiltFixture` keeps its four fields. `run_negative_cases.build_leak` is **unchanged by design** (it calls `build` and unlinks only the planted file, so the control stays a complete clean file); `test_run_negative_cases.py` moves only through the manifest length. Tests that move: `tests/contract/test_fixture_builder.py` (the exact `KINDS` set, 33 kinds: the eight existing plus 25) and a new test that **the eight existing kinds still build byte-identically**: the two files of each old kind hashed with `blake2b` (`hashlib.sha256` is banned) against digests pinned at the start of IC-02 from the unmodified builder (this test passes before and after the edit by design, so it is not a red-first claim). The unchanged `run_self_test()` runs every kind on every `leak_scan` invocation, so a blind scanner fails loudly (`PLANTED_NOT_DETECTED`).
- The module docstring changes with the kinds. **Reader-level planted pairs (red-first, outside `contracts/tools/`):** `payload_leaks` over a built `ArtifactContent` whose body was left unredacted must report `HOST_PATH` and `EMAIL`, and over a built detail whose subtask or dependency title holds a credential it must report `SECRET`; each fails if the reader stops redacting or withholding (artifacts and detail test modules; clean twins pass).

### `leak_scan.py`

- `ARTIFACT_PATH_KEYS = frozenset({"path", "artifactPath"})`. In `_Scanner.walk`, a string under one of those keys whose ancestors hold no `x-source` or `x-derived` key is checked by `malformed_artifact_path` **instead of** the strict and human host-path and e-mail patterns **of the structured pass** (AD-19). `scan_text` is a second, independent pass: it runs the human patterns (host path, e-mail **and** `SECRET`) over every non-blank raw line of every file. **Under OD-4 X** `scan_text` takes a second argument, the text with the artifact-path value spans blanked: `artifact_path_spans(text)` composes the YAML (`yaml.compose`, scalar start and end character indexes) and returns the span of each scalar value of a key in `ARTIFACT_PATH_KEYS` reached without passing through an `x-source` or `x-derived` key; `mask_spans` blanks those characters (newlines kept, so line numbers hold); host-path and e-mail findings come from the blanked text, `SECRET` findings from the original line, so a token in a path value is still reported. JSON files and a YAML file that does not parse are scanned unmasked. A test pair proves the mask is bounded: a flow mapping line holding an at-sign `path` and a `title` with an address reports the title and not the path; an `x-source` path holding an address is reported; a token in a path value is reported; a contract example holding an at-sign path passes the whole scan; the module docstring ("nothing is exempt") is rewritten to name the masked span. **Under OD-4 Y** `scan_text` is unchanged and no contract file holds an at-sign path. The prototype of X was run on a scratch copy of the tools (research R-14). Under `x-source` and `x-derived` the key `path` is a repository path (226 occurrences) and keeps the human scan.
- `malformed_artifact_path(path) -> str | None` is the one definition of the predicate on the tooling side: it returns a stable reason (`empty`, `too_long`, `absolute`, `tilde`, `drive_letter`, `backslash`, `nul`, `line_break` (any character `str.splitlines` treats as a line break: LF, CR, VT, FF, the three information separators FS, GS and RS, NEL, U+2028, U+2029; added by WP02's review, orchestrator 2026-10-04: a line break must make the path malformed so the artifact-path mask can never hide a leak on a second line), `empty_segment`, `trailing_slash`, `dot_segment`, `dotdot_segment`) or `None`. The reference reader and `payload_leaks` import it through the existing loader (tests importing tools is the allowed direction); it lives here, inside the slice file set, rather than in `leak_patterns.py`, which is outside it. Three-way agreement is tested: this function, a literal restatement of the spec's predicate in the test, and the `ArtifactPath` schema pattern over the same table of cases.
- New finding code `ARTIFACT_PATH_MALFORMED`; the last line gains `values_artifact_path=N` after `values_all=N` (the existing last-line assertions of `test_leak_scan.py` are prefix and key-presence checks and keep passing; a new assertion covers the added key). No floor on the class in `check()` for every root (fixture roots hold no such key); the real-contract test asserts the count is positive once the examples exist.

## E. Stable test-failure messages

Every new corpus-level assertion states its examined and discovered counts in its failure text and fails when either is zero. A fault-injection test fails with `the injected fault did not fire` when its counter is zero. A mutation test fails with `the mutation was not killed: <name>` when the planted defect leaves its target test green.
