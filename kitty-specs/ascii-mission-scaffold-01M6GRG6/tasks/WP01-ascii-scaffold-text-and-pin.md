## Objectives & Success Criteria

`src/specify_cli/core/mission_creation_scaffold.py` holds `TASKS_README_TEMPLATE`, the single
core-owned scaffold text rendered into `kitty-specs/<mission>/tasks/README.md` by
`render_tasks_readme_content(planning_branch)`. It contains a U+2013 EN DASH on the
`# Work Package Prompt: WP01 – Work Package Title` line and box-drawing characters in its
directory tree. Both are non-ASCII; the en dash is additionally in
`specify_cli.text_sanitization.PROBLEMATIC_CHARS`, which is what
`spec-kitty validate-encoding` scans for.

This WP is complete when:

1. `render_tasks_readme_content(branch)` returns text whose every byte is `< 0x80`, for any
   ASCII branch name.
2. `detect_problematic_characters(render_tasks_readme_content("main"))` returns `[]`.
3. A new pin test fails when a glyph is injected into `TASKS_README_TEMPLATE` (self-mutation),
   and passes unmutated.
4. The scaffold's `history:` example uses `at:` / `actor:` — the field names the pack
   template uses — instead of `timestamp:` / `agent:`.
5. Nothing on the create/scaffold path calls `sanitize_markdown_text` (NFR-001).

### Subtask T001 - Red-first pin: the rendered scaffold is ASCII

- **Purpose**: Produce the failing test that proves the defect, before touching the
  constant. This is the ATDD anchor for the whole mission (DIRECTIVE_034).
- **Files**: create `tests/core/test_tasks_readme_scaffold_ascii.py`.
- **Steps**:
  1. Write `test_rendered_tasks_readme_is_ascii`, parametrised over
     `("main", "feature/x", "release-4.0.0")`.
  2. Assert `max(rendered.encode("utf-8")) <= 0x7F`, with a failure message that lists the
     offending lines (`[line for line in rendered.splitlines() if not line.isascii()]`) —
     match the #6579 message shape so the failure is actionable.
  3. Write `test_gate_detector_finds_nothing`: assert
     `detect_problematic_characters(rendered) == []`, importing the detector from
     `specify_cli.text_sanitization` (the gate's own authority — do not restate the
     character list).
  4. Run it and record the RED:
     `uv run pytest tests/core/test_tasks_readme_scaffold_ascii.py -x -q`.
     Expected: fails on the `# Work Package Prompt: WP01 – …` line (U+2013).
- **Notes**: the pin must read `TASKS_README_TEMPLATE` /
  `render_tasks_readme_content` from `specify_cli.core.mission_creation_scaffold`, never a
  copy of the text (C-003).

### Subtask T002 - Red-first: the self-mutation case

- **Purpose**: Prove the pin can fail, so it is a gate and not a screenshot
  (DIRECTIVE_043, `architectural-gate-non-vacuity`).
- **Parallel?**: yes — independent of T003.
- **Steps**:

     `TASKS_README_TEMPLATE` (or re-`.format` a copy) to contain U+2013 and U+2014, render,

- **Notes**: the mutation must be a *behavioural* injection — if someone later "fixes" the

## Risks & Mitigations

- **A sanitizer sneaks in at the write boundary.** Mitigation: T005's round-trip test and the
  import-absence check; the PR body states NFR-001 explicitly.
- **The pin asserts on a copy instead of the constant.** Mitigation: T002's self-mutation case
  goes red if the pin stops reading `TASKS_README_TEMPLATE`.
- **Rendered output is compared against a golden string in some other test.** Mitigation: grep
  `tests/` for the old glyph (`grep -rn $'\u2013' tests/ src/`) and judge each hit — re-pin a
  stale golden, do not delete a test to go green.
- **ASCII tree loses meaning.** Mitigation: keep the four entries, their order and the caption;
  only the box-drawing runes change.
- **Diff creep.** Mitigation: no rewording of instructions in the constant; if a line must
  change for readability, record why in the WP history.
