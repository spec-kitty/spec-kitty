# Tooling friction

- **[2026-11-01][discovery] `spec-kitty specify` scaffolds into the primary checkout, not the coordination worktree.** On a `coord` topology mission the scaffold (`spec.md`, `meta.json`, `tasks/`) landed in the root checkout's `kitty-specs/`, while `next` names the `.worktrees/<slug>-coord` mission directory as the mission dir and only `status.events.jsonl` was committed there. The scaffold was moved into the coordination worktree by hand before any planning artifact was authored. Candidate gap (no issue filed; a specify step that resolves the mission dir through the same resolver `next` uses would close it).
- **[2026-11-01][discovery] `spec-kitty charter context --include procedure:mission-wrap-up-sequence` resolves from the installed pack, but the same artifact is absent from the fetched internal pack tree.** `packs/internal/procedures/` (and the internal-pack checkout on this host's maintainer doctrine path) has no `mission-wrap-up-sequence.procedure.yaml`, so the documented fallback path does not exist and only the CLI answers. Workaround: read it from `spec-kitty charter context`.
