- **[2026-10-13][specify] D-7 Mission selection is by `missionId` only, through the resolver #5529 already uses.** The contract says the display number is never accepted, and the oracle resolves by `mission_id` (`index_missions`). One resolver means the "first unusable Mission met" ruling of #5529's WP06 review applies to all five routes. Decided in the spec (FR-001, FR-012 rows C2 to C6).
- **[2026-10-13][specify] D-8 Inbound ports: two interfaces, names provisional.** `MissionDetailQuery` (three operations) and `ArtifactQuery` (two) in `application.port.in`, beside the existing `MissionStatusQuery`; typed parameters, domain results, typed refusal exceptions. Reason: a later MCP adapter wants resources, not a growing god-interface, and a refusal that is a typed exception maps to an HTTP status in one place and to an MCP error in another. The plan may fold them; the constraint is FR-013.
- **[2026-10-13][specify] D-9 One shared Work Package file index for three routes (OQ-1).** The detail oracle skips an unusable file as if absent; `build_detail` and `build_work_package` have no handling. Three routes with three rules would disagree on whether a Work Package exists. Chosen: one index, skip, and one `wp_file_skipped` diagnostic so that neither the 404 nor the Mission page is silent. Alternative (500 on `getMission`) recorded in OQ-1; one half-written planning file would otherwise deny the page of a running Mission. Open for the operator.
- **[2026-10-13][specify] D-10 The read fence is amended per route, not only per file.** A single widened global list would let `/missions` read `tasks/*.md` without a test noticing. The amendment therefore ships per-route access sets: the three existing routes may touch none of the new classes, so #5529's intent is a ratchet for them. Each new class has a positive control in both directions (FR-011, AC-11.1, AC-11.2).
- **[2026-10-13][specify] D-11 Ten new read classes, including a content read of `tasks.md` the operator did not list (OQ-6).** [Corrected by D-36.] The read list (frontmatter, review-cycle files, a stat of spec/plan/tasks and a stat of `.worktrees/<lane>`) comes from the readiness report and the orchestrator's dispatch, not from the operator's verbatim record. The contract's subtask titles come from `tasks.md` content (`title_rows`). Chosen: TASKS_MD READ, 4 MiB, on the detail route only; alternative (null titles) recorded. Open for the operator.
- **[2026-10-13][specify] D-12 `worktreePresent` = a real lane worktree directory and its `.git` entry, both statted (OQ-3).** The oracle's `ResolvedWorkspace.exists` requires the `.git` entry; a bare directory is a husk (#1833). One stat of the directory would report a husk as present. Two stats stay inside the operator's "stat-only" ruling. Open for the operator.
- **[2026-10-13][specify] D-13 `promptMarkdown` mirrors Python's text-mode newline translation.** `FrontmatterManager.read` reads with `read_text`, so CRLF and lone CR reach the body as LF. The golden is generated from the oracle, so the Java side mirrors it rather than serving different bytes under the name "as authored". Recorded so that nobody "fixes" it to raw bytes without regenerating the golden.
- **[2026-10-13][specify] D-14 Non-boolean `includePrompt` is a 400 (OQ-2, DC-4).** #5529 treats a non-integer `pageSize` as absent, which is harmless for a page size. For a prompt the caller asked for, treating `1` as absent is a silent drop. The contract's `default` Problem makes the 400 legal without a contract change.
- **[2026-10-13][specify] D-15 Contract-fixed 500 codes carry the contract's code; the log carries the cause.** `WorkPackageDetailRefusal` allows `not_found` and `source_unreadable` only; the artifact refusals allow their seven codes. So a ledger fault on the detail route is 500 `source_unreadable` with the true `ledger_unparseable` in the diagnostic. The generic-Problem routes use the diagnostic code in the body, as #5529 does (DC-2).
- **[2026-10-13][specify] D-16 A refused Mission directory is 404 `not_found` with `path_refused` in the log (DC-5).** The coded routes cannot carry another 404 code. One client-visible code, the cause in the diagnostic.
- **[2026-10-13][specify] D-17 Extend the existing conformance generator instead of adding a module.** `tests/contract/_mission_status_conformance.py` and its test already own the golden directory and the router glob. A new corpus-marked module would need a registry entry in `test_ci_corpus_trigger_completeness.py`. The extended generator may import `src` files the router group must name; AC-14.6 decides.
- **[2026-10-13][specify] D-18 Sort by UTF-8 bytes everywhere a contract orders text.** `String.compareTo` orders by UTF-16 units and differs for supplementary characters; a collator differs again. The fixtures use `U+FF5E` against `U+1F600` and `B` against `a` so that each wrong choice is red (AC-4.2, AC-14.2).
- **[2026-10-13][specify] D-19 A symlinked `spec.md`, `plan.md` or `tasks.md` is not an artifact.** The oracle's `Path.is_file` follows links; the service never does (the contract: "a symlink is never followed"). Stricter than the oracle, recorded as a `knownDivergence` with a `path_refused` diagnostic, in the same way #5529 made the `symlink` class Java-only.
- **[2026-10-13][specify] D-20 `changeState` divergence is by design and listed.** The oracle answers `changed`/`unchanged` on a host with git and a worktree. The golden is generated under `NO_WORKTREES`; one host-capable fixture is a `knownDivergence` whose Java assertion is `unknown` (AC-10.1).
- **[2026-10-13][specify] D-21 No cache for file-derived data in v1.** The ledger keeps the cursor-keyed `ProjectionCache` of #5529. Work Package files, `tasks.md` and listings are read per request: they are small, a cache key for them is not the cursor, and a stale cache on a Mission being written is the silent-wrong-answer class. Revisit with a measurement under NFR-001.
- **[2026-10-13][specify] D-22 The Java reduction must grow (FR-020).** `WpState` has no assignment, review, subtask, actor or history members. Found by reading `domain/model/WpState.java` against `reconstruct_wp_view`. It is the largest hidden piece of work and goes first in the plan.

- **[2026-10-13][specify-fold] D-27 The read scope is an explicit input of the fence (SPEC-ARCH-001, SPEC-VERIFY-001, SPEC-ARCH-011).** A path-only, specific-first classifier makes `spec.md` PLANNING_FILE (stat only) and so contradicts the artifact routes, which must read it (also `tasks.md`, `tasks/WP*.md`, review-cycle files, `meta.json`, `lanes.json`). - **[2026-10-13][specify-fold2] D-39 The lookup is the scan of `MissionStatusService.resolve`: a readable match wins, the first fault decides only when nothing matches (SPEC-FRESH-001, SPEC-FRESH-002).** Supersedes the "stops at the first Mission met" reading of D-7. #5529's ruling of 2026-10-11 (WP06, item 1) says an id that matches no readable Mission answers by the first fault, and `resolve` records the first fault, keeps scanning and returns the first readable match. # D-entry draft (WP16 cycle 2, F1): artifact sizeBytes is a Long, scoped by a post-generation rewrite

**Decision.** `ArtifactEntry.sizeBytes` and `ArtifactContent.sizeBytes` are served as `Long`. The contract is unchanged (`type: integer`, `minimum: 0`, no format, no maximum). The mapper no longer clamps; a 3 GiB file is listed with `"sizeBytes":3221225472`.

**Why not a global mapping.** openapi-generator `typeMappings` `integer -> Long` is global; it would change every other integer member of every generated model and the served bytes of other routes. The generator has no per-member override without a contract change (`format: int64`), and the contract stays as is.

**Mechanism chosen: post-generation override.** A `doLast` on `openApiGenerate` (`services/mission-status-api/build.gradle.kts`) rewrites exactly the field, getter, setter, fluent setter and constructor parameter of `sizeBytes` in the two generated files `ArtifactEntry.java` and `ArtifactContent.java`. It fails the build when the member is present and any `Integer sizeBytes` / `Integer getSizeBytes` remains. When the member is absent (the `ContractDriftNestedBuildTest` rename mutation), it does nothing and the probe reference fails to compile, as that test requires. Rejected alternative: three hand records (`ArtifactEntry`, `ArtifactContent`, `ArtifactListing`, the last because it references the entry) in `adapter.in.http.dto` plus a `HAND_DTO_RECORDS` edit in `tests/ci/test_mission_status_api_build.py`; heavier, and it would drop the generated drift sensor for these models.

**Scope proof.** `diff -r` of `build/generated/openapi` before and after (`wp16c2-gen-diff.txt` in the scratchpad): only the two files differ, only the `sizeBytes` field, getter, setter, fluent setter and constructor parameter (`Integer` -> `Long`). No other generated model changes.

**Named edits.** `ContractDriftProbe.artifactContent()` and the pin in `ContractDriftNestedBuildTest` (`sizeBytes(1)` -> `sizeBytes(1L)`); `ArtifactMapperTest` clamp test replaced by two true-size tests; `ArtifactControllerTest` gains a 3 GiB sparse-file listing test. `HAND_DTO_RECORDS`, the models list, `jacoco-class-floor.properties` (domain=121, application=131, recounted) are unchanged.
