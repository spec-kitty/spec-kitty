# Design decisions — single-branch-topology-honesty-01M3M22V

- 2026-09-28 — "Repo-root checkout" (decision item 1) is read as the mission's **write checkout** (repo root or validated owned checkout, ADR 2026-09-03-1) so PR #5009's owned-checkout lifecycle is absorbed, not regressed. Source: alignment squad.
- 2026-09-28 — "Protected" is resolved only via `ProtectionPolicy` (ADR 2026-06-21-1); an explicit config list replaces the defaults there, so the decision's "primary + configured" wording is met by the default config. No second authority.
- 2026-09-28 — The pr-bound-but-coord-unreachable create arm also defaults to `lanes`: the decision says single_branch only comes from explicit requests. Answers #2602.
- 2026-09-28 — Lane presence for topology derivation/corroboration means **code lanes**: a repo-root lane is "no lanes", otherwise the degenerate manifest reclassifies single_branch as lanes (`classify_topology`, `backfill_topology._has_lanes`).
- 2026-09-28 — Lane work tip lives in the per-lane `WorkspaceContext` (gitignored, per machine), not `lanes.json` (which would force a planning commit per lane advance). Captured by a post-commit companion to the existing commit-guard hook (not skipped by `--no-verify`) plus every spec-kitty lane advance. Residual: hooks disabled and lane destroyed before any spec-kitty observation.
- 2026-09-28 — Override flag named `--commit-to-target`, persisted as `meta.json` `commit_to_target: true`, absent by default.
- 2026-09-28 — PR #5009: absorb only its resolver arm (effective_root threaded into `resolve_workspace_for_wp`), re-keyed on topology, with a `Co-authored-by: samuelgoff` trailer; rest of #5009 stays with its author (it is in maintainer RESCOPE triage, 72 commits behind). Sequencing comment posted on #5009. Main already has `placement_seam(effective_root=)` and `core/owned_mission.require_unstaged_index` (reuse for FR-009).
- 2026-09-28 — Post-spec squad fold (renata/alphonso/paula). Protected = primary OR ProtectionPolicy-protected, one query on ProtectionPolicy (B1). Mission branch minted at **create**, recorded in meta `mission_branch` — the commit router refuses planning commits on a protected target, so implement-time minting is infeasible (alphonso C). FR-010 widened to any single_branch mission sharing the write checkout (B2). Dirty refusal exempts resume (M1).
- 2026-09-28 — Lane work tip moved OUT of `WorkspaceContext` (deviation from the brief's wording): a Python post-commit hook costs ~1.3 s; `context cleanup` deletes exactly the destroyed lane's record (guard would fail open); git cannot recover a deleted branch's tip. Plan: plain-sh post-commit writes `refs/spec-kitty/lane-tip/<branch>` (~5 ms, survives deletion, pins stranded commits against gc). Absorption test = `git merge-tree --write-tree <target> <tip>` tree equals target tree (verified on a 2-commit squash); git < 2.38 fails closed.
- 2026-09-28 — Repo-root lane keeps id `lane-planning`; split `is_repo_root_lane` (where it executes) from `is_planning_artifact_only` (no code) so single_branch code WPs are not treated as planning-only by acceptance/consolidate.
- 2026-09-28 — Post-tasks squad fold: WP06 (create default → lanes) now runs **before** WP05 (activation), and WP03's fail-closed call sites move into WP05's activation commit. Otherwise every single_branch finalize would go red between WP03 and WP05. The for_review claim-base gate counts only commits that touch non-bookkeeping paths, because status commits land on the same branch and would otherwise satisfy it vacuously. There is one terminal-transition hook (`claim_base.on_wp_terminal`), shared by the claim-base and lane-tip cleanup.
- 2026-09-28 — WP02 approved on review cycle 3. Follow-up for the PR's Deferred section: the coord-fallback terminal arm `_fallback_emit_single._coord` (~status_transition.py:577) is reachable only from inconsistent meta (topology coord with no `coordination_branch`), so it is possibly dead code. Tests pin it by patching routing only.
