3. **A canonical project with a symlinked (or non-UTF-8, or directory) `.gitignore` can never upgrade again (regression against base).** `_rewrite_gitignore` always calls `read_gitignore_text`, which raises `GitignorePathError` for a symlink or non-UTF-8 file. `detect()` turns that into True, and because the cutover is `runs_first` and selected **outside the version window**, it is selected on every `spec-kitty upgrade` of every such project. `apply()` then raises, the runner fails the upgrade, nothing is recorded, and the next upgrade repeats this forever. Reproduced: a fresh project stamped `4.0.0rc6` with only `charter_packs.org.packs: []` and `.gitignore -> real-gitignore` gives `get_applicable(...) == ['charter_pack_cutover']` and `upgrade(...).success is False` ("Refusing to read symlinked .gitignore"). On the base the same project upgrades with no migrations. A `.gitignore` that is a directory makes `apply()` raise a raw `IsADirectoryError` that the runner does not catch (an unhandled crash).
   Fix: an unreadable `.gitignore` must not make an otherwise canonical project actionable. For example, in the gitignore step catch `GitignorePathError` and `OSError` and add a `kept_for_review` line ("`.gitignore` could not be read safely; check it for `.kittify/doctrine` rules by hand"). `kept_for_review` is not actionable, so `detect()` stays False on a canonical project and the cutover can record success. Add tests: (a) a canonical project with a symlinked `.gitignore`, where `detect()` is False and a runner upgrade succeeds; (b) a legacy project with a symlinked `.gitignore`, where the move completes and the gitignore is reported for review; (c) a directory `.gitignore` does not crash.

4. **`detect_legacy_charter_layout`, and with it `detect()` and `structural_detect()`, are not total on Python 3.11, the venv and supported minimum.** In 3.11, `Path.is_dir()` and `Path.is_symlink()` re-raise any `OSError` except ENOENT, ENOTDIR, EBADF and ELOOP, so EACCES on `.kittify/doctrine` propagates. Reproduced by making `Path.stat` raise `PermissionError` for `.kittify/...`: both `detect()` and `structural_detect()` raise `PermissionError`. This contradicts the module docstring ("never raises") and the DoD totality item, and the predicate is about to run on every CLI invocation (WP14). Fix: guard the stat calls (`os.lstat`/`os.stat` in a `try/except OSError`) and report a finding, for example `unreadable_project_root`, so the migration is selected and `apply()` names it. Also call the predicate inside `detect()`'s `try`, or make it provably non-raising. Add a monkeypatched-EACCES test.
