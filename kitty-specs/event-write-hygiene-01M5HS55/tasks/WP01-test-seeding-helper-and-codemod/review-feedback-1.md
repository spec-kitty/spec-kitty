**Issue 1 (blocking): `tests/status/test_writer_serialization.py::_flat_mission` makes the SC-008 recorder's non-vacuity guard vacuous.**

`_HeldLocksAtWrite.assert_locked_for` starts with `assert writes, "no store write observed for {feature_dir}"`: proof that the production family under test actually wrote. On the base, the seed went through the plain door (no `_fsync_directory`, no `os.replace`), so the recorder never saw it and `writes` held only production writes. Now `seed_wp_to_planned` goes through `append_raw_rows_atomic`, so the seed itself is recorded. Wrapping it in `feature_status_lock` makes that recorded seed pass the lock check. As a result, families 1-single, 1-inner-state, 2, 4, 5 and 8 would pass even if the production writer wrote nothing. Reproduced: a "family" that only calls `_flat_mission(tmp_path)` and then `recorder.assert_locked_for(fd)` passes on HEAD (it would fail with "no store write observed" on ea7168e7). The per-write lock check still catches an unlocked production write, but the guard against a vacuous pass is lost. The test is also now partly checking a lock that the test itself takes.

Fix: keep the seed invisible to the recorder, as it was before. Seed before the recorder is installed. For example, split each `_family_*` into a setup step (`_flat_mission`) that runs before `_HeldLocksAtWrite(monkeypatch)` and an act step that runs after it. Alternatively, give the recorder a `paused()` context that the seed runs under. Then drop the `feature_status_lock` wrapper (and its import) from `_flat_mission`. Keep `assert_locked_for` unchanged, and record the change in history, since the file is outside `owned_files`.
