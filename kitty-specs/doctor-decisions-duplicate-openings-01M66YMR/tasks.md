# Work Packages: doctor decisions reports tolerated duplicate openings

**Inputs**: Design documents from `/kitty-specs/doctor-decisions-duplicate-openings-01M66YMR/`
**Prerequisites**: plan.md (required), spec.md (user stories), research.md

**Tests**: Required. This mission is red-first: the defect is an absent report, so the
failing test is written against the real `doctor decisions --json` CLI before the fix.

**Organization**: Fine-grained subtasks (`Txxx`) roll up into work packages (`WPxx`).
Each work package must be independently deliverable and testable.

**Prompt Files**: Each work package references a matching prompt file in `/tasks/`
generated by `/spec-kitty.tasks`.

## Subtask Format: `[Txxx] [P?] Description`

- **[P]** indicates the subtask can proceed in parallel (different files/components).
- Subtasks are **reference rows**, not checkboxes: record completion with
  `spec-kitty agent tasks mark-status <Txxx> --status done`.

- **Single project**: `src/`, `tests/`.

## Work Package WP01: Informational duplicate-opening finding (Priority: P1) 🎯 MVP

**Goal**: `doctor decisions` names every decision whose event log holds duplicate
`DecisionPointOpened` rows that the canonical fold already tolerates, on both the human
and the `--json` surface, without changing `clean`, the exit code or `--repair`.
**Independent Test**: Build a mission whose `status.events.jsonl` holds two identical
openings; run the real `doctor decisions --json`; assert exit 0, `clean: true`, and the
decision id in `duplicate_openings_tolerated`. Then feed two openings that differ beyond
`recorded_at` and assert the decision is in `malformed_folds` only.
**Prompt**: `/tasks/WP01-informational-duplicate-openings.md`
**Requirement Refs**: FR-001, FR-002, FR-003, FR-004, FR-005, FR-006, NFR-001, NFR-002, NFR-003, C-001, C-003, SC-001, SC-002, SC-003, SC-004, SC-005

### Included Subtasks

T001 [P] Red-first test: duplicate log reports `clean: true` and names the decision in `duplicate_openings_tolerated` (currently absent) in `tests/decisions/test_decisions_reconciler.py`
T002 [P] Red-first test: three identical openings name the decision once; a log without duplicates yields an empty list
T003 [P] Red-first test: openings differing beyond `recorded_at` stay in `malformed_folds` and never appear in the duplicate list
T004 Add the exported `index_fold` helper that counts tolerated duplicate openings from the same per-decision event group
T005 Collect the duplicate decision ids in `_fold_diagnostics` and carry them on `DecisionsReconciliationReport` without touching `clean`
T006 Emit the finding on both surfaces: one informational human line and the additive `duplicate_openings_tolerated` `--json` key
T007 Prove read-only and pre-existing-test stability: log and index bytes unchanged, `--repair` behaviour unchanged, whole module green

### Implementation Notes

- The helper belongs in `specify_cli/decisions/index_fold.py` and must reuse
  `_opened_identity()`; it must not raise `FoldError` (the fold owns that refusal).
- `_fold_diagnostics` already materialises each decision's events, so the count costs no
  extra read and no extra fold (NFR-001).
- The report field must not enter the `clean` property.
- `--repair` re-runs `_diagnose`, so the finding appears post-repair with no repair-path
  change (FR-006, C-001).

### Parallel Opportunities

- T001–T003 (three independent tests in one module) can be written together; T004–T006
  follow them red → green.

### Dependencies

- None. This is the MVP package.

### Risks & Mitigations

- A second duplicate rule drifting from the fold → the helper consumes the fold's own
  `_opened_identity()`; T003 fails if the two diverge.
- Accidentally gating `clean` or the exit code → T001 asserts both explicitly.
