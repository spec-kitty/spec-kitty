# Design decisions

- 2026-10-04: mission_number becomes a package (leaf `__init__` + `bake.py`) — keeps the stdlib-only contract drivers.py relies on (research.md R-1).
- 2026-10-04: driver, door `try`, inline phase calls and `_report_rollback` stay in executor.py so the AST/source pins keep reading the same code (R-2).
- 2026-10-04: patches re-pointed to every module that looks the name up; no patch-only aliases (R-3).
- 2026-10-04: branch named `issue-2026-consolidation-decomposition` per charter "issue branch first", overriding the brief's `refactor/consolidation-decomposition` (charter wins).
- 2026-10-04 (WP01): the moved cluster's one `logger.warning` keeps the logger name `specify_cli.consolidation.ordering` (log labels are do_not_change); the mypy quarantine entry moved from `ordering` to `mission_number.bake` with the one pre-existing `no-any-return` finding instead of editing moved logic. `ordering` is now strict-clean.
- 2026-10-04 (WP03): multi-module patches use a shared-mock helper (`patch_executor_family` / `setattr_executor_family`) rather than N independent patches, so call assertions keep seeing every call; it raises when no family module binds the name (keeps monkeypatch's raising semantics).
- 2026-10-04 (WP03): fixed-scope gates widened to the receiving modules; `_STATUS_BEARING_MODULES` is an exemption list, so adding phase_claim/entry_preflight is a re-point of the moved read_events sites, not a tightening (reviewer note).
- 2026-10-04 (WP03): cohesion nits left for a follow-up (no behaviour impact): `_restore_regressed_gate_artifacts` (phase_advance, used by phase_bookkeeping), `_created_lane_worktree` (phase_advance, used by entry_preflight/phase_teardown; moved to run_state in the pre-PR fold, together with `_resume_reconciliation_already_passed`), `CoordinationTeardownError` (run_state, used by phase_teardown).
- 2026-10-04 (pre-PR squad fold): correction to the `_STATUS_BEARING_MODULES` note above. The list is dual-use in `test_coord_read_residuals_closeout.py`: it is the read-func-scoped exclusion for `read_events` reads, and it is also the scan list for the coord-awareness check (`for rel_path in _STATUS_BEARING_MODULES`). Adding phase_claim/entry_preflight therefore keeps that scan on the moved `read_events` sites (a widening of the scan), and the exclusion stays limited to `read_events` reads.
- 2026-10-04 (pre-PR squad fold): `_created_lane_worktree` and `_resume_reconciliation_already_passed` moved verbatim to run_state, which removes the phase_claim -> phase_gate and phase_teardown/entry_preflight -> phase_advance edges; `_WRITE_DIR_CONSUMER_MODULES` widened to the whole executor family; leaf-contract wording corrected (file-level, not import-closure).
