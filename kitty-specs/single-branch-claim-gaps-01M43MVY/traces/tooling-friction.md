# Tooling friction

Tooling touched: `spec-kitty agent mission create`, `spec-commit`, `safe-commit`, `implement`, `agent action implement`, `move-task`, `consolidate`.

- 2026-10-04: `agent mission create` without `--topology`, run on topic branch `issue-5680-single-branch-claim-gaps`, resolved to `coord`, not `lanes`. This clone has no `origin/HEAD` symbolic ref, so primary-branch detection falls back to the current branch. This is the documented pre-existing caveat in CLAUDE.md "Create-time topology". Kept `coord` rather than hand-rolling a teardown and recreate.
- 2026-10-04: `spec-commit` refuses a directory argument (`decisions/`). Every file has to be listed. `decisions/index.json` landed in a second commit because the decision tooling writes it lazily.
- 2026-10-04: `agent mission create` refuses to run from a linked worktree. The real-record #5680 reproduction therefore used a local `git clone` of the branch.
- 2026-10-04: `safe-commit` warns "--to-branch will be required in v3.3", which is a stale version reference on a 4.0 line.
- 2026-10-04 (implement): The editable install points at the repository root checkout's `src/`, but `pytest.ini` `pythonpath = src` makes pytest in the lane worktree import the lane's own code. I verified this before trusting red→green. Anything that shells out to `spec-kitty` would still run the root checkout's code.
- 2026-10-04 (implement): In the hand-built fixture of `test_single_branch_implement_refusals.py` (no `.kittify/config.yaml`), `move-task --to blocked` writes but does not commit the status change. The claimant's dirty check then refuses on the occupant's status files. In the realistic `make_mission` fixture the transition commits. The remedy test therefore lives in the end-to-end suite.
- 2026-10-04 (implement): `make test-fast` runs `uv run --frozen`, which would build a fresh `.venv` inside a lane worktree. I ran the target's exact pytest command with the existing venv instead.
- 2026-10-04: #5680 did not block this mission's own claims, because it is a `coord` mission (see the first entry), so no `--force` override was needed.

Committed afterwards with `safe-commit`. The approval gate also refused until `issue-matrix.json` verdicts were recorded (`spec-kitty agent issue-verdict`); the reviewer recorded them from checked evidence.

That does not fit a bugfix mission with no new contract surface. I used the documented `--lenient`; the remaining warnings list the optional artifacts. `spec-kitty agent mission accept` has no `--actor`, while top-level `spec-kitty accept` does.
