# Design decisions

- **[2026-11-01][plan] Vocabulary lives in the router, not the pack.** Profile keywords
  are fetched from `spec-kitty-open-packs` and regenerated by `make sync-packs`; the
  router is the canonical routing authority (ADR-3) and ADR-3 itself names expanding the
  alias table as the remedy for a coverage gap.
- **[2026-11-01][plan] Docs artifacts fold onto the existing `documentation` keyword.**
  No new confidence tier, no new profile, and the shipped `curator-carla` already declares
  that keyword, so the new vocabulary reuses the tier that exists.
- **[2026-11-01][plan] Bare `index` is excluded from the docs family.** "Index the invoice
  table" must not route to a documentation profile; `adr index` and `documentation index`
  already carry an unambiguous noun.
- **[2026-11-01][plan] Nearest-profile ordering is a total order.** overlap desc,
  `routing_priority` desc, `profile_id` asc — capped at three, so the message is stable
  and short for any catalog size.
- **[2026-11-01][tasks-review] New signals are fallback tiers, not additional candidates in
  one pool.** A pre-implementation reviewer proved that adding phrase and docs-alias matches
  next to today's single-token matches would move live routes ("release notes for the sprint"
  from `planner-priti` to `comms-cleo`; "the guide for the spike" to a priority-40 tie). The
  ordering is now tier 2 literal single token → tier 3 literal phrase → tier 4 docs alias,
  so every request that routes today resolves in tier 2 and is byte-identical (FR-011,
  SC-006).
