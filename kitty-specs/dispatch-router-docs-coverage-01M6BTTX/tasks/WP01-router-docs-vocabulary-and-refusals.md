## Objectives & Success Criteria

Fix `ActionRouter` so that:

1. A documentation-maintenance request routes on the shipped catalog without `--profile`
   (FR-001), while bare `index` stays out of the documentation vocabulary (FR-002).
2. A declared keyword or canonical verb containing a space or hyphen matches its own
   words in a request (FR-003) — as a **fallback tier** below today's literal
   single-token matches, so no request that routes today moves (FR-011, FR-012).
3. `ROUTER_NO_MATCH` reports up to three nearest profiles, deterministically ordered,
   with a suggestion containing a runnable `--profile <id>` command (FR-004, FR-005),
   and `ROUTER_AMBIGUOUS`'s suggestion names the tied ids and one `--profile` per id
   (FR-006).
4. The JSON payload shape is unchanged (FR-008), the router stays pure (FR-009), and the
   verb tier still outranks domain vocabulary (FR-010).

Done when the targeted suite is green and each subtask's red-first proof was observed.

Requirements: FR-001, FR-002, FR-003, FR-004, FR-005, FR-006, FR-008, FR-009, FR-010,

### Subtask T004 – Phrase-aware keyword matching as a fallback tier

- **Purpose**: make declared multi-token signals work (FR-003) without moving a single

## Risks & Mitigations

- **Vocabulary too broad** → misroutes a database "index" request: bare `index` is
  excluded by design (FR-002), and the tier ladder (single-token first) plus T007's
  differential corpus catch collateral changes.
- **New signal outranking an existing route** → the tier ladder makes new signals strictly
  additive: tier 2 (today's pass) resolves every request that routes today before tiers 3–4
  are consulted (FR-011).
- **Ordering instability** → flaky messages: the ordering is a documented total order,
  asserted with a shuffled catalog.
- **Router purity** → the ranking must be pure in-memory work over `list_all()`; no
  filesystem/env access is added.
