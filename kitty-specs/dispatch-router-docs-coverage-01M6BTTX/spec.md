# Mission Specification: `spec-kitty dispatch` routes a documentation-maintenance request

**Mission Branch**: `kitty/mission-dispatch-router-docs-coverage-01M6BTTX`
**Created**: 2026-11-01
**Status**: Draft
**Input**: User description: "Issue #6970 — `spec-kitty dispatch` returns ROUTER_NO_MATCH for an ordinary documentation-maintenance request. Make a docs-maintenance request route without `--profile`, and make the refusal name the closest profiles and the `--profile` command."

## Context

`spec-kitty dispatch "<request>"` is the governed entry point for ad-hoc work: it maps a
natural-language request to `(profile_id, action)` and opens an Op. Two governed sessions
in `spec-kitty/doc-kitty` (CLI 4.0.0rc8) hit the mapping's coverage gap:

- "mark ADR-0068 Accepted and regenerate the ADR index" → `ROUTER_NO_MATCH`, no Op
  opened, no candidate suggested. Re-running with `--profile` worked.
- an unused `eslint-disable` lint fix and an ADR id-pattern normalisation → the lint fix
  (and, on `main`, ADR work) routes to nothing, or refuses as `ROUTER_AMBIGUOUS` with
  only the code in hand.

The router (`src/specify_cli/invocation/router.py`) is the pure, deterministic
three-tier matcher ADR-3 fixed: explicit `--profile` hint, canonical verb table
(`CANONICAL_VERB_MAP` → role → every profile with that role), then per-profile
`specialization-context.domain-keywords` (plus `collaboration.canonical-verbs`).

Three defects compose the report (evidence in
`kitty-specs/dispatch-router-docs-coverage-01M6BTTX/research.md`):

1. **The documentation domain has no routable vocabulary in practice.** The request's
   nouns (`adr`, `index`, `docs`, `changelog`, `readme`, `guide`) are declared by no
   shipped profile, while the one profile that owns the documentation domain
   (`curator-carla`: `documentation`, `knowledge base`, `glossary`, `doctrine`, …)
   never sees its own keyword. A routine docs request therefore matches nothing.
2. **Multi-word and hyphenated keywords can never match.** Keyword matching is exact
   token equality against a request split on non-word characters, so `knowledge base`,
   `bug fix`, `design patterns` and `transcribe-notes` are dead signals their authors
   declared in good faith.
3. **The refusal carries no signal.** `ROUTER_NO_MATCH` is raised with an empty
   `candidates` list and a generic suggestion; `ROUTER_AMBIGUOUS` carries candidates in
   the `--json` envelope but its suggestion never names the tied ids, and a non-`--json`
   invocation prints a raw JSON blob to stderr. An agent's only choices are to guess a
   profile id or to skip governance — exactly what dispatch exists to prevent.

This mission closes the coverage gap inside the router (ADR-3's own prescribed remedy)
and makes both refusals actionable, without inventing a winner for a genuine tie.

Out of scope: changing the shipped profile pack (its keywords are fetched from
`spec-kitty-open-packs` and regenerated by `make sync-packs`); adding an LLM/plugin
routing fallback (ADR-3's Option C, still deferred); changing `--profile` semantics;
`ROUTER_AMBIGUOUS` tie-breaking into a silent winner.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - A docs-maintenance request routes on its own (Priority: P1)

An agent working in a `.kittify/` project runs `spec-kitty dispatch "mark ADR-0068
Accepted and regenerate the ADR index"`. The router selects the project's documentation
profile, opens the Op, and reports `router_confidence: domain_keyword` — no `--profile`
guess, no skipped governance.

**Why this priority**: this is the reported defect. Without it the issue is not fixed.

**Independent Test**: `spec-kitty dispatch "<docs request>" --dry-run --json` against the
shipped catalog exits 0 with a `profile_id` whose declared domain covers documentation.

**Acceptance Scenarios**:

1. **Given** a project whose routing catalog contains the shipped profiles, **When**
   `spec-kitty dispatch "mark ADR-0068 Accepted and regenerate the ADR index" --dry-run
   --json` runs, **Then** it exits 0, `status` is `dry_run`, `profile_id` is
   `curator-carla`, `router_confidence` is `domain_keyword`, and the action is a
   curator-canonical action.
2. **Given** the same project, **When** a docs request uses a different documentation
   noun (`changelog`, `readme`, `docstrings`, `guide`), **Then** it routes to the same
   profile with `domain_keyword` confidence.
3. **Given** the same project, **When** a request names a database index ("index the
   invoice table"), **Then** it does **not** route through the documentation domain
   signal (bare `index` is not a docs signal).

### User Story 2 - A refusal names candidates and the remedy (Priority: P1)

An agent gets a refusal it can act on: the closest profiles by id, why each was
considered, and the exact command to run with `--profile`.

**Why this priority**: the issue's second "Done when" item, and the difference between a
governed retry and an agent guessing.

**Independent Test**: a request with no verb and no domain keyword exits 1 with a
non-empty `candidates` list (when any profile overlaps at all) and a `suggestion` that
contains a runnable `spec-kitty dispatch "<request>" --profile <id>` command.

**Acceptance Scenarios**:

1. **Given** a project with the shipped catalog, **When** a request matches no verb and
   no keyword but shares words with a profile's declared vocabulary, **Then** the
   refusal lists the top overlapping profiles (at most three, deterministic order) with
   a `match_reason` that says the overlap is partial, and the suggestion names the
   `--profile` remedy with a concrete id.
2. **Given** a request that shares nothing with any profile, **When** it is refused,
   **Then** `candidates` is empty and the suggestion points at
   `spec-kitty profiles list` (nothing is invented).
3. **Given** an `ROUTER_AMBIGUOUS` tie, **When** the refusal is rendered, **Then** the
   suggestion names the tied candidate ids and a `--profile <id>` command for each.

### User Story 3 - Declared multi-word keywords actually match (Priority: P2)

A profile that declares `knowledge base` or `bug fix` (or a hyphenated verb such as
`transcribe-notes`) matches a request that says those words, so the vocabulary the
catalog author wrote has effect.

**Why this priority**: it is a real defect found while grounding the P1 work, and it is
the class of signal that would have covered the reported request if it had not been
dead. It is P2 because no reported case depends on a multi-word keyword alone.

**Independent Test**: a registry with a profile declaring a two-word keyword routes a
request containing that phrase to it; the same request with only one of the two words
does not.

**Acceptance Scenarios**:

1. **Given** a profile declaring `domain-keywords: ["knowledge base"]`, **When** the
   request "refresh the knowledge base article" arrives, **Then** it routes to that
   profile with `domain_keyword` confidence.
2. **Given** the same profile, **When** the request contains `knowledge` but not `base`,
   **Then** the pair does not match.
3. **Given** a profile whose `collaboration.canonical-verbs` contains `transcribe-notes`,
   **When** the request says "transcribe notes for the meeting", **Then** the hyphenated
   verb matches.

### User Story 4 - A refusal is readable without `--json` (Priority: P2)

An operator running dispatch without `--json` sees a short human message — error code,
candidates, remedy — instead of a JSON blob on stderr.

**Why this priority**: the report's author read the bare code and nothing else; the
machine envelope already suffices for machines.

**Independent Test**: a refused dispatch without `--json` writes no JSON error envelope
to stderr and names the code plus the remedy in the console output.

**Acceptance Scenarios**:

1. **Given** a `ROUTER_NO_MATCH` refusal on the real (Op-opening) path without `--json`,
   **Then** the console shows the error code, the candidates, and the remedy, and exits 1.
2. **Given** the same request with `--json`, **Then** the existing JSON error envelope is
   emitted on stderr, unchanged in shape.

### Edge Cases

- A project that deactivated the only documentation profile: no docs profile exists to
  route to; the refusal must name the nearest activated profiles and must not invent one.
- An empty catalog (nothing admitted by activation): keeps the existing
  activation-specific suggestion (#4114) and carries no candidates.
- An explicit `--profile` hint: unchanged — exact confidence, no candidate computation,
  no new vocabulary consulted.
- A request whose only signal is a canonical verb tied across several profiles (e.g. two
  implementer profiles at the same `routing_priority`): still `ROUTER_AMBIGUOUS`; the
  change is in the message, never in the decision.
- A request mixing a docs noun and a canonical verb ("review the ADR index"): the
  verb tier wins, as ADR-3 and #3840 fix it; the docs signal must not override a verb.

### Key Entities

- **ActionRouter** (`src/specify_cli/invocation/router.py`): the pure request → decision
  function; gains the documentation vocabulary, phrase-aware keyword matching and the
  nearest-profile ranking used only on refusal.
- **RouterDecision**: unchanged shape (`profile_id`, `action`, `confidence`,
  `match_reason`, `alternatives`).
- **RouterAmbiguityError** (`src/specify_cli/invocation/errors.py`): unchanged shape
  (`error_code`, `candidates`, `suggestion`); `candidates` becomes populated for
  `ROUTER_NO_MATCH` and the `suggestion` becomes actionable.
- **ProfileRegistry** (`src/specify_cli/invocation/registry.py`): read-only input; the
  activation-gated catalog the router scores.
- **Dispatch CLI** (`src/specify_cli/cli/commands/dispatch.py`): renders router refusals
  for humans when `--json` is absent.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The issue's exact request text ("mark ADR-0068 Accepted and regenerate the ADR index") routes through `spec-kitty dispatch --dry-run --json` with exit 0 and a documentation profile, with no `--profile` passed. — [build] · no-op passable: no
- **SC-002**: 100% of refusals over a request that shares at least one normalized token with any profile's declared vocabulary name up to three candidate profile ids, and 0% of those suggestions name a profile not in the catalog. — [build] · no-op passable: no
- **SC-003**: Every `ROUTER_AMBIGUOUS` refusal rendered by the CLI names the tied profile ids and one `--profile` command per tied id. — [build] · no-op passable: no
- **SC-004**: Every request that routed successfully on `main` routes to the same profile and action after the change (differential check over the existing router fixtures). — [ratchet] · no-op passable: no
- **SC-005**: A keyword or canonical verb containing a space or hyphen matches when its words appear contiguously in a request, and does not match on a single word of the phrase (pairwise assertions). — [build] · no-op passable: no
- **SC-006**: Every request in a fixed corpus that routes on `main` routes to the same profile and action after the change, checked against the shipped catalog (including requests whose only match today is a single-token keyword that a new phrase or vocabulary signal would otherwise outrank). — [ratchet] · no-op passable: no
