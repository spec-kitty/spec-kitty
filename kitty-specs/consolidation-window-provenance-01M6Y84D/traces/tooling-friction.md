- **[2026-11-08][specify] `agent mission create` refused with WRITE_CHECKOUT_DIRTY over untracked scratch folders.** The operator's untracked `reports/` and `research_notes/` folders made the write checkout count as dirty. Workaround: added them to `.git/info/exclude`. Candidate gap: create could ignore untracked paths outside `kitty-specs/`, or name the `.git/info/exclude` remedy in its refusal.
- **[2026-11-08][specify] `spec-kitty spec-commit` failed on a transient `.git/index.lock`.** A concurrent git process held the lock; a retry succeeded. Candidate gap: a bounded retry/backoff on `index.lock`, or a clearer message saying the lock is transient and how to check for a live git process.
- **[2026-11-08][specify] First `mission create` output lost to a shell parse error; resume probe showed not_found.** The create output never reached the agent, and the resume probe correctly reported `not_found`, so the create was re-run cleanly. No change needed: the probe worked as designed.
- **[2026-11-08][plan] TokenFactory deepseek endpoint unreachable during the post-plan squad.** The coverage check routed to deepseek failed with "Cannot connect to host"; it was rerun on glm-5.3 and completed. Candidate gap: the opencode/LiteLLM routing had no fallback model group, so one unreachable endpoint stopped the delegate instead of failing over.

- **[2026-11-08][tasks] A WP prompt writer (Claude Opus) simulated the implementation in a temp directory to "make sure the instructions hold".** That effectively implements the work twice: once while writing the prompt and again in the implement step. It is very wasteful in tokens and wall-clock. The operator flagged it. Disposition: candidate gap. Prompt-writer briefs (and the tasks command contract) should say to verify instructions by reading code and running existing tests only, never by prototyping the change. Applied from here on in this mission's delegate briefs. Filed upstream as spec-kitty/spec-kitty-open-packs#176 so the tasks, tasks-packages, plan and specify prompts carry the rule.
- **[2026-11-08][tasks] TokenFactory glm-5.3 timed out with no output on the cross-prompt consistency check.** The opencode run hit its 25-minute timeout and wrote an empty file (no partial output, no error). The same check was rerouted to Claude Haiku. Disposition: candidate gap. With deepseek unreachable earlier the same day, TokenFactory reliability is too low to rely on for blocking steps; the opencode route needs streamed or partial output and a fallback model group.
- **[2026-11-08][tasks] `create_intent` is checked per work package, not across the dependency chain.** `finalize-tasks --validate-only` refused 42 owned paths in WP10-WP20 that an earlier work package in the same chain creates (`reconciliation_family.py`, the split modules, the corpus files). The only remedy is to repeat each such path in every later owner's `create_intent`, so the field now reads "does not exist at planning time" rather than "this work package creates it". A chain-aware check (accept a path that a dependency's `create_intent` lists) would keep the field truthful.
- **[2026-11-08][tasks] `map-requirements` rewrites every WP frontmatter in a different YAML style.** The call sorted and unquoted the keys and switched lists to zero-indent block sequences in all 21 prompts, with `--no-auto-commit`. A text edit made against the old style broke the YAML until it was re-normalised. The command should preserve the existing frontmatter layout, or say that it reformats.

Fixed in the plan (WP21 to `code_change`; WP07 takes over WP02's planned stand-in-constant replacement), but the tool gave no hint that the planning lane is a single node in the lane graph.
