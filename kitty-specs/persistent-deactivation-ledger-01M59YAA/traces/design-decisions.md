Strict: a deny key in the data or a non-`None` `deny_change` raises `ActiveCharterConfigError` naming the ledger and `spec-kitty upgrade`; nothing is written. - **[2026-10-19][WP03] Rendering identity uses the public seam, not a new baseline row.** `rendering_inputs` asks `charter.activation.api.load_activation_ledger(report_stray=False)` for the source after today's legacy checks, and appends the ledger path when it is `LEDGER` (also for a fresh strict project before the first write, so provisioning validates against it). The SPDD probe derives its legacy key set from `ArtifactKind` locally, since C-004 forbids importing the seam's `LEDGER_KEYS`.
- **[2026-10-19][WP03] The kernel probe parses with the round-trip loader.** Once the readers went through the resolver, `test_compiler_charter_yaml.py::test_provision_round_trip_input_classes` went red: a `config.yaml` with a custom tag or a complex key, which every activation reader parses with ruamel's round-trip loader, failed the kernel probe's safe loader. - **[2026-10-19][WP04] D-18: the overlay reads the extends:-walking iterator.** `_iter_org_charter_docs` yields `(declared, member, raw)`; each declared pack first, then its bases nearest first (resolved by `resolve_extends_order`), so first-seen union order is unchanged for flat packs. `_read_org_required_selections` and `read_org_required_ids` read every member, so a requirement inherited through `extends:` is now selected and required; the activations block and `read_org_skill_namespace` filter `declared == member` to keep their one-document-per-pack semantics. Lenient readers fall back to the declared pack alone on a bad chain; strict refuses.
- **[2026-10-19][WP04] Strict floor refusals.** `read_org_required_provenance(strict=True)` refuses an unreadable registry, a declared pack that is not a directory, an unreadable, empty or non-mapping `org-charter.yaml`, a `required_<plural>` that is not a list of strings, and a cycling or dangling `extends:`, as `ActiveCharterConfigError` (precedent `require_org_skill_policy_readable`, which also refuses a zero-byte charter). A pack with no `org-charter.yaml` requires nothing.
- **[2026-10-19][WP04] Unknown id on deactivate.** Per data-model §3 an id neither available nor in the present allow list raises `UnknownActivationIdError`; an id the allow list alone knows stays removable. - **[2026-10-19][WP04] Cascade under an absent allow list.** `_active_urns` counts an absent "all" kind as every DRG node of that kind, less denied ids (C-007), so built-in children are mostly shared.
