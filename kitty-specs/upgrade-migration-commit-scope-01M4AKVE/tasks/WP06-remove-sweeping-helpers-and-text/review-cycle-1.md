## MAJOR-1: merge-conclusion guidance says something false
`src/charter/offering/skills/spec-kitty-implement-review/SKILL.md:839`
`git diff --staged --name-only           # confirm only the resolved files are staged`

When a merge is being concluded, the index holds every change the merge brought in, plus your
resolutions. Reproduced: a lane adds `incoming.txt` and conflicts on `c.txt`. After `git add -- c.txt`,
`git diff --staged --name-only` prints `c.txt` AND `incoming.txt`. The check this comment describes
fails on any merge that brings in more than the conflicted files. An agent that obeys it literally
will unstage the files that merged cleanly, and the merge commit then silently drops the lane's
changes. Fix: replace the check with one that is true during a merge. For example, confirm no
unmerged paths remain (`git diff --name-only --diff-filter=U` prints nothing). Say plainly that the
staged set is the incoming changes plus your resolutions, and that this is expected.
Also `:837`: the comment says "list the conflicted files before resolving", but the command is placed
after step 3 (resolve). Move it into step 3, or reword the comment ("still-unmerged files").
