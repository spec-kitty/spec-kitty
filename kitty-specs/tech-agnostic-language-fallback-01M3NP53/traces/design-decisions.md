# Design decisions — tech-agnostic-language-fallback-01M3NP53

- 2026-09-29 — Unknown language = reserved `unknown` token in `catalog.languages` (operator). Keeps the load-bearing `None` (admit all) vs `[]` (admit none) contract from #3292 intact; `unknown` is a third, explicit state that admits no language-scoped artifacts and triggers the charter-extension advisory.
- 2026-09-29 — #4614: only `charter generate --from-interview` re-derives languages from the interview; runtime readers and activate/pack recompiles keep compiled-first precedence (operator). Rationale: flipping precedence globally would reopen #2395 and risk the #3292 feedback loop.
- 2026-09-29 — Dead-code not-applicable = gate recorded `skip` + non-failing `dead_code_not_applicable` finding with new code `MISSION_REVIEW_DEAD_CODE_NOT_APPLICABLE` (operator). Preserves #2987 FR-015 "never a false clean zero".
- 2026-09-29 — Folds: #4613 minimal (hyphenated compounds only) and the review pytest pre-check (downgrade to warning; no review gate runs Python tests). `available_tools` registry NOT widened; only de-conflated from language detection.
- 2026-09-29 — Post-spec squad folds: `unknown` fires only from the languages/frameworks answer when it is non-empty, not the shipped default, not a placeholder, and no recognised language matched anywhere (otherwise every defaults-built charter would become admit-none — the #3292 trap). The #4614 bypass is an explicit precedence parameter on the single language authority, set only by the from-interview generate path. Dead-code gate record becomes tri-state (pass/fail/skip). A Python mission with only tests/docs changes also becomes not-applicable (deliberate: nothing to decide), distinct wording for excluded test paths. Advisory string = product code constant in charter activation, not a pack artifact (avoids graph regen and the #5202 guideline owner). `unknown` reserved in artifact scoping. Migration `or []` latent bug filed as #5335.
- 2026-09-29 — Post-plan: `unknown` is NOT a scoping sentinel (sentinels = always load); a separate reserved set is stripped from both sides in `applies_to_languages_match`. Operator chose a doctrine-derived language vocabulary: a whole-word language named in the languages/frameworks answer that active doctrine is scoped to (e.g. go, csharp) resolves as recognised, so `unknown` means "no specialist guidance exists" and Go/C# projects keep their scoped tactics. `charter generate` also passes the interview preference into its doctrine-service builder to avoid resolving references under a stale language (split-brain M1). An ADR records the catalog.languages states.
- 2026-09-29 — Operator directive: tactics are language-independent. Doctrine audit found secure-regex / chain-of-responsibility / dependency-hygiene wrongly scoped (secure-regex's scope contradicts its own header; likely added to dodge the bias test's `applies_to_languages:` substring exemption). Operator: de-scope all three here (WP07, FR-018), accept a rebase against PR #5324; keep the doctrine-derived vocabulary (now backed only by genuinely language-specific artifacts). Vocabulary is a YAML scan, not a raw DoctrineService (sole-door gates; ~2 s cold via the service).
- 2026-09-29 — WP07 removed bare "Maven" words (bias-test denylist has no example-label notion) and narrowed the in-house-reference test to the three de-scoped tactics.
- 2026-09-29 — WP01: scan_dead_code returns an outcome ("scanned"/"not_applicable"/"unscanned") and `_dead_code_gate_result` maps it to the gate result, so `skip` is never inferred from the finding list; mixed sets get a console-only note; test git repos keep mission files untracked so .json/.jsonl do not leak into unsupported extensions.
- 2026-09-29 — WP03: vocabulary scan cold ~262 ms / warm ~0 ms (functools.cache); `packaged_default_answer(key)` public accessor added to interview.py (out-of-map, leeway) to avoid duplicating the defaults literal; `is_placeholder_language_answer` shared with the synthesizer; C#/C++ resolve to unknown (pinned).
- 2026-09-29 — WP04 keys the re-derive flag on the effective `interview_source == "interview"` rather than the raw `--from-interview` flag; builder forwards interview/prefer_interview only when set.
- 2026-09-29 — WP05 found the DRG action walk (action_doctrine_bundle.py) is language-blind: language-scoped ids leaked into a Zig context despite repository scope filtering; added _drop_scope_filtered_ids (unknown-language only, via repositories' scope_filtered_ids). Advisory rendered as "  - Advisory: <text>" in both views, appended before the token budget.
- 2026-09-29 — operator: recognised-language id bleed filed as #5357, claimed and folded into closeout (drop the is_unknown_language gate in _drop_scope_filtered_ids).
- 2026-09-29 — docs must describe TWO language sources: the frozen built-in detector (8 languages + tool words, all answers) and the doctrine-derived vocabulary (languages/frameworks answer only, when the detector finds nothing); a Ruby/Swift/Rust project is 'recognised' by the detector even without scoped doctrine, so gets no unknown/advisory — accepted (C-001 forbids growing, not removing, the table). WP06 needed 3 review cycles to get this right.
