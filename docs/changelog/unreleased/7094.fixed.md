- **`spec-kitty upgrade` no longer keeps a project's generated command files only because this machine has no global copy yet** (#6954). **Before:** the shipped 3.1.2 command-globalization migration asked `~/.kittify/missions` and `~/.claude/commands` first, so on a machine whose first spec-kitty command was `upgrade` it kept a generated project-local command file that the same commit removed on the original machine, then recorded `success` and froze that answer. **After:** a successor migration reads the project's own `.kittify/metadata.yaml`; a stamp at or above the 3.1.2 command-globalization boundary proves that a version-marked project-local command file is generated and obsolete, so the file is removed and committed identically everywhere. The shipped migration stays byte-frozen as a superseded no-op. The home still decides for a project with no usable stamp, and a file with no version marker is still preserved. **What to do:** nothing; only generated copies the CLI recreates at its next command are removed.
