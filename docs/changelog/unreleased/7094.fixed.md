- **`spec-kitty upgrade` no longer keeps generated project command files merely because this machine has no global copy** (#6954). **Before:** the shipped 3.1.2 migration checked `~/.kittify/missions` and global command directories, so an empty-home `upgrade` could retain a generated file another machine removed and record `success`. **After:** a successor reads `.kittify/metadata.yaml`; a stamp at or above 3.1.2 proves a version-marked project-local command is generated and obsolete, giving the same removal on every machine. The shipped migration remains a byte-frozen superseded no-op. Projects without a usable stamp keep the home fallback, and marker-less files are preserved. The stamped path removes generated project files before a global copy exists and relies on `ensure_global_agent_commands` at the next CLI start; the obsolete legacy `.codex/prompts` folder is not recreated globally because Codex uses skills.
