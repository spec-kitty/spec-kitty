- **`spec-kitty upgrade` no longer keeps a project's generated command files only because this machine has no global copy yet** (#6954). **Before:** the 3.1.2 command-globalization migration asked `~/.kittify/missions` and `~/.claude/commands` first, so on a machine whose first spec-kitty command was `upgrade` it kept a generated project-local command file that the same commit removed on the original machine, then recorded `success` and froze that answer. **After:** a project stamped at or above the migration's target version in its own `.kittify/metadata.yaml` decides alone — a version-marked project-local command file is ours and obsolete, so it is removed and committed, identically everywhere. The home still decides for a project with no usable stamp, and a file with no version marker is still preserved. **What to do:** nothing; only generated copies the CLI recreates at its next command are removed.
