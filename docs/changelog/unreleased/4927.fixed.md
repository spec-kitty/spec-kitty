- **A converged Windows home stops re-planning permission repairs on every start and in `upgrade --dry-run`** (#4927, #4810). **Before:** Windows (NTFS) reports every directory as `0o777` and every file as `0o666` or `0o444`, so the global skill sync and the global asset bootstrap planned a `chmod` for each skill directory (253 on a typical home) that could never take effect. The same repairs came back on every CLI start and in every `upgrade --dry-run`, while `doctor tool-surfaces` reported the project clean. **After:** every planner and recheck compares modes through one host-aware rule. On Windows a directory or symlink compares its kind only, and a file compares only its read-only state; on Linux and macOS modes still compare exactly, so a loosened directory or a changed execute bit is repaired as before. A converged home plans nothing.
- **Windows project skills: a managed file whose read-only state differs from the plan is now repaired** (#4927). **Before:** the project-skill planner ignored every Windows file mode, so a managed skill file that had become writable, or read-only, was never noticed. A read-only file can block later writes and deletes. **After:** the read-only state, the one permission NTFS stores, is compared and repaired in both directions. This deliberately replaces the earlier rule that ignored file modes on Windows entirely.
