- **A project whose command surfaces come from a harness plugin is reported as set up, not broken** (#6894, #6493). **Before:** with `agents.available: []` in `.kittify/config.yaml` — the stated-empty list #6494 gave the meaning "no CLI-managed agents" — `spec-kitty agent config list` printed `No agents configured.` and told you to run `spec-kitty init` or `agent config add`; `init` claimed it had verified and restored skill surfaces it never touched; `init --ai claude` exited 1 with `Requested agents are not configured`; and `doctor skills`, `doctor tool-surfaces` and `doctor command-files` printed `all … healthy (0 …)` over a surface set they never examined. Following that advice installed a second copy of every command the plugin already supplies. **After:** all of them name the stated no-CLI-managed state, exit 0, install nothing, and `doctor` prints `no CLI-managed agents — nothing to check`. A config with no agent list at all is reported as the legacy every-agent fallback instead of "no agents configured". JSON envelopes keep their keys, and the `agent config sync --create-missing` diagnosis for a *listed* agent whose command skills are missing is unchanged.
