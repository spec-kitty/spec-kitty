- **`spec-kitty events tail` and `spec-kitty agent status materialize` refuse a status that lives only on a branch** (#7276). **Before:** with the coordination worktree empty or absent, or a default Mission's topic branch held by no checkout, `events tail --once` printed nothing and a stream waited for a file, and `materialize` wrote or read the repository root checkout's copy. **After:** both exit 1 with `status_surface_on_ref` and a remedy (materialize the coordination worktree, or check out the topic branch), and a status source the read door cannot resolve exits 1 with `status_surface_unavailable`. **What to do:** run the printed remedy, then re-run the command; scripts that treated an empty `events tail --once` as "no events" should check the exit code.
- **Lane cleanup is the last step of `spec-kitty consolidate`** (#7280). **Before:** lane and coordination checkouts and branches were removed in the middle of the run. **After:** they are removed only after the landing is verified, under the destructive guard, with one line per lane: `Removed`, `Kept` (the guard refused; the line names the code) or `Retained` (retention policy); a `Kept` lane does not fail the run. An interrupted cleanup resumes from a `cleanup_started` marker, and `--abort` after it rolls nothing back and prints `git branch <b> <sha>` recreate hints. **What to do:** remove a `Kept` lane yourself once you have checked what the guard named.
- **Lane cleanup goes through the landed-removal guard, and `accept --mode pr` and `doctor workspaces --prune` clean up a released Mission's lanes** (#7280, #7275). **Before:** `consolidate` removed lane worktrees with the older guarded primitives, `accept --mode pr` printed raw `git worktree remove` and `git branch -d` advice, and `doctor workspaces --prune` always reported a Mission lane as report-only. **After:** `consolidate` and `orchestrator-api consolidate-mission` remove each lane through `guarded_landed_removal`, proving the local target is still at the PASS tip (a moved target keeps the lane with `LOCAL_TARGET_OFF_GATE_TIP`); a committed `accept --mode pr` removes every lane the pushed pull request head already carries and keeps the rest with `NOT_LANDED_ON_NAMED_REMOTE`; `doctor workspaces --prune` treats a lane of a consolidated or pr-accepted Mission as a candidate when no consolidation record is active and no retention is declared. A moved lane, or one with no process probe (macOS, Windows), is kept and reported. **What to do:** after a pull request lands, run `spec-kitty doctor workspaces --prune` for any lane that was kept.
- **Lane cleanup keeps a lane whose work never landed, and `accept --mode pr` honors lane retention** (#7280). **Before:** a lane `consolidate` did not land, such as one whose work packages were all canceled, was deleted with no ref left to restore it, and `accept --mode pr` removed the lanes of a Mission created with `--retain-worktrees` / `--retain-branches`. **After:** the first is kept with `NOT_LANDED_ON_NAMED_REMOTE`, and the second reports its lanes `Retained`. **What to do:** remove a kept lane yourself once you no longer need its commits.
- **Lane checkouts no longer carry the Mission's status files** (#7281). **Before:** every lane worktree held its own copy of `status.events.jsonl` and `status.json`, which could drift from the status surface. **After:** a managed sparse exclusion keeps both files out of every lane checkout, and a status write aimed at a lane checkout refuses with `STATUS_WRITE_TARGETS_LANE_CHECKOUT`. **What to do:** run status commands from any checkout; the CLI writes to the status surface.
- **A Mission's default topology is settled by size at the first `finalize-tasks`** (#7282). **Before:** `agent mission create` without `--topology` chose `coord` or `lanes` from the current branch. **After:** create mints one Mission topic branch and no worktree on every target; the first `finalize-tasks` keeps `single_branch` for at most two work packages or at most one code lane, and otherwise settles `lanes_with_coord` with the topic branch as the coordination branch (ADR `2026-11-06-3`). `--validate-only` only previews, and a failed settlement is undone and refuses with `TOPOLOGY_SETTLEMENT_REFUSED`. `consolidate` refuses the coordination teardown, keeping the branch, while the topic branch holds planning changes the target does not carry. **What to do:** pass `--topology` to choose a topology yourself; `lanes` and `coord` are explicit-only.
- **Core skills and agent guidance teach the shipped lane model** (#7285). **Before:** skills taught `merge`, manual stale-lane recipes (`cd .worktrees/...` and `git merge`) and hand status commits. **After:** they teach `consolidate`, status reads through the CLI, cleanup as the last step and the for_review gate on the lane branch; the stale-lane remedy prints `spec-kitty agent action implement <WP> --mission <handle>`. **What to do:** run `spec-kitty upgrade` to refresh the generated skills.
