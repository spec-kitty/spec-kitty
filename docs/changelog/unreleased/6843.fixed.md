- **`spec-kitty upgrade` no longer re-identifies a Mission whose `meta.json` it cannot see in the working tree** (#6673). **Before:** a `kitty-specs/<slug>/meta.json` that git tracks but the working tree had lost (an accidental `rm`, a sparse checkout) was rebuilt from the directory name by the `2.0.6` sweep, the `3.2.0a4` normalization then minted a fresh `mission_id` into it, and the runtime-state cutover wrote a `{"status_phase": "1"}` stub when the file was still missing, so the next `git add -A` committed a second identity for a Mission whose history used the first. **After:** the sweep rebuilds the file from the copy git holds and the Mission keeps its `mission_id`; when that copy cannot be read (a corrupt committed file, or one staged but never committed) nothing is written for it and the output names `git checkout -- kitty-specs/<slug>/meta.json`. **What to do:** nothing; a Mission without a readable tracked copy now waits for that one command instead of silently changing identity ([upgrade notes](../guides/how-to/installation/upgrade-project.md#if-a-mission-s-meta-json-is-missing)).
