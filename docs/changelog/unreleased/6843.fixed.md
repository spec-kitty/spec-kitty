- **`spec-kitty upgrade` no longer re-identifies a Mission whose `meta.json` it cannot see in the working tree** (#6843, #6673). **Before:** a `kitty-specs/<slug>/meta.json` git tracked but the working tree had lost (an accidental `rm`, a sparse checkout) was rebuilt from the directory name by the `2.0.6` sweep, the `3.2.0a4` normalization then minted a fresh `mission_id` into it, and the runtime-state cutover wrote a `{"status_phase": "1"}` stub when the file was still missing, so the next `git add -A` committed a second identity. **After:** the upgrade rebuilds the file from the copy git holds and the Mission keeps its `mission_id`; a copy that lost its `mission_id` takes the tracked one back; an unusable tracked copy is left alone and the output names the repair. **What to do:** nothing ([upgrade notes](../guides/how-to/installation/upgrade-project.md#if-a-mission-s-meta-json-is-missing)).
