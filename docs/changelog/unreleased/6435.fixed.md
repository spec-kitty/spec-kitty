- **An org-required artifact is written to an activation list by its file name, not by its declared id** (#6435). **Before:** activating any artifact of a kind whose absent key means "only what the org packs require" (skills) materialised the org's `required_<kind>` list verbatim, so the written list carried a declared id beside a file name — `activated_skills: [acme-skill-id, other-skill-file]` for a `required_skills: [acme-skill-id]` declared by `acme-skill-file.skill.yaml` — and activating the required artifact by its declared id stored both spellings of it. **After:** that floor is read through the same identity authority every other writer uses, so each entry is stored by its file name (ids inherited through an `extends:` chain included), a colliding required id is still refused with `ActivationIdCollisionError`, and the effective set's fallback path applies the same one rule. Existing lists are not migrated; they take the new spelling on their next write. **What to do:** nothing.
