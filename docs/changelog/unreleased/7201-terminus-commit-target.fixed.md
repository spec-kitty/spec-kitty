- **`spec-kitty consolidate --target <branch>` now commits the terminus retrospective onto `<branch>` instead of refusing it** (#7201). **Before:** the retrospective bookkeeping commit resolved its destination from `meta.json`'s `target_branch`, so after a `--target` landing `safe_commit` warned `HEAD is '<branch>', expected 'main'`, refused the commit, and left `retrospective.yaml` plus its `status.events.jsonl` append uncommitted for the operator to commit by hand; the suggested recovery, `spec-kitty mission close`, resolved the same stale target and refused too. **After:** the consolidate run hands the terminus the landing target it already resolved, so both files are committed on that branch with no manual step, and `mission close --target <branch>` heals a Mission refused before this fix (the warning now prints it). The commit guard and the fail-open policy are unchanged.
