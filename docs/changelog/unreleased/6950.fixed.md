- **A custom mission type that produces code can no longer reach review with nothing implemented** (#6328; with #6327). **Before:** the review-readiness prerequisite that asks for implementation commits on the work package's lane ran only for the `software-dev` family, so an activated custom code-producing type passed `move-task --to for_review` with an empty lane and the gap showed up only later. **After:** a mission type carries a `code_producing` capability — `software-dev` true; `research`, `documentation` and `plan` false; an undeclared custom type false — and the prerequisite reads it, so a custom code-producing type is refused and names the missing commits, while `research`, `documentation` and `plan` behave exactly as before. **What to do:** a custom type that produces code declares `code_producing: true` in its mission-type descriptor; a type that produces none declares nothing and keeps its current flow. The #6715/#5939 evidence gates are unchanged.
