- **`doctor workspaces --prune` keeps commits that only a destroyed reflog still reached** (#7211). `git worktree remove` deletes the worktree `HEAD` reflog and `git branch -D` deletes the branch reflog, so a commit made while the worktree was detached, or one dropped with `git reset --hard`, was reachable from nothing afterwards and the next `git gc` could collect it. **Before:** the prune dropped it silently. **After:** it is recorded under `refs/spec-kitty/discarded/reflog/<sha>` before anything is removed, named in the `kept_commits` key of the `--json` payload; an unwritable record refuses the removal. Only a commit the prune can prove is already on `origin/<primary>` — every commit between it and the primary patch-equivalent, with no merge among them — is not recorded, so a rebase landing keeps nothing extra; a merge commit always is, because no patch carries its resolution.
