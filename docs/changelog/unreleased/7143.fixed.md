- **`--owned-checkout` refuses a worktree that already belongs to a Mission** (#6956). **Before:** `spec-kitty agent mission create --owned-checkout <path>` admitted a registered coordination worktree or lane worktree, scaffolded the new Mission inside another Mission's write surface, and let the refusal arrive only afterwards; the read-only startup gates could consult such a checkout too. **After:** the create claim refuses either worktree up front with `OWNED_CHECKOUT_IS_MISSION_WORKTREE`, before any branch switch, commit or scaffold, and the same refusal covers `dispatch`, `profile-invocation complete` and `invocations list`. An ordinary linked owned checkout is unaffected, including one that lives under `.worktrees/` -- apart from the reserved `<slug>-lane-<id>` directory name, which now means "a lane worktree" at this claim.
