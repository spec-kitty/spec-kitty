- **`charter activate`, `charter deactivate`, `--preset` and the activation-ledger migration no longer lose a change to a concurrent synthesis run** (#6719). **Before:** those commands read the activation config (or the whole synthesis manifest, for the migration's stamp), then wrote it back outside the run-wide synthesis lock. A `charter deactivate` that landed inside a `charter synthesize` run's append window was overwritten — synthesis put the artifact back — or refused with `precondition_changed` and the artifact stayed in force; the migration's manifest stamp could drop entries the run had just written. **After:** each read-modify-write runs under the existing synthesis lock (#6453), so the two writers serialize. While another run holds the lock, these commands wait about 10 seconds and then exit 1 with `CHARTER_SYNTHESIS_LOCK_HELD`, naming the lock file, with nothing written (previously `charter activate` saved its change unlocked and skipped the re-stamp with a warning — that unlocked save was the race). `--dry-run`, `--dry-run-evidence` and `--list-topics` still take no lock.
