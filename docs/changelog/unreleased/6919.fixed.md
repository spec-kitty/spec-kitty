- **`agent retrospect synthesize` now plans generator-shape proposals, and a created record that plans nothing says so** (#6385). **Before:** every record `retrospect create` writes carries `proposals: []`, and even a hand-authored generator-shape proposal was dropped: `synthesize` printed `planned: [] applied: [] conflicts: []`, warned only when the record happened to carry a proposal, and exited 0. **After:** a generator-shape proposal may carry an optional `payload` block, validated by the same union `synthesize` applies; it is translated into a pending proposal and the JSON envelope and text output both report a `diagnostics` block naming the record shape, finding counts, translated/planned counts and every proposal that could not be translated with its reason. `retrospect create` no longer tells you to "review proposals" on a record that has none. Generator proposals are never auto-accepted, whatever `auto_applicable` says: select one with `--proposal-id` (with `--apply` to mutate); an id that is unknown or untranslatable is refused with the JSON error code `proposal_not_selectable`.
