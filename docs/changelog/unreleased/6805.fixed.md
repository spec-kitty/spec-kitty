- **`agent action implement` no longer leaves a shared lane's workspace context on the lane's first work package — the false `ACTIVE_WP_CONTEXT_STALE` warning is gone** (#6650; #3946). **Before:** claiming a second or later work package into an already-materialized lane through `spec-kitty agent action implement` re-entered the lane's self-heal but never refreshed the persisted workspace context, so `current_wp` kept naming the first work package, every later commit in the lane warned `ACTIVE_WP_CONTEXT_STALE`, and `spec-kitty context info` reported the wrong work package; PR #4584 had fixed the other two claim paths (`spec-kitty implement` and the orchestrator API's `start-implementation`). **After:** the command's reuse path routes through the same shared `refresh_reused_lane_context` helper (now all three claim paths), so the context follows the work package that just claimed the lane and later commits are quiet; a lane with no persisted context keeps that shape. **What to do:** nothing — re-claiming an existing lane is enough.
