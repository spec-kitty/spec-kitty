- **`spec-kitty agent tasks status` reads the same status log as every other command** (#7335, #7408). **Before:** for a coordination Mission whose coordination worktree was empty or not checked out, the board showed the repository root checkout's stale copy of the log while `next` and `consolidate` showed the coordination branch; a reopened Mission still read as merged. **After:** the board reads through the one status read door: it shows the coordination branch in that state, exits 1 on an unreadable log or ref instead of showing an empty board, and treats a Mission as merged only when `merged_at` is set (a Mission merged before #4090 restored `merged_at` no longer reads as merged in `next`). Origin-freshness lane selection, lane-tip cleanup and the review dependents warning read the same door.
