- **An upgrade refusal no longer tells you to `git checkout --` a file git could not read** (#7131). **Before:** when a Mission's `meta.json` was gone from the working tree and git could not answer for that checkout at all — an unreadable or garbled `.git` pointer, a `GIT_DIR`/`GIT_WORK_TREE` naming elsewhere, a checkout that git refuses on ownership grounds, or a damaged object store — the refusal called the **tracked** file "missing" and told you to restore it with `git checkout -- <path>`. Git never established that the path was tracked, and that command fails for the same reason. **After:** the refusal keeps its `TRACKED_META_UNAVAILABLE` code, mints no identity and writes nothing, but now names what could not be verified and which repair applies: fix the repository layout or environment (`git status` reports the cause), repair the object store (`git fsck`), or — where git refuses the checkout's ownership — decide deliberately to trust that one checkout (never a wildcard `safe.directory`). No trust setting is weakened or written for you. **What to do:** nothing until you meet the refusal; then repair the repository and re-run.
