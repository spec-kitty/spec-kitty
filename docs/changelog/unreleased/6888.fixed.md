- **Another Mission's lane worktrees can no longer block `implement` with a false "legacy sparse-checkout state"** (#6888, #6844). **Before:** the managed-lane check read lane policy only from the repository-root checkout's `kitty-specs/*/meta.json`, i.e. from whatever its current branch had committed, so on a branch that did not carry a (often long-merged) Mission's `kitty-specs/<slug>/` that Mission's own lane worktrees were classified as legacy state: `spec-kitty agent action implement` refused, and the refusal pointed at `doctor sparse-checkout --fix`, which would have disabled those managed lanes. **After:** a lane worktree's policy is also read from the lane's own `kitty-specs/<slug>/meta.json`, so the verdict is the same whichever branch the repository-root checkout stands on. Genuine legacy state still refuses, unchanged in wording and effect, and a lane carrying no `meta.json` of its own still blocks (fail closed). **What to do:** nothing — if you hit the old refusal, re-run without `--allow-sparse-checkout` and without running `doctor sparse-checkout --fix` on those lanes.
