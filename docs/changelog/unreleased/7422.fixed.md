- **Lane and recovery correctness fixes** (QW4, #7395). Six corrections across lane-id minting, the claim-ancestry gate, crash recovery and single-branch landing docs:
  - Per-lane test database names respect PostgreSQL's 63-byte identifier cap (#3122). **Before:** a long mission slug composed a name the engine silently truncated, collapsing distinct lanes into one database. **After:** an over-long name is truncated to 63 bytes with a stable sha1 digest suffix, so distinct `(mission, lane)` pairs stay distinct.
  - A failure of the claim-ancestry gate's recheck self-heal surfaces as the structured `ANCESTRY_NOT_ESTABLISHED` refusal at every claim seam (#3763). **Before:** the original exception escaped raw — a traceback at the `implement` CLI seam, a non-JSON crash at the `orchestrator-api` boundary. **After:** the gate wraps it in `AncestryNotEstablishedError` (the original failure chained as `__cause__`), and both seams render the structured envelope and exit non-zero.
  - Crash recovery globs `tasks/WP*.md` once per scan instead of once per candidate work package (#4523). **Before:** an N-WP mission ran N directory scans while computing `ready_to_start`. **After:** one sorted glob builds an id-to-file map consulted per WP; the first match is now deterministic (sorted order) instead of OS-order arbitrary.
  - `_list_mission_branches` recognizes a mission's branches through the canonical branch-name parser instead of trusting the glob's prefix (#5152). **Before:** `kitty/mission-057-foo*` also listed `kitty/mission-057-foobar-lane-a` — a different mission whose slug merely shares a prefix — so recovery could scan and act on a sibling mission's branches. **After:** only branches that parse to the exact recorded slug (or its `<slug>-<mid8>` recombination) are listed.
  - Lane-id minting fails closed when all 26 positional ids are claimed (#5155). **Before:** the minting loop walked past `z` into `{`, `|` and beyond, silently minting ids like `lane-{` that match no lane-id grammar. **After:** it raises `LaneIdExhaustedError` (error code `LANE_ID_EXHAUSTED`), so an over-wide mission is refused loudly instead of persisting malformed ids.
  - `is_single_branch_mission`'s docstring no longer claims `consolidate` refuses an unmigrated single-branch mission with code lanes (#7250). **Before:** it said `SINGLE_BRANCH_CODE_LANES_UNMIGRATED` trips first — no consolidation path runs that check. **After:** the docstring names the real callers (finalize-tasks, `implement`'s lane allocation, the review gate) and states that `consolidate` does not run the check.
