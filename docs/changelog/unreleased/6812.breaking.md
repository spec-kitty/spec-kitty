- **`events tail` follows every canonical ledger, and its default output is now human-readable** (#6611). **Before:** `events tail --mission <slug>` could tail only the mission's `status.events.jsonl`, and its `--json` flag was accepted but had no observable effect (JSON lines were the only mode). **After:** `--log <kind>` selects any of the seven canonical ledgers — `status` (default), `decisions`, `mission`, `run` (the mission's newest run journal), `glossary`, `ops` or `canonical`; an unknown kind is a usage error (exit 2) before any file access. Without `--json`, each event prints as one plain-text line (timestamp, event type, sorted payload; cursor keys omitted); `--log run` with no matching run journal refuses with a typed `run_log_unavailable` envelope, exit 1. **What to do:** pass `--json` to keep the machine envelope — byte-identical to the previous output on every kind, including `tail_offset`/`tail_invariant`, so `--from-offset`/`--from-invariant` resume contracts are unchanged (`docs query --json` precedent). Further log kinds are deliberately deferred.
