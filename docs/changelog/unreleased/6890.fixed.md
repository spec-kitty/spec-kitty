- **A project with no agent list no longer makes migrations and `doctor` act on every agent folder** (#6890, #6501). **Before:** a missing `.kittify/config.yaml`, or one with no `agents`/`tools` section, made the agent read return the whole registry, so `spec-kitty upgrade`, `doctor`, shim generation and `.gitignore` repair touched all 12 slash-command agents — rewriting or recreating folders the project never had. **After:** such a legacy project is treated as using the agents whose project directory it already has (`.github` needs its managed `prompts/` directory, since a CI directory is not a Copilot choice), the read warns once naming `.kittify/config.yaml` and `agents.available`, and it never invents a surface or widens past what is there. A project with no agent directory at all gets none. A stated list is unchanged: `available: []` still means no Spec Kitty-managed agents (#6494) and an unreadable config still fails closed. **What to do:** run `spec-kitty agent config add <agent>` to record the set and stop the warning.
