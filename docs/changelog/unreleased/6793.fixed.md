- **An org asset sidecar whose YAML is not a mapping no longer crashes the asset repository load** (#6735). **Before:** an `*.asset.yaml` (or any other kind's overlay sidecar, or a built-in file) whose top level was a list or scalar raised `AttributeError: 'list' object has no attribute 'get'` and aborted the whole repository construction — every `AssetRepository` consumer, and in `doctor charter-packs` the org asset containment check, which failed closed and hid every other named escape. **After:** a present-but-non-mapping document is treated as malformed exactly like invalid YAML or a schema-invalid file: it is skipped with the usual `Skipping invalid <layer> <kind> <file>: expected a YAML mapping, got <type>` warning, the repository loads, and every valid sidecar beside it still lands. Empty files stay absence (no warning). This holds for every repository kind sharing `BaseArtifactRepository`, in the org, project and built-in tiers.
