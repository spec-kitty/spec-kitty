- **`spec-kitty agent tasks status` reads the same status log as every other command** (#7335, #7408). **Before:** for a coordination Mission whose coordination worktree was empty or not checked out, the board showed the repository root checkout's stale copy of the log, while `next`, `consolidate` and the other status readers showed the committed coordination branch; a reopened Mission still read as merged on the board and in `next`. **After:** the board reads through the one status read door, so it shows the committed coordination branch in that state, refuses an unreadable coordination ref instead of showing an empty board, and treats a Mission as merged only when it has landed (`merged_at`, cleared by a reopen). The origin-freshness lane selection, the lane-tip cleanup at a terminal transition and the review dependents warning read the same door.
