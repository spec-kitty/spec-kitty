- **`doctor bytecode-cache` no longer trusts a checked-hash pyc whose source no longer matches** (#4531). **Before:** a pyc compiled with `--invalidation-mode checked-hash` was trusted on its flags alone, so a stale or tampered checked-hash pyc whose source had changed was reported healthy. **After:** a checked-hash pyc is trusted only when its embedded hash equals `importlib.util.source_hash` of the current source file; on any mismatch (or an unreadable source) it is reported as a finding, like an unchecked-hash pyc already was.
- **`doctor decisions` now reports unreadable ledger lines instead of silently skipping them** (#5304). **Before:** a corrupt line in the decisions event ledger (invalid JSON, a non-object row, a missing or non-object payload, or a non-string decision point id) was dropped from reconciliation, so `--json` reported a clean state and `--repair` could "succeed" over input it never read. **After:** `clean` surfaces the unreadable lines with their line numbers and reasons (human warning and a `unreadable_lines` JSON key), and repair refuses to run — exiting 1 — until the ledger is fixed.
- **`agent config lint-hooks` no longer crashes or substitutes defaults on a corrupt `.cursor/hooks.json`** (#5293). **Before:** a UTF-8 decoding error raised an unhandled exception, and a syntactically valid non-object JSON document silently fell back to the default hook configuration. **After:** both are reported as an unreadable-hooks warning and the command moves on without linting hooks against invented data.
- **`migrate repair-mission-meta` no longer mints a fresh mission id over a tracked, id-less `meta.json`** (#6833). **Before:** when git tracked a `meta.json` that carried no `mission_id`, the repair minted a brand-new ULID into it, silently diverging from the identity the repository had recorded. **After:** the repair reuses the tracked mission id when the tracked file carries one, and refuses — recording a validation error, writing nothing — when the tracked file is unavailable; a present-but-corrupt meta still fails loudly at read time.
- **`agent tasks migrate --issue-matrix` no longer silently drops rows with an unknown verdict** (#5453). **Before:** a matrix row whose verdict matched no known value was filtered out of the migration with no diagnostic reaching the operator. **After:** the migration raises, naming each dropped row's diagnostic and the allowed verdicts, instead of losing the row.
- **`migrate backfill-runtime-state --dry-run` no longer labels a would-fail mission "Skipped (already migrated)"** (#4044). **Before:** a mission whose fail-closed verify refused (for example a phantom work-package row injected into the event ledger) would neither flip nor seed, so the dry-run summary counted it under "Skipped (already migrated)" — although a live run reports it as Failed. **After:** the dry-run Skipped bucket counts only missions that are genuinely already migrated; a mission that would fail a live run lands in no bucket rather than under a label that lies.
