- **`spec-kitty doctor workspaces --prune` removes worktrees whose work has landed** (#7173). **Before:** landing worktrees and branches stayed after the merge. **After:** it gives every registered worktree a reasoned verdict: landed, not landed, unproven, or Mission-owned. `--prune` removes only worktrees whose commits are on local `origin/<primary>` (squash and rebase merges need git 2.38+), then their branches. Linux only: on macOS and Windows it removes nothing. It never fetches or uses `--force`; it prints a recreate command. It keeps dirty, locked, busy and Mission worktrees. `--fix` is unchanged. **What to do:** after a merge, run `git fetch origin`, then `spec-kitty doctor workspaces --prune`. Ignored files such as `.venv/` are listed, then deleted; see the [landing runbook](../development/how-to/pr-landing.md#12-after-the-merge-remove-the-landing-worktree) for other gaps.
- **`spec-kitty upgrade` no longer commits into non-Mission worktrees you did not name** (#7173). **Before:** it wrote and committed into every non-Mission worktree under `.worktrees/`, including landing worktrees. **After:** it skips them unless you name one with `--include-worktree PATH` (repeatable) or pass `--all-worktrees`. The preview lists every worktree and what will happen to it; the output lists what did happen. Mission worktrees are skipped as before, and a symlink that resolves outside `.worktrees/` is never selected. `--cli` or `--no-worktrees` with an opt-in flag exits 2. In `--plan-json`, `commit_policy.worktrees_enabled` now means at least one worktree is selected, so a plain run reports `false`. **What to do:** if a script relied on the old behavior, add `--all-worktrees`.
