- **The follow-up commit of a lifecycle command on a Mission without a coordination branch runs in the same checkout as the status commit** (#7633). **Before:** it always committed in the repository root checkout and ran its "already committed?" check in `.worktrees/<slug>-coord` whenever that directory existed, so a default Mission whose topic branch another checkout held failed with a HEAD mismatch after the status rows were already committed. **After:** both use the placement seam's status checkout, and a file in another checkout is never reported as already committed.
