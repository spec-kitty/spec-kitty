- **A default Mission's planning work package is worked and evidenced on its Mission branch until it lands** (#7860). **Before:** for a Mission created without `--topology` and settled to `lanes_with_coord`, planning work on the Mission branch was refused with `IMPLEMENTATION_MISSING`. **After:** `implement` names the coordination worktree; `move-task`, `accept`, `consolidate` and the orchestrator API judge one evidence window from the claim commit, and `consolidate` lands the work. The landing check credits each approved planning work package only for its own `owned_files` in commits after its claim, and a file only when every change to it since the recorded Mission base (a commit on the target) is credited; another file is refused as un-attributable, and no planning-lane note names it while the lane credits other work (#7891). The lane credits nothing when a planning work package is not approved, an `owned_files` list is unreadable or too broad, a claim commit is unproven or no usable Mission base exists; the refusal names the lane, reason and remedy. A Mission branch no checkout holds refuses with `PLANNING_CHECKOUT_MISSING`. Each work package is credited only up to its approval, and its `owned_files` are read as committed on the Mission branch, never from the working tree. See `docs/migrations/planning-lane-write-branch.md`.
