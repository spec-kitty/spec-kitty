- **A default Mission's planning work package is worked and evidenced on its Mission branch until the Mission lands** (#7860). **Before:** for a Mission created without `--topology` that settled `lanes_with_coord`, `implement` sent a planning work package to the repository root checkout on the target, the evidence check ended its window at the target, and work committed on the Mission branch was refused with `IMPLEMENTATION_MISSING`. **After:** `implement` names the coordination worktree, the evidence window runs from the commit that introduced the claim to the Mission branch (content written before the claim is never evidence), `move-task`, `accept`, `consolidate` and the orchestrator API judge that one window, and `consolidate` lands the work. The reconciliation claim `consolidate` checks the landing against now reads that planning lane's authorship from the Mission branch, crediting each approved work package only for its own `owned_files` and only for commits made on top of the commit that introduced its claim (a commit a merge brought in beside the claim is not, and no merge commit is credited, since a merge that resolved a conflict can carry a change made before the claim), admits a commit by SHA or patch-id only when every path it changes is credited that way or is Mission bookkeeping, and credits a file's final content or deletion only when every commit on the Mission branch that changed that file is credited for it, so an owned-file change made before the claim never lands as approved work through a later credited commit. The lane authors nothing, so the gate refuses that content as un-attributable, when any planning work package is not approved (canceled or in flight: the claim admits by path, not by author), when an `owned_files` list cannot be read or every list is empty, when a pattern has fewer than two literal leading path segments and names no top-level file (`src/**`, `src/*`, `src`, `docs/*.md`, ...), or when a work package's claim commit cannot be found; no attestation lifts this planning-lane credit rule. When the un-attributable content is the planning lane's, the refusal names the lane, the reason, the work packages and the remedy, with the work package ids and `--mission <slug>` filled in: a dropped work package that owes no work is recorded with `spec-kitty agent tasks move-task <WP> --to claimed --force --agent <implementer> --mission <slug>` (only when it was never claimed), `move-task <WP> --to approved --force --agent <reviewer> --mission <slug>` and `spec-kitty consolidate --mission <slug> --attest-no-implementation <WP> --attest-reason "<why>"` (recorded operator acts, the approval by another identity than the claim; the attestation answers only the owned-file evidence check); a too-broad `owned_files` is narrowed; for a claim commit that cannot be found, the work package is reopened with `move-task <WP> --to planned --review-feedback-file <file>` and claimed with `spec-kitty agent action implement <WP> --agent <agent>`, moved to `planned` once more and claimed again to start a new window when a claim event is recorded but cannot be proven (a move out of review keeps the old claim; with no claim event recorded the first claim starts the window), and its change is committed again, reviewed and approved again. A Mission branch no checkout holds refuses with `PLANNING_CHECKOUT_MISSING`. Other Missions and code lanes are unchanged.
