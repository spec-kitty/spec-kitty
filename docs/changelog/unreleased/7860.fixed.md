- **A default Mission's planning work package is worked and evidenced on its Mission branch until the Mission lands** (#7860). **Before:** for a Mission created without `--topology` that settled `lanes_with_coord`, `implement` sent a planning work package to the repository root checkout on the target, the evidence check ended its window at the target, and work committed on the Mission branch was refused with `IMPLEMENTATION_MISSING`. **After:** `implement` names the coordination worktree, the evidence window runs from the commit that introduced the claim to the Mission branch (content written before the claim never counts), `move-task`, `accept`, `consolidate` and the orchestrator API judge that one window, and `consolidate` lands the work. The reconciliation claim `consolidate` checks the landing against now reads that planning lane's authorship from the Mission branch, crediting each approved work package only for its own `owned_files` and only from the commit that introduced its claim, and admits a commit by SHA or patch-id only when every path it changes is credited that way or is Mission bookkeeping. The lane authors nothing, so the gate refuses that content as un-attributable, when any planning work package is not approved (canceled or in flight: the claim admits by path, not by author), when an `owned_files` list cannot be read or every list is empty, when a pattern has fewer than two literal leading path segments and names no top-level file (`src/**`, `src/*`, `src`, `docs/*.md`, ...), or when a work package's claim commit cannot be found; no attestation lifts it (take every planning work package to approved, or narrow the `owned_files`, and run `consolidate` again). A Mission branch no checkout holds refuses with `PLANNING_CHECKOUT_MISSING`. Other Missions and code lanes are unchanged.
