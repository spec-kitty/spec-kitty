- **A default Mission's planning work package is worked and evidenced on its Mission branch until it lands** (#7860). **Before:** for a Mission created without `--topology` and settled to `lanes_with_coord`, planning work on the Mission branch was refused with `IMPLEMENTATION_MISSING`. **After:** `implement` names the coordination worktree; `move-task`, `accept`, `consolidate` and the orchestrator API judge one evidence window from the claim commit, and `consolidate` lands the work. The landing check credits each approved planning work package only for its own committed `owned_files`, in commits between its claim and its approval, and a file only when every change to it since the recorded Mission base is credited; anything else is refused as un-attributable. The lane credits nothing when a planning work package is not approved, an `owned_files` list is unreadable or too broad, a claim commit is unproven or no usable Mission base exists; the refusal names the lane, reason and remedy. A Mission branch no checkout holds refuses with `PLANNING_CHECKOUT_MISSING`. See `docs/migrations/planning-lane-write-branch.md`.
