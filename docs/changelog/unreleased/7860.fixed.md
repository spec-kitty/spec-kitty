- **A default Mission's planning work package is worked and evidenced on its Mission branch until the Mission lands** (#7860). **Before:** for a Mission created without `--topology` that settled `lanes_with_coord`, `implement` sent a planning work package to the repository root checkout on the target, the evidence check ended its window at the target, and work committed on the Mission branch was refused with `IMPLEMENTATION_MISSING`. **After:** `implement` names the coordination worktree, the evidence window runs from the commit that introduced the claim to the Mission branch (content written before the claim never counts), `move-task`, `accept`, `consolidate` and the orchestrator API judge that one window, and `consolidate` lands the work. The reconciliation claim `consolidate` checks the landing against now reads that planning lane's authorship from the Mission-branch window (the planning commit to the Mission branch tip), scoped to the `owned_files` of its approved work packages only, and admits a commit by SHA or patch-id only when every path it changes is in that scope or Mission bookkeeping; a canceled work package's paths, a commit that also changes a path outside the scope, and a whole-tree or inferred `src/**` ownership glob are left out, so the gate refuses that content as un-attributable. A Mission branch no checkout holds refuses with `PLANNING_CHECKOUT_MISSING`. Other Missions and code lanes are unchanged.
