- **The orchestrator API answers a refused status write with a JSON envelope instead of a traceback** (#5642, #5156). **Before:** `start-implementation`, `start-review` and `transition` caught only `TransitionError`, so a `BookkeepingError` from the transactional status write — a policy refusal, a status-lock timeout, an unresolvable worktree, or the `COORD_STATUS_SURFACE_DIVERGED` / `COORD_STATUS_SURFACE_UNREADABLE` guard — escaped as a raw Python traceback with an empty stdout, and a `StatusReadPathNotFound` raised outside the mission-resolution seam did the same. **After:** both are one JSON envelope with a non-zero exit. A refused status write reports `BOOKKEEPING_FAILED` and carries the refusal's own code in `data.bookkeeping_error_code` — `BOOKKEEPING_LOCK_TIMEOUT` for a retry, `BOOKKEEPING_POLICY_REFUSED` or `COORD_STATUS_SURFACE_DIVERGED` when an operator has to act. A read-path refusal keeps `STATUS_READ_PATH_NOT_FOUND` with its `data.coord_candidate` / `data.primary_candidate`, now guaranteed by the command group. API contract `1.26.0`. **What to do:** nothing — key on `error_code`, and read `data.bookkeeping_error_code` to tell a retry from an operator action.
