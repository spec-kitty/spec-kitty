- **An acceptance criterion can now be recorded `deferred`, with a reason and a follow-up reference** (#7308). **Before:** a criterion could only be `pass`, `fail` or `pending`, so a criterion the Mission had agreed to postpone held `overall_verdict` at `pending` and `spec-kitty accept` refused for good. **After:** `spec-kitty agent acceptance-verdict --criterion <id> --result deferred --reason "<why>" --follow-up <issue number, URL or ruling id>` records the deferral on the existing locked write path (the row carries `deferral_reason` and `deferral_follow_up`). A deferral without both is refused (exit 2 from the command; an evidence error that keeps the verdict `pending` if hand-written). A matrix of `pass` and justified `deferred` criteria reads `overall_verdict: pass`, and `accept` lists every deferred criterion: a `criteria_deferred` entry under `skipped_checks` in `--json`, and a "Deferred criteria" section in the console. `acceptance-verdict` also takes `--description` and `--notes` in criterion mode, so scaffolded "Verify FR-xxx" / "TODO" text no longer needs a hand edit. No `overall_verdict` value was added, so the `orchestrator-api` contract is unchanged.
