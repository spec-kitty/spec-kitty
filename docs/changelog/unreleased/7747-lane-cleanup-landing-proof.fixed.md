- **`spec-kitty consolidate` and `spec-kitty doctor workspaces --prune` remove the lanes of a squash-landed Mission** (#7747). **Before:** cleanup kept every lane with `NOT_LANDED_ON_NAMED_REMOTE`, and the printed `doctor workspaces --prune` remedy refused them with `CONTENT_NOT_ON_PRIMARY`. **After:** one landing proof sets aside Mission files a lane never wrote and judges `status.json` by its log; `consolidate` also proves each lane landed through the Mission branch, crediting only approved lanes' later changes, and keeps such a lane's `refs/spec-kitty/lane-tip/<branch>` so its superseded work stays recoverable (`orchestrator-api consolidate-mission` does not, so it keeps such a lane); `accept --mode pr` and `doctor workspaces` use the same proof. Unlanded work keeps its lane. After a push, `doctor workspaces` still keeps a lane whose lines a later lane rewrote.
- **A lane with no usable landing proof is kept, never deleted** (#7325). **Before:** a lane with no landing proof, an empty reconciliation PASS anchor, a missing worktree or no nameable tip went to the older remover, which could delete a branch holding unlanded commits. **After:** it is kept with `LANDING_PROOF_UNAVAILABLE`, its branch untouched, and the remedy compares content with `git diff` (or names the lane-tip ref when the branch is gone).
