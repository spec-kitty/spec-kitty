`spec-kitty consolidate` no longer refuses a lane as stale for a change the lane already contains (#7311). The stale check now counts a mission-branch path as overlapping only when a commit the lane does not contain changed it (a merge counts only for what its own resolution introduced), instead of diffing from a single merge base, which on a lane that depends on another lane could be an older base that made the dependency's change look missing. A genuine overlap still refuses, and a failed probe falls back to the stricter merge-base diff. The stale refusal's remedy no longer points at a `cd .worktrees/*-lane-x` glob that matches nothing when the worktree is absent; it names the lane branch and how to find or recreate its checkout.
