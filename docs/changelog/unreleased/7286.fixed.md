- **A pack skill whose `body_path` leaves its own folder is refused when it is read, not only when it loads** (#6734; follow-up to #6418). **Before:** the read that renders `SKILL.md` into your agent folders joined `body_path` with no check, so a symlink swapped after load served a file from outside the skill directory. **After:** load and read both go through the one containment check, `resolve_relative_path_within_root`. An absolute path, a `..` part or a symlink pointing outside is refused before anything is read. A contained path to a missing file still reports "not found". **Changed:** a `body_path` such as `nested/../body.md`, whose `..` resolves back inside, is now refused. **What to do:** write `body_path` relative to the `.skill.yaml` folder, with no `..`.
- **`charter status` and `charter org validate` report an org-pack path that escapes its pack, like `doctor charter-packs`** (#6733, #6731). **Before:** for a `drg/fragment.yaml` node whose `body_path` escaped the pack, the doctor exited 1 while `charter status --json` returned `org_layer.errors: []` and `charter org validate` exited 0, and `charter status` also missed an escaping asset sidecar `path`. **After:** all three report the same finding with the same message. `charter status` adds it to `org_layer.errors` (no new key), and `charter org validate` reports category `body_path_escape` and exits 1. Each judges the pack against the root it was loaded from, reading the pack registry once. A check that cannot run says so. The doctor's JSON is unchanged. **What to do:** nothing; fix any path these now report.
