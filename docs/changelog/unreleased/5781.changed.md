- **The `move-task` ownership guard now applies to orchestrator-claimed work packages** (#5781, operator ruling R28, parity). **Before:** an `orchestrator-api` claim recorded no `agent`, so no owner was shown and a host `move-task --agent <another tool>` went through. **After:** the claim records `agent` = `--actor` (orchestrator-api contract 1.30.0; no envelope field or `error_code` is removed), and a Mission that mixes an API claim by one tool with a host move by another gets the same `Agent mismatch` refusal a host-only Mission gets. Known residual: after a rollback to `planned`, the next claim's live `agent`/`shell_pid` slots read empty, because the shared reducer folds the release after every transition (#7794, `spec-kitty-events`). The implementer of record and acceptance are unaffected.
