- **A non-interactive git contact can no longer pop a GUI askpass dialog** (#5860). **Before:** `no_prompt_env` set `GIT_TERMINAL_PROMPT=0` but left `GIT_ASKPASS`/`SSH_ASKPASS` in force (including on the `GIT_SSH` early return), so a helper such as the VS Code askpass could still open a credential dialog during an unattended contact. **After:** both askpass variables are popped from the returned environment on every return path. spec-kitty clears both for every remote contact it makes: the origin-freshness reads, `clone_repository`, `fetch_tags` and `fetch_commit_subtree` (charter-pack git sources), and pack fetch and pack vendor. CI that authenticates through an askpass helper should configure a non-interactive `credential.helper` (or `http.extraHeader`) instead; spec-kitty leaves those untouched, so they cover every remote contact. `SPEC_KITTY_ORIGIN_CHECK=warn` is only a fallback that relaxes the origin-freshness gates alone; the `ORIGIN_UNREACHABLE` remedy says the same.
- **The atomic YAML temp-file create is hardened against symlinks** (#4847). **Before:** `write_mapping_atomic` created its temp file with a bare `os.open`, which already refused a pre-planted symlink on POSIX and Windows because `O_CREAT|O_EXCL` fails on it. **After:** the temp file is created through `kernel.no_follow.open_no_follow`, the shared symlink-refusing open primitive, as defence-in-depth hardening. On a platform without `O_NOFOLLOW`, a refusal now raises the named `NoFollowPathError`.
- **Bookkeeping commit surfacing: typed empty-changeset classification, an implicit subject that names the staged artifact, and a labeled protected-branch remedy** (#4610, #4837, #5319). **Before:** the commit router classified a benign empty changeset by prose-matching the exception message (a wording drift would misreport it as a real failure); an implicit bookkeeping commit subject named only the operation (`chore(spec-kitty): status transition batch WP01`), so several missions' commits were indistinguishable in `git log`; the protected-branch refusal offered `SPEC_KITTY_ALLOW_PROTECTED_BRANCH_COMMITS=1` with no label, burying the branch-level remedy. **After:** the router checks `isinstance(exc, SafeCommitStagedTreeUnchanged)` first with the prose match kept as a fallback; the implicit subject names the staged artifact areas, e.g. `chore(spec-kitty): status transition batch WP01 (kitty-specs/<slug>-<mid8>)`; the refusal and `REMEDY_PROTECTED_PRIMARY` name the topic-branch escape first (with `spec-kitty safe-commit <files> -m <message> --to-branch <branch>` as the example, since only `safe-commit` has that flag) and label the env var an operator-only override.
