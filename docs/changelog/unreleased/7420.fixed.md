- **A non-interactive git contact can no longer pop a GUI askpass dialog, and the atomic YAML write refuses a symlinked temp path** (#5860, #4847). **Before:** `no_prompt_env` set `GIT_TERMINAL_PROMPT=0` but left `GIT_ASKPASS`/`SSH_ASKPASS` in force (including on the `GIT_SSH` early return), so a helper such as the VS Code askpass could still open a credential dialog during an unattended contact; `write_mapping_atomic` created its temp file with a bare `os.open`. **After:** both askpass variables are popped from the returned environment on every return path, and the temp file is created through `kernel.no_follow.open_no_follow`, the shared symlink-refusing open primitive.
- **Bookkeeping commit surfacing: typed empty-changeset classification, an implicit subject that names the staged artifact, and a labeled protected-branch remedy** (#4610, #4837, #5319). **Before:** the commit router classified a benign empty changeset by prose-matching the exception message (a wording drift would misreport it as a real failure); an implicit bookkeeping commit subject named only the operation (`chore(spec-kitty): status transition batch WP01`), so several missions' commits were indistinguishable in `git log`; the protected-branch refusal offered `SPEC_KITTY_ALLOW_PROTECTED_BRANCH_COMMITS=1` with no label, burying the branch-level remedy. **After:** the router checks `isinstance(exc, SafeCommitStagedTreeUnchanged)` first with the prose match kept as a fallback; the implicit subject names the staged artifact areas, e.g. `chore(spec-kitty): status transition batch WP01 (kitty-specs/<slug>-<mid8>)`; the refusal and `REMEDY_PROTECTED_PRIMARY` name the topic-branch/`--to-branch` escape first and label the env var an operator-only override.
