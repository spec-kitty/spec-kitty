- **`spec-kitty agent release prep` classifies a work package as accepted from the reduced lane on the resolved status surface, and a corrupt status log fails the prep** (#6612). **Before:** the changelog draft took the last `to_lane` in file order from the primary checkout's `status.events.jsonl` and silently skipped corrupt lines, so an out-of-order or union-merged log put work packages in the wrong section — and under a coordination topology the stale primary copy was read instead of the coordination branch's authoritative log. **After:** every work package is classified by the canonical reducer (wall clock `at`, then `event_id`, with the approved-departure lift) over the mission's resolved status surface, read once per mission; a corrupt log fails loudly naming the mission and line, and a deleted coordination branch fails with its `doctor coordination --fix` remediation instead of classifying off the stale primary copy. An unmaterialized coordination worktree falls back to the work package frontmatter. **What to do:** nothing on a healthy repo; if prep names a mission whose declared coordination branch is gone, run `spec-kitty doctor coordination --fix`.
