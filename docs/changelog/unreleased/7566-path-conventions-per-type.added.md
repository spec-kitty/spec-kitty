- **Path conventions can be remapped for one Mission type** (#7748). **Before:** a `project.path_conventions` key remapped the path for every Mission type that declared it, so a content repository could not move software-dev's `workspace` to `packs/` without also moving documentation, plan and research. **After:** a mapping keyed by a Mission type (`project.path_conventions.software-dev.workspace: packs/`) applies to that type only; per key it wins over the plain value, which wins over the type's default. An unknown type, an unknown key or an invalid value stops `accept` with a configuration error. Plain values work as before.
- **A narrow path-convention waiver beside `--lenient`** (#7566). **Before:** the only in-command escape from a path-convention miss was `accept --lenient`, which also skipped the work-package metadata checks. **After:** `accept --waive-path-conventions --waive-reason "<why>"` makes the misses of remappable layout paths warnings for one run and records the reason on the acceptance history entry, while every other check stays strict (a missing Mission artifact such as `contracts/` still blocks unless `contracts: none` is declared); a Mission can declare the same for every run with `"path_conventions": "waived"` and a `"path_conventions_rationale"` in its `meta.json`. The failure text now leads with the per-type remap for the failing Mission type, names both waivers before `--lenient`, marks the `mission.yaml` copy as a last resort, and names `contracts: none` beside the `contracts/` suggestion.
