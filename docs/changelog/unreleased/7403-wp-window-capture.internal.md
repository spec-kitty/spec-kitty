- **Status events record the work-package window-open SHA** (#7403). Every move of a lane work package into `claimed` or `in_progress` now records `policy_metadata.wp_window`: the lane head, or a typed gap (`lane_branch_missing`, `capture_failed`). The move is never refused, and the value comes from the same lane-head reading as `lane_head`, so no extra git read is taken. A git failure while reading the lane head is recorded as `capture_failed` with cause `git_error`, never as a missing branch, and a failure detail names neither the repository root nor the home directory. One codec in `specify_cli.status` writes and reads the value, and it accepts SHA-256 object names; at consolidation a git error while checking a recorded value refuses instead of reading as a gap. Like `lane_head`, the record does not mark a Mission as carrying runtime state for the cutover check.
