- **The decisions runtime lock is never uncommitted work and never committed** (#7498, #7540). **Before:** every decision command left `kitty-specs/<mission>/decisions/index.json.lock` on disk (by design: the lock file is never deleted, so a waiting process keeps its lock), and in a project without a `*.lock` ignore rule it showed up as an untracked file in the repository root checkout and in worktrees. `spec-kitty safe-commit` and `spec-commit` committed it when it was among the files passed, and a branch that tracked it later collided with the local copy when it landed ("would be overwritten by reset --hard"). **After:** the first decision command in a clone adds the lock to the clone's `.git/info/exclude` (never committed), so no checkout lists it, and every Spec Kitty commit refuses to stage it with `SAFE_COMMIT_PATH_POLICY`, even with `SPEC_KITTY_ALLOW_PROTECTED_BRANCH_COMMITS=1`. A reset refusal now also names the obstructing file's state in words ("untracked", or "ignored by a .gitignore or exclude rule"). A lock that a branch already tracks is still repaired with `spec-kitty agent decision repair-runtime-lock`.
- **Spec Kitty creates `.git/info/exclude` when a clone has none, and never appends a rule to an unterminated last line** (#7498). Every local exclusion Spec Kitty writes (`.worktrees/`, `.spec-kitty/`, the decisions runtime lock) now creates a missing `.git/info/exclude` instead of skipping, so the rule lands even in a clone made from an empty template.
