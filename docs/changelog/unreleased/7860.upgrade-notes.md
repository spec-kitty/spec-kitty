- **Planning work of a default Mission already in flight that was committed on the target branch no longer counts as its evidence** (#7860). No migration runs. A planning work package whose owned change sits on the target only is refused with `IMPLEMENTATION_MISSING`, and the refusal names those commits and both remedies: cherry-pick them onto the Mission branch in the coordination worktree (`.worktrees/<slug>-coord`), or, if the work package owes no implementation, run `spec-kitty accept` or `spec-kitty consolidate` with `--attest-no-implementation <WP> --attest-reason "<why>"`. See `docs/migrations/planning-lane-write-branch.md`.
- **A default Mission created on 4.0.0rc8 or earlier still gets no credit for its planning lane's work at `consolidate`** (#7860, #7560). It records no `mission_base_sha` (written at create from 4.0.0rc9 on), and a base derived from its first commit is not trusted, so its planning work packages' owned files are refused as un-attributable, as before. Remedy: record the commit on the target that `git merge-base <target> <scaffold>^` prints (the refusal fills in the start) as `mission_base_sha` in meta.json, commit it on the Mission branch, then run `spec-kitty consolidate --mission <slug>` again. A value that is not a commit on the target is not used. No command records the base yet (#7892). See `docs/migrations/planning-lane-write-branch.md`.
