- **Status reads go through one read door** (#7277). **Before:** readers resolved a Mission's status through several path helpers, and an empty coordination worktree could read as an empty history. **After:** `status/read_surface.py::resolve_status_read` picks one source per topology and coordination state (ADR `2026-11-06-2`): the coordination branch, the Mission branch or the checkout that holds it, or the target once the Mission has landed; consolidation's status readers use it, and `materialize` on a ref-sourced status exits 1 with `status_surface_on_ref` and a remedy. **What to do:** read status with `spec-kitty agent tasks status`, never from a lane checkout.
- **The `for_review` gate counts commits on the lane branch** (#7278). **Before:** its verdict depended on a guess about the checkout topology and on whether a lane checkout existed. **After:** it counts `git rev-list <base>..refs/heads/<lane>` from the repository root, with the same verdict on every surface, and a missing lane branch refuses with `LANE_BRANCH_MISSING`. **What to do:** nothing.
- **`single_branch` Mission branches are bounded by per-work-package approval windows** (#7283). **Before:** a `single_branch` Mission landed its Mission branch without checking commits against approvals. **After:** consolidation runs the approval-stamp check on the Mission branch and refuses with `LANE_MOVED_AFTER_APPROVAL` any content commit that lies in no approved work package's window, from its first claim stamp to its newest approval stamp, naming the work package approved before it. **What to do:** rework, review and approve that work package again.
