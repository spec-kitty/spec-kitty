- **`spec-kitty upgrade` no longer re-runs the legacy mission migrations on a machine whose `~/.kittify` has never been bootstrapped** (#6946, #6551). **Before:** `uses_centralized_runtime` asked whether `~/.kittify/cache/version.lock` existed before it read the project's own `metadata.yaml`, and `upgrade` deliberately does not bootstrap that home first. On a second machine or a CI runner whose first spec-kitty command was `upgrade`, `0.6.7_ensure_missions` and `0.12.0_documentation_mission` answered "not centralized" for a 4.x project, copied the packaged missions into it, and the upgrade auto-committed them — after which the project resolved all three built-in `mission.yaml` from those frozen copies. **After:** a readable `metadata.yaml` stamped 2.0.0 or later decides on its own, so the same commit gives the same answer for everyone; the home is consulted only for a project with no metadata stamp. **What to do:** nothing. A project that already carries such overrides is repaired under #6548.
