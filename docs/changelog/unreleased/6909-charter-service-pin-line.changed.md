- **Pinning a service now defaults to that service's own release repository, and a GitHub bump verifies the release's build provenance before it writes the pin** (#6909). **Before:** every `spec-kitty service vendor` bump defaulted to `spec-kitty-events`, the charter service's asset prefix was marked provisional, and a bump trusted the release's `SHA256SUMS` alone. **After:** `charter-service` defaults to `spec-kitty-charter` (the events services stay on `spec-kitty-events`), and each downloaded asset is checked with `gh attestation verify` (signer workflow and source tag ref) before `pins/<service>.source.yaml` is written. A refusal leaves the lockfile unchanged, and `--no-attestation` is the explicit escape for an offline mirror or a rehearsal; a `file://` pin and an installed CLI's fetch still verify the pinned digest only. See [Service pins](../development/how-to/service-pins.md).
