- **`upgrade --project` no longer stalls forever on a legacy Mission whose `meta.json` `mission_id` is its own slug** (#6689). **Before:** `migrate backfill-runtime-state` minted its claim seed row with no `mission_id`; reading that row back re-resolved it through `meta.json` and re-attached the slug, so its own fail-closed verify reported `claim mismatch (deterministic seed payload diverged)` on every run and left `status_phase` untouched — one accepted historical Mission blocked the runtime-state cutover for all the others, and no on-disk state could satisfy the check. **After:** the seed row carries the `mission_id` `meta.json` declares, which is exactly what the reader already re-derives, so the seed and its verifier agree, the Mission flips, and a re-run appends nothing. Seed ids, ordering and the fail-closed posture are unchanged, and a project already half-migrated by the old build converges without hand-editing. **What to do:** re-run `spec-kitty upgrade --project` (or `spec-kitty migrate backfill-runtime-state --mission <slug>`).
