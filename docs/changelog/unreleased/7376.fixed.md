- **A lifecycle payload the published contract rejects is now refused at emit time instead of being written** (#6438). **Before:** `MissionReopened`, `FollowUpRecorded` and `ReviewerSelfApproval` were written to `status.events.jsonl` from a hand-built dict, so a field the `spec-kitty-events` model rejects — an empty `reason`, `recorded_by` or `failure_reason` — reached the status event log and was only caught later by a consumer. **After:** the three emitters build `MissionReopenedPayload`, `FollowUpRecordedPayload` and `ReviewerSelfApprovalPayload`, so such a payload raises at emit time and nothing is appended, while a valid emit persists the same row as before and existing lines are never rewritten. `spec-kitty mission reopen --reason ""` now refuses with `reason_required` and writes nothing. **What to do:** nothing; give `mission reopen` a non-empty `--reason`.
