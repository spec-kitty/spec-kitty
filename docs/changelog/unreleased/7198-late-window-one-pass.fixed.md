- **`spec-kitty consolidate` approves a late coordination commit only once every change in it is proved landed, on a first run and on `--resume` alike** (#7198, #7199, #7265). **Before:** the late-window proof covered only coordination records, so a status event committed on the coordination branch from another checkout, or a late `meta.json` edit, was approved and deleted with the branch at exit 0. A `--resume` that landed a commit made after its own capture still refused with `compare-and-swap failed`; you had to resume twice. **After:** the window is read once, at the coordination tip the teardown opened it on. Every change in it is landed, proved or refused: status events by event id in the target's committed log, `status.json` only while it is that log's derived snapshot, a target-authored document when the window's change is already on the target's copy. Anything else refuses with `Error code: COORD_LATE_PROJECTION_REFUSED.` and keeps the branch, worktree and marker. A proven tip becomes the tip teardown approves on both run kinds, so a resume finishes in one attempt. **What to do:** follow a refusal's own repair, then re-run.
