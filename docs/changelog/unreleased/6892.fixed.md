- **An upgrade no longer restores the per-project `spec-kitty.*` command files that 3.1.2 retired** (#6547). **Before:** a project whose migration ledger was adopted before 4.0.0rc8's adoption floor (that first ledger-era upgrade recorded what `metadata.yaml` listed and nothing else) had the two pre-globalize writers re-selected: `2.1.4_enforce_command_file_state` and `3.0.2_restore_prompt_commands` read the files 3.1.2 removed as *missing* and wrote 14 back, while `3.1.2_globalize_commands` and `3.2.0a4_safe_globalize_commands`, already recorded, were skipped. The upgrade exited 0, and because `init` gitignores `.claude/`, `git status` stayed clean. **After:** both writers are recorded no-ops superseded by `3.2.0a4_safe_globalize_commands`, so the upgrade keeps the removed state whatever the ledger holds, and a `spec-kitty.*` file of your own is never touched. **What to do:** nothing; delete any copies an earlier upgrade restored.
