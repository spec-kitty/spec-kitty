- **The project-intent rename keeps a deactivation instead of silently lifting it** (#6565). **Before:** the `mission-type-scope-directive` → `project-intent-directive` rename (`#6443`, run by `spec-kitty upgrade`, `charter synthesize` and `charter resynthesize`) rewrote the activation allow lists only. A project whose exclusion named the old stem — a refused or skipped rename, then `charter deactivate`, then a later rename — was left with an entry naming a stem that no longer existed, reported as `DENY_UNKNOWN_ID`, and the renamed `project-intent-directive` came back into force. **After:** the rename moves the exclusion to `NNN-project-intent-directive` in the same ledger write as the allow list, so the directive stays deactivated; every other exclusion is untouched, and an entry spelled as a declared id is not renamed. **What to do:** nothing; run `spec-kitty upgrade` as usual (or `charter resynthesize`) on an affected project.
