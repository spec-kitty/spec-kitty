- **A malformed `charter_packs` registry is now refused with the same code by `charter activate` and `charter deactivate`** (#6772). **Before:** `charter activate` reported `ACTIVATION_FAILED` for a malformed `charter_packs` value in `.kittify/config.yaml` (`[1, 2]`, for example) while `charter deactivate` reported `ACTIVE_CHARTER_CONFIG_INVALID`, because the two verbs read the org pack registry through different paths. **After:** both verbs report `ACTIVE_CHARTER_CONFIG_INVALID`, in text and `--json`, exit 1 and write nothing. A declared org pack that was never fetched keeps its distinct `ACTIVATION_FAILED` refusal on `activate`, with the `spec-kitty charter fetch` remedy in the message. **What to do:** nothing for most callers. `doctor` and the orchestrator-api are unaffected, since they do not go through the strict `resolve_pack_chain(strict=True)` seam. Tooling that branches on the old `ACTIVATION_FAILED` code for a malformed `charter_packs` registry must now match `ACTIVE_CHARTER_CONFIG_INVALID`.
