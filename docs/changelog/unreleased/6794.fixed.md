- **A compact `--agent` value no longer stores whitespace identity or silently drops segments past the fourth** (#6755). **Before:** `--agent "claude: :"` stored `model: " "`, `--agent "claude\n"` stored `tool: "claude\n"`, and `--agent "a:b:c:d:e"` was silently truncated to `tool: a, model: b, profile: c` with `d:e` dropped on `move-task`, `mark-status` and `add-history`. **After:** every segment is stripped, a segment that is blank after stripping is treated as absent (`null`), and a value with more than four segments is refused before any write with the existing clean refusal `Invalid --agent value: Too many segments in --agent value: … (expected at most 4, got 5)`; a tool that is blank after stripping is refused as an empty tool, as before. Free-text `--actor` values on `agent status emit` and `orchestrator-api`, and recorded identities, keep being stored whole (#6400). **What to do:** nothing if you passed well-formed `--agent` values; a value that now refuses was silently losing segments before.
