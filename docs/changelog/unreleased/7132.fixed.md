- **Semantic-check events now record the glossary strictness the generation gate actually enforced** (#7065). **Before:** `SemanticCheckEvaluated` was emitted before the gate resolved strictness, so every event published `effective_strictness: "medium"` and derived `blocked` from `strictness != "off"`: a run configured `off` was logged as a blocking `medium` run, a `max` run was under-stated, and a medium-severity conflict under `medium` was logged as blocked although the gate let it through. **After:** the gate, the semantic-check middleware and the emitter share one resolution path, so the event carries the configured value (global, mission, step or `--strictness`) and `blocked` mirrors the gate's decision. `spec-kitty glossary conflicts --strictness off|medium` lists the conflicts the gate let through with their real type and strictness. Gate behavior is unchanged.
