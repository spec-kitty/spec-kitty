- **Semantic-check events now record the glossary strictness the generation gate actually enforced** (#7065). **Before:** the check emitted `SemanticCheckEvaluated` before the gate resolved strictness, so the event always published `effective_strictness: "medium"` and derived `blocked` from `strictness != "off"` — a run configured `off` was logged as a blocking `medium` run, a configured `max` run was under-stated, and under `medium` a medium-severity conflict was logged as blocked although the gate let it through. **After:** one resolution path serves the gate, the semantic-check middleware and the emitter, so the event carries the configured value (global, mission, step or `--strictness`) and its `blocked` flag mirrors the gate's `should_block` decision for that check. Gate behavior is unchanged; a conflict resolved interactively is recorded as found-and-then-resolved.
