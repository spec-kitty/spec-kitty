- **The lifecycle-envelope upgrade migration marks a rewritten legacy row unclocked instead of clocking it at zero** (#6906, #6414; #6411). **Before:** the `migrate_lifecycle_envelope` upgrade step stamped `lamport_clock: 0` on every legacy row it rewrote, a row that never recorded a causal clock. Since `spec-kitty-events` 11.0.0 made `Event.lamport_clock` optional, `0` is a *real* clocked position: the row sorted after every never-migrated (unclocked) row of the same log regardless of its timestamp, and joined one "concurrent" group with every other migrated row. **After:** those rows carry `lamport_clock: null`, the contract's own unclocked representation, so they keep their real timestamp order relative to newer rows. The rewrite stays byte-identical on a re-run, and a row an older migration already stamped `0` is left untouched. **What to do:** nothing; the change applies at the next `spec-kitty upgrade`. See [Consumers of the optional clock](../development/reference/optional-lamport-clock-consumers.md).
