- **A caller-supplied `migration:` actor is refused, so only an in-process migration can write a reconstruction seed** (#6754). **Before:** `agent status emit --actor migration:x`, the four `orchestrator-api` lifecycle verbs and the hidden `implement --actor` stored the value verbatim, and `is_migration_actor` then treated that event as a reconstruction seed — exempt from the review-exit note rule, skipped by timestamp continuity and invisible to consolidation work windows — so a caller could make a live transition look like reconstruction. **After:** those surfaces refuse an identity starting with `migration:`, exit non-zero and write nothing; the value is never rewritten into a live-looking actor. An explicit `--agent migration:x` is unchanged (read as `tool:model:profile`, so its tool is `migration` and it is not a seed), a recorded `migration:` identity keeps its seed status when re-recorded, and stored logs read exactly as before. **What to do:** drop `migration:` from any scripted `--actor` and pass the live identity instead.
