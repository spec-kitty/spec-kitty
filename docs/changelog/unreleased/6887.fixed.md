- **Activating or deactivating a built-in mission step contract now reaches the graph node it names** (#6887, #6741). **Before:** the DRG identifies a step contract by its owning pair (`mission_step_contract:documentation/accept`), while every activation surface resolved the contract's declared id to `mission_step_contract:documentation-accept` — a URN no node carries. Activating one made `charter consistency-check` report a graph gap whose only remedy was `charter resynthesize`, which cannot help, and deactivating one by its declared id had no effect at all. **After:** the activation filter, the config↔graph parity check and the deny sets all resolve tokens through one identity authority, so an activated step contract is kept, a deactivated one is dropped, and a step contract whose owning mission type is inactive gets a suggestion naming `mission_type_activations` instead of a pointless resynthesis. A new architectural gate fails if a shipped graph URN and the declared identity of the artifact it names ever disagree again. **What to do:** nothing.
