- **`spec-kitty next` and `orchestrator-api answer-decision` commit the event row they write into the coordination worktree** (#5938). **Before:** every `next --result success` appended to `kitty-specs/<mission>/mission-events.jsonl` in the coordination worktree and left it untracked, so `consolidate` refused a `next`-driven coordination Mission with `MERGE_UNSAFE_WORKTREE_DIRTY` until someone committed the file by hand. **After:** both commit that one file there (`chore(next): record next invocation for <mission>`); nothing else in the worktree is staged, a refused commit is reported as a warning (on stderr, or in `answer-decision`'s `warnings`) instead of failing the command, and a lane cut from the coordination branch afterwards still moves to review (the lane guard accepts the inherited log the way it accepts the inherited status files).
- **`spec-kitty next` also commits its event row in the repository root checkout** (#5938). **Before:** on a `single_branch` or `lanes` Mission the row was appended to the root checkout's `mission-events.jsonl` and left uncommitted. **After:** it is committed there too; the row of a Mission that has already landed is never committed, and a refused commit outside a coordination worktree is not reported, because the claim gate already tolerates that row.
