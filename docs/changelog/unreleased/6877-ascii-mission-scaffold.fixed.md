- **A new mission's own scaffold no longer fails `spec-kitty validate-encoding`** (#6877). **Before:** `tasks/README.md` was rendered from a template carrying a U+2013 en dash and a box-drawing tree, so `validate-encoding --mission <slug>` reported `Needs Fix` for a mission whose only content was the scaffold the tool had just written - and `--fix` then rewrites the prose the operator authored too. `setup_feature_directory` carried a second, hand-inlined copy of the same document that had drifted from it. **After:** the scaffold is ASCII by construction and renders from one constant that both entry points read; the WP-frontmatter example uses the `at:`/`actor:` history fields the pack template documents. A pin asserts every rendered byte is below `0x80`, that the gate's own detector finds nothing, and proves it can fail when a glyph is injected. **What to do:** nothing - existing missions keep their glyphs and `--fix` still repairs them. The four `packs/built-in` templates are fixed upstream (`spec-kitty-open-packs` 112), not here.
