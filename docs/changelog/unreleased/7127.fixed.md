- **Claiming a work package no longer invalidates the recorded analysis** (#7127, #7106). **Before:** the first `agent action implement WPxx` wrote its own runtime bookkeeping — `base_branch`/`base_commit`/`created_at` into the work-package prompt, the VCS lock into `meta.json` — inside the analysis-freshness fingerprint, so every later claim, and every rework re-claim, was refused with `analysis_report_required` until an unchanged `/spec-kitty.analyze` report was re-recorded. **After:** the fingerprint excludes exactly those runtime keys (and a rejected work package's `tasks/<wp>/` review artifacts), so a mission records the analysis once and claims all of its work packages; edits to `subtasks`, `dependencies`, `requirement_refs`, `owned_files`, a prompt body or an added work package still make the report stale, and an unexpected `vcs` value still refuses the claim. A report recorded under an older release after a claim or a rework is reported stale once after the upgrade; re-record it.
