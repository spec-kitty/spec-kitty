- **`spec-kitty review` no longer overwrites a mission review it did not write** (#7753). **Before:** it replaced `kitty-specs/<slug>/mission-review-report.md` unconditionally, so an agent-written mission review saved under that name was lost, with no backup. **After:** it still refreshes its own previous machine report, but when any other file is at that path it refuses with `MISSION_REVIEW_REPORT_PATH_OCCUPIED` (also as a JSON diagnostic line), writes nothing and names the move to `kitty-specs/<slug>/mission-review.md`. It checks before any gate runs and again at the write, so a review saved while the gates run is also kept. The `spec-kitty-mission-review` skill now saves its report at `kitty-specs/<slug>/mission-review.md`. The retrospective generator reads that file too, by the same rule as `mission-review-report.md`.
