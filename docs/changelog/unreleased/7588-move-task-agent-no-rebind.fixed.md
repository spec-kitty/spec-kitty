- **`move-task --agent` on a rejection no longer makes the reviewer the work package's owner** (#7588). **Before:** `move-task WP01 --to planned --agent <reviewer>` recorded a differing reviewer as owner. Another implementer's claim was then refused with "Agent mismatch … Use --force". **After:** on a move that hands a work package back for work, `--agent` records only who acted. That covers a move into `planned`, `in_review → in_progress`, `approved → in_progress`, and `for_review → in_progress`. A move into `claimed` is a claim and still records `--agent` as owner. A move into `planned` releases the claim, so any implementer can claim the work package without `--force`. The other hand-backs return it to its implementer of record, not the reviewer. To hand the work package to a named agent, pass `--assignee <agent>` on the same move. Every other move still records `--agent` as owner.
