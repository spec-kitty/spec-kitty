- **`move-task --agent` on a rejection no longer makes the reviewer the work package's owner** (#7588). **Before:** `move-task WP01 --to planned --agent <reviewer>` recorded the reviewer as owner when the reviewer differed from the current owner. Another implementer's claim was then refused with "Agent mismatch … Use --force". **After:** on a move that hands a work package back for work, `--agent` records only who acted. That covers a move into `planned`, `in_review → in_progress`, `approved → in_progress`, and a move back out of `for_review`. A move into `planned` releases the claim, so any implementer can claim the work package without `--force`. The other moves keep the current owner (after a review claim, the reviewer). To hand the work package to a named agent, pass `--assignee <agent>` on the same move. Every other move still records `--agent` as owner.
