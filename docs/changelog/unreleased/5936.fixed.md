- **A teammate's first coordination status write no longer refuses after a clone or pull** (#5936). **Before:** in a clone where the coordination branch existed only as `origin/kitty/mission-<slug>`, `agent status emit`, `agent tasks move-task`, `agent tasks mark-status` and `agent action review` refused with `COORDINATION_WORKTREE_UNMATERIALIZED`, and the printed remedy (`git fetch` plus `spec-kitty doctor coordination --fix`) changed nothing. **After:** the write creates the local coordination branch from the owning remote's tracking ref (with that ref as its upstream) and materializes the coordination worktree, as 4.0.0rc5 did; `doctor coordination --fix` does the same, and its report leads with `--fix`. A clone with no ref for the branch at all still refuses, and no remote is contacted.
