- **Lane test runs prove they test the lane's own code** (#7554, #7547). **Before:** a test or `spec-kitty` run in a lane worktree could load the repository root checkout's source through its editable install, so a review could pass unfixed code. **After:** `spec-kitty implement` prints each lane's test invocation and reports whether it loads the lane's code (`verified`, `foreign`, `unverified`); the implement and review prompts carry it. When the pre-review gate runs tests, it uses that invocation for head and baseline and records the evidence tree with its verdict. A lane whose tests would load code from another tree is refused at `move-task --to for_review` with `EVIDENCE_TREE_MISMATCH` and exit 1, whatever `review.fail_on_pre_review_regression` says; `--force` proceeds and records the bypass. An `unverified` probe never refuses, and the gate's skip switch still skips everything.
- **New lanes get the pinned pack trees** (#7577). **Before:** a lane worktree in a repository that pins its packs had no fetched pack tree, so the lane's CLI and pack tests failed with `BuiltInPackMissing`. **After:** `spec-kitty implement` places the pinned, digest-verified pack trees into a new lane from the local cache, without network access; when the cache is cold it prints a line telling you to run `make sync-packs` in the lane.
