- **Lane test runs prove they test the lane's own code** (#7554, #7547). **Before:** a test or `spec-kitty` run in a lane worktree could load the repository root checkout's source through its editable install, so a review could pass unfixed code. **After:** `spec-kitty implement` prints each lane's test invocation and reports whether it loads the lane's code (`verified`, `foreign`, `unverified`); the implement and review prompts carry it. When the pre-review gate runs tests, it uses that invocation for head and baseline and records the evidence tree with its verdict. A lane whose tests would load code from another tree is refused at `move-task --to for_review` with `EVIDENCE_TREE_MISMATCH` and exit 1, whatever `review.fail_on_pre_review_regression` says; `--force` proceeds and records the bypass. An `unverified` probe never refuses, and the gate's skip switch still skips everything. The gate's head and baseline runs no longer inherit `PYTHONPATH`, `VIRTUAL_ENV` or `UV_PROJECT_ENVIRONMENT`; a tree with its own `.venv` runs with that venv first on `PATH`. If your tests relied on an inherited `PYTHONPATH`, set it in `review.test_command`. When the gate falls back to running pytest itself (no `uv`, or no `uv.lock`), a lane with its own `.venv` uses that venv's Python, the one that was checked. Only `src/<package>/__init__.py` layouts are checked; other layouts report `unverified` and are never refused. Evidence recorded in the status log shows paths outside the repository as `<external>/…` rather than your home directory.
- **New lanes get the pinned pack trees** (#7577). **Before:** a lane worktree in a repository that pins its packs had no fetched pack tree, so the lane's CLI and pack tests failed with `BuiltInPackMissing`. **After:** `spec-kitty implement` places the pinned, digest-verified pack trees into a new lane from the local cache, without network access; when the cache is cold it prints a line telling you to run `make sync-packs` in the lane.
