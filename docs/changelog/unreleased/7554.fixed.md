- **Lane test runs prove they test the lane's own code** (#7554, #7547). **Before:** a test run in a lane worktree could load the repository root checkout's source through its editable install, so a review could pass unfixed code. **After:** `spec-kitty implement` and the implement and review prompts show each lane's test invocation and whether it loads the lane's code (`verified`, `foreign`, `unverified`). The pre-review gate runs tests through it and records the evidence. A lane whose tests would load another tree's code is refused at `move-task --to for_review` with `EVIDENCE_TREE_MISMATCH`; `--force` proceeds and records the bypass, and an `unverified` probe never refuses. The gate's runs no longer inherit `PYTHONPATH`, `VIRTUAL_ENV` or `UV_PROJECT_ENVIRONMENT`: if your tests relied on an inherited `PYTHONPATH`, set it in `review.test_command`. Only `src/<package>/` layouts are checked. Details: ADR `2026-08-13-6`, Amendment 2026-11-12.
- **New lanes get the pinned pack trees** (#7577). **Before:** a lane worktree in a repository that pins its packs had no fetched pack tree, so the lane's CLI and pack tests failed with `BuiltInPackMissing`. **After:** `spec-kitty implement` places the pinned, digest-verified pack trees into a new lane from the local cache, without network access; when the cache is cold it prints a line telling you to run `make sync-packs` in the lane.
