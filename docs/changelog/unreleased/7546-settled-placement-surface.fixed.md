- **Commits and checks after `finalize-tasks` settles a default Mission to `lanes_with_coord` land in the checkout that holds the Mission branch** (#7546, #7551). **Before:** once the coordination worktree held the Mission branch and the repository root checkout went back to its starting branch, `spec-kitty spec-commit` refused a tracer, decision or `baseline-tests.json` path with `WRONG_SURFACE`, its remedy told you to check out a branch git could not check out, and the `for_review` baseline file was silently left uncommitted. **After:** these commits land on the Mission branch from either checkout, a file that exists only in the repository root checkout is refused (never copied) with the coordination worktree named, the baseline is committed (or a warning names the file), and the safe-commit remedy names the worktree that holds the branch.
- **`spec-kitty agent action implement` and `agent tasks move-task` run from a repository root checkout on a protected branch for a settled Mission** (#7601). **Before:** both refused because they judged the root checkout's branch, the remedy offered `--no-auto-commit` to a command that has no such option, and `move-task` silently skipped the work package's own update. **After:** they judge the branch of the checkout the commit actually runs in, so the Mission branch is written and the protected branch never moves; a Mission whose write target really is protected is still refused, with a remedy the command accepts.
- **The implement and move-task banners name a settled Mission's declared target branch** (#7595). **Before:** they fell back to `main` when the Mission's `meta.json` lived only in the coordination worktree. **After:** the target is read where the Mission keeps its metadata.
- **`spec-kitty accept` names a missing path-convention artifact in the checkout that holds it** (#7602). **Before:** it printed a `.worktrees/<slug>-coord/...` path relative to the repository root. **After:** it prints `kitty-specs/<slug>/...` with the holding checkout and an absolute `mkdir -p` remedy.
- **A settled Mission's coordination status files are committed under the status lock** (#7607). **Before:** the lock was skipped, so a concurrent status transition could lose its row. **After:** the lock is taken whenever the commit runs in the coordination worktree.
