- **A declared-command run that fails opaquely is no longer reported as no new failures** (#7377, #6751). **Before:** every unparseable nonzero result had the placeholder identity `<declared-command>`, and the gate matched failures by name only, so a candidate that failed for a different reason than the baseline passed as `no_new_failures`, with no exit status on the verdict. **After:** an opaque failure's identity is its exit status plus a digest of the run's full output; it is pre-existing only when both match, and a differing one is a new failure. The verdict records the candidate's observed exit status and says that a `no_new_failures` result is baseline-relative. Named `FAIL <name>` and JUnit failures keep name-based matching; an older baseline still loads but cannot verify-equal a known candidate. **What to do:** nothing.
