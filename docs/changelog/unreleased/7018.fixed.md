- **A bare `spec-kitty doctor` now runs the project's default checks instead of exiting 2** (#6969, superseding #4678's exit-2 remedy). **Before:** `spec-kitty doctor` with no subcommand printed the group help and exited 2 ("no diagnostic ran"), which the docs, the skills and every wrapper read as a usage error or a failed check. **After:** it runs `command-files`, `state-roots` and `ops` — all read-only and project-local — prints one line per check naming the subcommand that shows the full report, and exits 0 when every check is healthy, 1 as soon as one reports a finding (or fails). Outside a project it exits 1 with the standard not-in-project error. Every `spec-kitty doctor <subcommand>` keeps its own output and exit codes. **What to do:** a wrapper that treated exit 2 as "nothing ran" should read 0/1; use `spec-kitty doctor <subcommand> --json` for machine-readable detail.
