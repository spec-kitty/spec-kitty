- **`spec-kitty upgrade` excludes the status files from existing lane worktrees** (#7281). **Before:** lane worktrees created earlier still showed the status files. **After:** the clone-local migration `4.0.0rc8_lane_checkout_status_exclusion` reports one outcome per lane worktree: `excluded`, `flagged_redundant`, `refused_lane_only_events`, `skipped_mid_operation` or `already_excluded`; it never drops an event. **What to do:** for a `refused_lane_only_events` lane, record each transition its copy holds with `spec-kitty agent tasks move-task`, discard the lane copy's change to the two status files, then run `spec-kitty upgrade` again; `spec-kitty doctor sparse-checkout` lists every such lane as `LANE_STATUS_NOT_EXCLUDED`.
- **A default `agent mission create` now mints only a topic branch** (#7282). **Before:** a create on the primary branch made a coordination branch and worktree at once. **After:** it records `topology: single_branch`, `topology_source: default` and `topology_settled: false`, and the topology settles at the first `finalize-tasks`; Missions created earlier, and every Mission created with `--topology`, keep their recorded topology. **What to do:** update scripts that expect a coordination worktree right after create.
- **In-flight `single_branch` Missions may refuse with `APPROVAL_STAMP_MISSING`** (#7283). **Before:** their approvals were never checked at consolidation. **After:** an approval recorded without a stamp refuses. **What to do:** attest each such work package with `spec-kitty consolidate --attest-approved-reviewed <WP> --attest-reason "<why>"`, or move it back and approve it again.
