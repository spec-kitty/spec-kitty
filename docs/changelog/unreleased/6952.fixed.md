- **`charter activate` and `charter deactivate` no longer take 16-18 seconds on a large project** (#6506). **Before:** on a project carrying this repository's own charter (165 KB `charter.yaml`, 264 references) one call took **~16.7 s**, 45 % of it in the compiled-charter write: `catalog` and `metadata` were refreshed as two separate round-trip writes, each loading, rendering and re-verifying the whole document, and each render paid two equality checks that serialized both sides. **After:** both sections are written in **one** cycle, and equality is decided structurally, round-tripping only what differs (1,189 ms → 1-4 ms, same verdicts). The command now takes **~10.4 s** (1.6× faster) and makes **6 whole-document round trips per recompile instead of 18**, with byte-identical output; a recompile with nothing to change still writes nothing and does not restamp `generated_at`. `charter generate` and skill rendering share the cheaper comparison. **Why not 2 s:** a pure read already costs 2.6 s here, so a structural round-trip budget replaces the 2 s line at this size ([ADR 2026-10-31-1](../adr/4.x/2026-10-31-1-charter-write-budget-for-repository-scale-projects.md)).
