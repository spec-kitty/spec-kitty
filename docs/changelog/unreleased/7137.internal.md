- **`CharterYaml` keeps refusing a hand-written `deactivated_<kind>` key on `charter.yaml`, and now says why** (#6855, #6850). The contract #6855 deferred is settled on the strict side: a deactivation is recorded only in the activation ledger (ADR 2026-10-19-1), so the model declares no deny field and `model_validate` raises a refusal naming `.kittify/charter/activation.yaml`, the fact that such a key was never applied, and the remedy, instead of pydantic's generic `extra_forbidden` text. The `CharterYaml` and `_stored_deny` docstrings no longer read as if the shape were legitimate, and `tests/charter/test_activation_vocabulary_setequal.py` pins the ledger's deny vocabulary as disjoint from the activation vocabulary and refused for every key, including an unknown prefixed key. This changes the model API diagnostic; current CLI readers still read mappings without validating them through this model.
