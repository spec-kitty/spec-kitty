- **`spec-kitty doctor ops` finds and closes Op records in every checkout of the repository, not only the root** (#6661). **Before:** since #6564 an Op record is written in the checkout the command runs in, but the sweep read `<project root>/kitty-ops` only, so an Op opened in a linked worktree was invisible to `doctor ops` and never closed by `--close-stale` — the listing reported no orphan records while work was still open. **After:** the sweep reads every checkout through the same `git worktree list` enumeration Op custody uses, and `--close-stale` closes each stale Op through an executor rooted in the checkout that owns it, so the closure lands on that checkout's `kitty-ops/op-closures.jsonl` and its branch. A listed path names its checkout (`../lane/kitty-ops/<id>.jsonl`); a checkout whose Op store cannot be read is named on stderr instead of being treated as empty; the `--json` payload shape, the session-start/stop reminder (still the root checkout only, still no git call) and the exit codes are unchanged.
