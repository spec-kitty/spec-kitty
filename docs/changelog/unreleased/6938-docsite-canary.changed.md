- **A dispatched canary tries the doc-kitty docsite on the real GitHub Pages service before cutover** (#6938, with #2361, epic #6100). **Before:** nothing had served the doc-kitty build from Pages, so its redirect stubs and directory URLs were unverified there. **After:** dispatching `docs-pages.yml` on `main` with `canary: true` builds the site through the shared `docs-site-build.yml`, publishes it, runs `scripts/docs/site_live_probe.py` against `https://docs.spec-kitty.ai`, and then republishes DocFX whatever the probe found; a failed probe leaves the run red. The probe checks one URL per class, derived from the committed ledgers, with a 300 s budget per URL, and the `docs-site` gate runs it against every build. A push to `main` still deploys DocFX. Run the canary only in an announced window with docs merges frozen. ADR 2026-10-31-1 carries an amendment.
