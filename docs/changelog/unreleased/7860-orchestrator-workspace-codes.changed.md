- **`orchestrator-api` no longer leaks unregistered workspace refusal codes** (#7860, contract 1.32.0). **Before:** a planning-lane work package's `start-implementation` refusal put `WRITE_CHECKOUT_*` straight into the envelope `error_code`, and `resolve-workspace` always answered the repository root checkout. **After:** such a refusal is `LANE_ALLOCATION_FAILED` with the real code in `data.workspace_error_code` (for example `PLANNING_CHECKOUT_MISSING`), a failure with no code is named in `data.error_type`, `resolve-workspace` resolves the planning workspace, and for a default Mission's planning work package before it lands `workspace_path` and `lane_branch` name the coordination worktree and the Mission branch. Planning-lane work packages are stamped `direct_repo` on `start-review` and `transition` on every topology.
