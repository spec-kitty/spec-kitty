- **User-global Claude commands and skills follow `CLAUDE_CONFIG_DIR`** (#7701). **Before:** spec-kitty always wrote them to `~/.claude/commands` and `~/.claude/skills`, so a Claude Code session run with `CLAUDE_CONFIG_DIR` set saw no `/spec-kitty.*` commands and no skills, and `doctor command-files` still reported every file healthy. **After:** they are written to `$CLAUDE_CONFIG_DIR/commands` and `$CLAUDE_CONFIG_DIR/skills` when the variable is set, and `doctor command-files` prints the directory it checked for each agent. Copies under `~/.claude` are left in place; remove them yourself if no session uses that tree.
- **A relative `CLAUDE_CONFIG_DIR`, `OPENCODE_CONFIG_DIR` or `LLXPRT_CONFIG_HOME` is refused** (#7701). **Before:** a relative value resolved against the directory the command ran in, so `CLAUDE_CONFIG_DIR=cfg spec-kitty upgrade` inside a project wrote a stray `cfg/` tree into it. **After:** the command exits 1 with an error that names the variable and asks for an absolute path; a leading `~` is still expanded.
- **Copies left under `~/.claude` after you set `CLAUDE_CONFIG_DIR`** (#7701) are not cleaned up: remove them by hand, or run `spec-kitty upgrade` with the variable unset first. Follow-up #7731 tracks a doctor check.
