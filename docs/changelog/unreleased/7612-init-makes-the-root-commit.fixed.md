- **`spec-kitty init` makes the first commit of a repository that has none** (#7612). **Before:** after `git init`, `spec-kitty init` left `.kittify/`, the agent files, `.gitignore` and `.gitattributes` uncommitted and printed a note, because its #7555 commit worked only on a branch that already had a commit. **After:** init makes the root commit (`chore: initialize spec-kitty project`) holding exactly the files it wrote; files you already had, staged or not, stay out of it and stay staged. If a pre-commit hook stages more files itself, init names them after the commit lands. `--no-commit` still opts out. With no git identity, init still writes its files and exits 0, but skips the commit and names the reason in a note (`INIT_GIT_IDENTITY_MISSING`: set `user.name` and `user.email`, then commit the listed files).
- **`spec-kitty init` exits 1 when git refuses the first commit of a repository that has none** (#7612). **Before:** init left its files uncommitted and exited 0. **After:** when a hook rejects that commit, init prints `INIT_ROOT_COMMIT_FAILED`, git's reason and the files it wrote. With no first commit the branch does not exist, so later spec-kitty commands cannot work. On a repository that already has commits, the same refusal is still only a note and init exits 0. **Remedy:** fix or bypass the hook, then run init again, or pass `--no-commit` and make the first commit yourself.
