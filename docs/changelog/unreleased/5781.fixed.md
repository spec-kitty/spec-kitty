- **A Mission driven through `orchestrator-api` can be accepted** (#5781). **Before:** `orchestrator-api start-implementation` recorded its claim with no `agent`, so `accept-mission` and host `accept` refused every API-claimed Mission with "missing agent in canonical runtime state". The repair they printed (`move-task --to <current lane>`) could never run, and the `--force` workaround then failed `REVIEW_NOT_INDEPENDENT`. **After:** the readiness gate reads the implementer of record from the event log, which also heals Missions recorded on older builds. Every claim path (`start-implementation`, `orchestrator-api transition --to claimed`, `agent status emit --to claimed`) records `agent` through one claim-sidecar builder. The refusal names a repair only when the state machine allows an implementing claim from the work package's lane, and the command it prints runs.
- **A work package canceled before anyone claimed it no longer blocks acceptance** (#5781). **Before:** host `accept` asked it for an implementer, and the printed repair failed `Illegal transition: canceled -> canceled`. **After:** a canceled work package with no claim history needs no implementer, and none is fabricated.
- **`orchestrator-api accept-mission` accepts a descoped Mission** (#5818). **Before:** it counted every work package outside `approved`/`done` as incomplete, so a work package canceled with an operator reason refused `MISSION_NOT_READY` where host `accept` passed. **After:** it uses the provenance-aware acceptable-ending authority host `accept` and `consolidate` use, and its success payload names the descoped work packages in a new `canceled_wps` field. A synthetic cancellation is still incomplete. Acceptance-matrix `code_review` rows of a descoped Mission still need an explicit `acceptance-verdict` (#7798).
- **`orchestrator-api transition --to planned` releases the work package's claim** (#7644). **Before:** the previous holder and its `shell_pid` stayed bound. **After:** it releases them exactly as `move-task --to planned` does, through one shared release. The implementer of record is kept.
- **Lane-approved done evidence names the approver** (#5781). **Before:** when an approved work package had no review record, done bookkeeping named the claim holder, the implementer, as its reviewer. **After:** it names the actor of the latest approval.
