- **`spec-kitty upgrade` stamps `merged_at` on Missions merged before the marker existed** (#7433). **Before:** a Mission merged before #4090 carried only `mission_number`, so `next` and `agent tasks status` read it as not merged, and a coordination one refused with `COORDINATION_BRANCH_DELETED`. **After:** the migration `4.0.0rc8_backfill_merged_at` stamps `merged_at` on each Mission with `mission_number`, no `merged_at` and no reopen, dated by `baseline_merge_commit` when that commit exists, else by the oldest commit that set `mission_number`. A reopened Mission is never stamped; one with neither commit is named in a warning and left alone. **What to do:** run `spec-kitty upgrade` and commit the changed `meta.json` files; for a Mission named in a warning that did land, set `merged_at` (ISO-8601 UTC) by hand.
