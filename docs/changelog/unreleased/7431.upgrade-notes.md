- **`spec-kitty upgrade` stamps `merged_at` on Missions merged before the marker existed** (#7433). **Before:** such a Mission had no `merged_at`, so `next` and `agent tasks status` read it as not merged, and a coordination one refused with `COORDINATION_BRANCH_DELETED`. **After:** the migration `4.0.0rc8_backfill_merged_at` stamps it only when the committed status log shows every work package `done` or `canceled`, at least one `done`, and no reopen, dated by the latest transition to `done` (UTC). `mission_number` is no proof of a merge (#5471). Every other Mission is left alone and named in a warning with its reason, including one mid-consolidation (finish it with `spec-kitty consolidate --resume`). **What to do:** run `spec-kitty upgrade` and commit the changed `meta.json` files; for a named Mission that did merge, set `merged_at` (ISO-8601 UTC) by hand.
