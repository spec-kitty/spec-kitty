- **`spec-kitty consolidate` no longer refuses a lane's own dependency merge as content of no approved work package** (#7307). **Before:** the `Merge dependency lane X into Y` commit that `implement` makes was reported as belonging to no approved work package whenever both lanes touched one file, so the landing and `--dry-run` refused. **After:** a merge is judged by what it adds beyond its parents (`git show --remerge-diff`): a clean merge carries nothing, and a resolution in a lane's own merge of a declared dependency lane counts as that lane's work. **Changed:** a merge that no lane owns and that resolves a conflict by keeping one side is now refused; it used to pass. Judging a merge needs git 2.36 or newer; with older git the gate refuses. **What to do:** nothing, or upgrade git to 2.36 or newer.
