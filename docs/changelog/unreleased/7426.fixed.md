- **`consolidate --dry-run` reports its refusal reasons with stable error codes** (#5373). The slug-unresolvable, unreadable-lanes and integration-preview failures now carry `MISSION_SLUG_UNRESOLVED`, `LANES_MANIFEST_UNREADABLE` and `TARGET_INTEGRATION_PREVIEW_FAILED` in the JSON forecast, so tooling can key on them.
- **`consolidate --dry-run` refuses a deleted mission branch instead of crashing** (#7267). The forecast now runs the same missing-branch check as the real run and reports `MISSION_BRANCH_MISSING` with the run's own remedy, instead of raising an unhandled `CoordinationBranchDeleted`.
- **Consolidation target-branch tip captures resolve the branch, not a same-named tag** (#5058). Four merge-domain tip reads (`bookkeeping_projection`, `phase_claim`, `phase_advance` baseline and re-anchor) route through the canonical `capture_branch_tip` authority, so a tag sharing the target branch's name can no longer misresolve a baseline or the transaction-start tip to the tag SHA.
- **`single_branch` mission done records state what actually happened** (#7354). A `direct_repo` `single_branch` Mission's merge-complete events now carry `execution_mode: direct_repo` and `merge_phase: direct_repo`, instead of the false `worktree` + `lane_integrated` audit stamp for a lane integration that never happened.
- **Owned-checkout writers follow nested Mission symlinks, and that is now the documented contract** (#5923). The `files()` docstring states the follow behavior, the false "still refused" comment in `owned_mission.py` is corrected, and the previously vacuous symlink-escape test now asserts the real contract (link returned by where it sits; refused only by an explicit `follow_links=True` boundary screen).
