- **`accept`, `consolidate` and `orchestrator-api` say when they cannot read a work package's ownership instead of reporting its implementation missing** (#7160; #7149). **Before:** an approved work package whose task file was missing, unreadable or invalid was refused with `IMPLEMENTATION_MISSING`, and `--attest-no-implementation` offered to lift it, which led operators to rewrite history or attest falsely. **Now:** it is refused with `OWNERSHIP_UNRESOLVED` (single_branch: `SINGLE_BRANCH_OWNERSHIP_UNRESOLVED`), naming the missing directory, the unreadable file and its error, or the missing id, and no attestation lifts it. `accept --owned-checkout` also reads canceled work packages from the owned checkout, and the orchestrator-api contract is 1.23.0.
