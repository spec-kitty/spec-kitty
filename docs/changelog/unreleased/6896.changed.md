- **One authority now decides every per-user cache, state and config location, so a macOS user has one cache tree instead of two** (#6896, #6488). **Before:** three callers applied an XDG-only rule (`~/.cache/spec-kitty` on macOS), two called `platformdirs` themselves (`~/Library/Caches/spec-kitty`), and the runtime-package marker fell back to `~/.cache`, so the upgrade, pack and service caches split from the upgrade-nag cache. **After:** `kernel.user_dirs` alone resolves them — Linux `${XDG_CACHE_HOME:-~/.cache}/spec-kitty`, `${XDG_STATE_HOME:-~/.local/state}/spec-kitty`, `${XDG_CONFIG_HOME:-~/.config}/spec-kitty`; macOS `~/Library/Caches/spec-kitty` and `~/Library/Application Support/spec-kitty`; Windows `%LOCALAPPDATA%\spec-kitty\Cache` and `%LOCALAPPDATA%\spec-kitty`; an XDG variable still wins where it did. **What to do:** nothing; the old directories go on the next command. On Windows the upgrade-nag settings file (`upgrade.yaml`) is copied to the new config location (`%LOCALAPPDATA%\spec-kitty`) before the old tree is removed, never over an existing file.
