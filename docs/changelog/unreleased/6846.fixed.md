- **Generated charter fetches preserve an explicit owned Mission** (#6845). **Before:** a prompt from an owned checkout could fetch charter context from the primary checkout. **After:** generated commands carry the validated checkout and Mission, and `charter context` revalidates that claim before reading or writing context. Ordinary commands retain their existing scope.
- **Reopening approved implementation preserves supplied review feedback** (#6845). **Before:** `spec-kitty agent tasks move-task <WP> --to in_progress --review-feedback-file <file>` discarded a valid reference and recorded a forced transition. **After:** the reference reaches the existing transition validators and the reopen records `force: false` without `--force`. Omitting feedback retains the existing forced-reopen policy.
- **Global runtime storage cannot authorize project migrations by itself** (#6845). **Before:** an inferred global `.kittify` directory could trigger project scans or recreate an ancestor `.git/hooks` directory outside a repository. **After:** inferred global storage needs fresh repository authority before project-wide migration work, and hook repinning requires an existing Git repository. Explicit supported project overrides and ordinary non-Git projects retain their existing migration behavior.
- **An explicit migrated owned checkout can create a Mission while the primary checkout remains legacy** (#6845). **Before:** startup inspected the primary checkout before validating `--owned-checkout` and refused with `LEGACY_CHARTER_STATE`. **After:** the canonical custody validator selects the explicit linked checkout for startup schema and legacy checks. Invalid claims still refuse, and command-level Mission and write custody checks remain in force. The validated basic claim is shared only within one command, preserving the existing Git-call budget.
