- **`spec-kitty doctor workspaces` can prove a landing against a remote other than `origin`** (#7214). **Before:** the landed check read `refs/remotes/origin/<primary>` unconditionally, so in a clone whose `origin` is a fork and whose canonical repository is `upstream` — the shape the landing runbook prescribes — every landing worktree reported `not_landed` (`CONTENT_NOT_ON_PRIMARY`) forever and `--prune` removed nothing. **After:** `--remote <name>` (default `origin`) selects the remote whose primary ref proves the landing, for the report and for `--prune`; the primary comes from that remote's `HEAD`; an unconfigured remote is an error naming the configured ones; and the `unproven` details name the missing ref and the `git fetch <remote>` that produces it. Nothing is fetched, and only the named remote's primary ref is read.
