- **`--allow-fail` on `spec-kitty accept` now exits 0 instead of 1** (#3084). **Before:** a not-ready acceptance summary printed the checklist but still exited 1, so `--allow-fail` was indistinguishable from a plain failure to any caller gating on the exit code. **After:** `--allow-fail` is report-only — it prints the same checklist and exits 0 — while a plain `accept` still refuses with exit 1. `--mode checklist` is unchanged.
- **`spec-kitty agent tasks add-history` can read the note from a file or stdin** (`--note-file`, `-` for stdin) (#2708). **Before:** the note had to be inlined in `--note`, so a shell-based orchestrator passed through shell expansion and mangled literal Markdown backticks and `$(…)` before the CLI saw them. **After:** `--note-file NOTES.md` and `git show -s --format=%B | spec-kitty agent tasks add-history WP01 --note-file -` record the note verbatim; `--note` stays the simple inline door, and passing both (or neither) is refused before any write.
- **`spec-kitty intake --clear` is the canonical brief-intake cleanup** (#706). **Before:** the specify step's brief-intake mode deleted `.kittify/mission-brief.md`, `.kittify/brief-source.yaml`, `.kittify/ticket-context.md` and `.kittify/pending-origin.yaml` with four raw `rm -f` lines in the prompt. **After:** `spec-kitty intake --clear` removes exactly those artifacts (idempotent, exit 0 when there is nothing to clear, files outside that set untouched). The specify prompt still uses the `rm -f` lines until the built-in pack switches to the command.
- **`spec-kitty charter context --include` accepts several selectors, and refuses a comma** (#3261). **Before:** a repeated `--include` silently kept only the last selector, and `--include a,b` resolved the whole tail as one bogus id ("No agent_profile found for selector '…,<id>'"). **After:** the flag is repeatable and every selector is rendered, a comma-containing selector fails loudly with the correct one-selector-per-flag syntax, and `--json` lists the selectors under `include`. With `--json`, `include` keeps its string value (the first selector) and a new `includes` key lists every selector.
- **`spec-kitty agent issue-verdict` can set the issue title** (`--title`) (#7348). **Before:** recording a verdict left the row's placeholder title in place, with no CLI way to fill it. **After:** `--title "…"` stamps the title on the row (creating or replacing it) while an omitted `--title` preserves the existing one.
- **`spec-kitty agent tasks status` reads `dependencies:` through the canonical parser** (#5435). **Before:** a WP with `dependencies: []` was reported as depending on a work package named `"[]"`, and a YAML list became one fused dependency string, so the board's readiness map disagreed with the dependency gate. **After:** the board uses the same parser the gate enforces, so an empty flow list, a flow list and a block list all read correctly.
- **`session-start` / `session-stop` project-root discovery honors `GIT_CEILING_DIRECTORIES` and no longer carries a test-only `stop=` bound** (#7122). **Before:** the hook commands' `.kittify` walk ignored the discovery ceiling every other root walk reads. **After:** it uses the one ceiling-aware ancestor walk, so it stops at a listed ceiling or the filesystem root, exactly as git does.
- **The frozen `doctor event-logs --help` snapshot matches the shipped help again** (#7381). The `#6739` retention work updated the help (Op-scoped logs, the Op index, an item whose recorded Mission the checkout cannot find) without re-pinning the golden; the golden now records that intended text instead of the pre-`#6739` wording.
