- **The issue matrix no longer auto-classifies the issue a Mission exists to fix as context-only** (#7011). **Before:** a positional citation label (`parent #`, `epic #`, a leading `see #`) matched anywhere on its line, so a spec header like `**Input**: Issue #6926 (part of epic #6100, …)` classified the Mission's own target `#6926` as `context_only` and scaffolded a terminal `not-applicable` row that the approval gate accepted. **After:** a positional label binds only to the reference it leads into, and the Mission's source issue — read from `meta.json` `source_description`, the `**Input**:` line, or a `Closes`/`Fixes`/`Resolves #N` line — is never auto-classified non-gating: it always scaffolds `unknown`, so a verdict is forced. The scaffold, approval blocker, `status doctor` and merge gate share that one classification; `not-applicable` remains available as an *explicit* verdict. **What to do:** nothing — re-scaffold a Mission in flight, or record the real verdict with `spec-kitty agent issue-verdict`.
