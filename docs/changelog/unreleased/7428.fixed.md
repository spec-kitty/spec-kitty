- **The review interpreter needs `uv.lock` before building `uv run --frozen`** (#3594). **Before:** a repo with `pyproject.toml` but no `uv.lock` still produced the `uv run --frozen …` command, which fails without a lock. **After:** the `uv` form requires both files; a missing lock falls back to `sys.executable`, so the verdict is real either way.
- **Ownership overlap compares on the path-component boundary** (#6312). **Before:** a prefix compare made `src/p1/**` read as overlapping `src/p10/**`. **After:** a prefix only matches through a following `/` (or an exact path), so sibling directories with a shared prefix do not overlap.
- **`spec-kitty accept` builds its summary from a linked worktree** (#3656). **Before:** the summary's relative paths were computed against the worktree root, so a WP resolved under a linked git worktree raised on path relativization. **After:** the relative path is computed against the root the WP path was resolved under, and a summary from a linked worktree no longer raises.
- **Acceptance cleanup advice no longer prints raw `git worktree remove` / `git branch -d` recipes** (#7327). **Before:** local-mode acceptance instructions told the operator to run `git worktree remove` and `git branch -d` by hand, bypassing the guards that keep stranded lane work recoverable. **After:** the worktree line points at `spec-kitty doctor workspaces --prune`, and the branch line names the consolidate-owned guarded removal, with the prune as the backstop.
- **`accept --lenient` records `lenient: true` in the acceptance history entry** (#7356). **Before:** the lenient flag gated the run but the persisted history entry did not say the acceptance was lenient, so an audit could not tell a lenient acceptance from a strict one. **After:** the flag is threaded through `perform_acceptance` into `_stamp_acceptance_record`; the entry carries `lenient: true`, and strict acceptances keep the key absent.
- **A requirement ID declared twice is refused at each repeat** (#5674). **Before:** the declared-id collector de-duplicated into a set, so a requirements table repeating `FR-001` read as one requirement and a WP mapping it covered both rows. **After:** an id's first declaration fixes its site, and another row of that same table (or another id-naming heading, for a heading-declared id) is an `InvalidRequirementId` at its own line, refusing setup-plan and design validation. A bullet or bold note, a later traceability table or a detail heading that restates the id is not a declaration and is never refused.
- **The dossier indexer hashes a `WP##`-named file outside `tasks/` as a generic artifact** (#2900). **Before:** every `WP##*.md` anywhere under the mission dir went through the work-package projection, so an auxiliary file that only shared the prefix (a glossary fragment, an activity log) failed closed through the `WPMetadata` schema. **After:** only a `WP##*.md` whose parent directory is `tasks/` is hashed as a work package; any other `WP##`-named file is hashed by its raw bytes.
- **Bulk-edit diff check classifies `.jsonl` as serialized** (#1791). **Before:** a `.jsonl` diff was judged as plain text, flagging serialized event logs as a semantic edit. **After:** `\.jsonl$` joins the serialized-keys classification.
- **The upgrade no-migrations stamp refreshes the environment block** (#4160). **Before:** a project upgraded across a platform-affecting release with no migrations to run kept `python_version` / `platform` / `platform_version` from the earlier build. **After:** the environment fields are re-stamped in the same write as the version bump.
- **The Op auto-commit carries the operator attribution trailer** (#7315). **Before:** the `op(...)` commit minted by `profile-invocation complete` was generated by the executor, so the configured `Co-Authored-By` trailer never rode it. **After:** `complete_invocation` takes `co_author`, resolves the trailer configured under the new optional `commit.co_author` key in `.kittify/config.yaml` (with `profile-invocation complete --co-author` overriding it), and the per-record and closure-spine commits both carry it; an invalid explicit value is refused before any write.
- **The orientation block renders ASCII-only** (#5757). **Before:** the session-presence block wrote a warning glyph, em dash and arrow, which some toolchains mangle. **After:** the render is ASCII (`[!]`, `-`, `->`), and blocks written before the change are still recognized as Spec Kitty's — legacy glyphs are normalized before the canonical compare, so an older block is refreshed instead of preserved as "edited".
- **Acceptance, consolidation and coordination files pass `mypy --strict`** (#7334). **Before:** untyped returns and locals at the cited sites kept strict checking red on `acceptance/__init__.py`, `consolidation/reconciliation.py`, `consolidation/phase_advance.py` and `coordination/transaction.py`. **After:** return annotations, typed locals and a `ParamSpec`-typed `_records_post_mutation_tips` decorator make those files strict-clean with no suppressions.
