- **`finalize-tasks` reads a Mission as started once any work package ever left `planned`, on every topology** (#7793, #7297). **Before:** a Mission whose work packages were all back in `planned` after a rejection counted as not started, so a plain finalize re-captured the branch tip as its planning commit. **After:** finalize keeps or refreshes the recorded planning commit as for any started Mission; `agent tasks finalize-tasks`, `doctor mission-state --fix` and `spec-kitty next` treat such a Mission with no `lanes.json` as needing `doctor mission-state --fix`. A planning commit derived from git now anchors on the last time the Mission's task files appeared, including files renamed into `WP*`, on every topology.
