## 5. Cost sizing

Cheap (seconds, no install per revision; `git archive <rev> src | tar -x` + grimp):
- Import graph, SCCs and cross-package edges: 0.01-0.18 s per revision, 0.2 s to archive. All 11 revisions above were measured. Per-month or even per-PR sampling (thousands of revisions) is affordable.
- Co-change, files per fix, commit-size and fix/revert chains: `git log --no-renames --name-only` over 21,714 commits takes 1.1 s.
- Tag and ADR timelines: ADRs by month in spec-kitty 2026-01 21, 02 23, 03 5, 04 36, 05 14, 06 22, 07 23, 08 24, 09 20, 10 40, 11 11. ADR totals: core 239, charter 83, events 8, open-packs 17, doc-kitty 99.
- Allowlist and baseline sizes per revision: `git show <rev>:<path>`.
- PR metadata via REST: about 30 calls for all PRs, or 1 call per commit.

Moderate:
- pytestarch gates: 150 s for test_layer_rules alone. E mutation loops: N mutations × the relevant gate files. Use grimp/import-linter as a fast oracle, but **measure detection with the real gates**.
- doc validators: seconds after a 40 s install.

Expensive or blocked:
- Gradle builds and jdeps over Java (it needs compiled classes; charter is feasible, events is blocked by 429).
- Installing old CLI versions per revision.
- Container-based D scenarios (Hub rate limit; use the gcr mirror).
- Whole test suites: forbidden, and spec-kitty tests are 1.44M LOC.
