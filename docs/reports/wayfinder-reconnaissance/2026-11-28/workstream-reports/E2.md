# Workstream E2: mutation author

## Profile and directives applied

Profile `debugger-debbie` in squad-delegate mode: I answered the brief directly and dispatched no
sub-agents. Charter context was loaded for the action `implement`.

- Profile boundary "production code implementation" is outside the profile. The brief asks for
  patch files, so the envelope wins: I wrote patches and applied none to a checkout under
  `/home/user`.
- Applied from the profile: falsify before reporting (every patch was re-checked in a second set
  of fresh clones), and the divergence-matrix habit (class by subtlety by repository, every cell

- Applied from the charter context: Terminology Canon (Mission, never the retired word),
  `change-apply-smallest-viable-diff` (each patch is 2 to 14 changed lines), Locality of Change
  (22 of 24 patches touch one file), canonical sources (every rule is cited from a charter, ADR,

## Method and tools

1. `git clone --shared` of core, `spec-kitty-charter`, `spec-kitty-events` and
   `spec-kitty-open-packs` into scratch, each checked out at its `head` revision. The local core
   checkout was not at `head`, so nothing was read from its working tree for patch context.
2. Read the intended model from charters, ADRs, architecture documents, contract documents,
   production source and dependency sections.
3. Edited the scratch clone, exported `git diff`, reset the clone, ran `git apply --check`.
4. Re-verified all 24 patches in a second set of fresh clones (`apply-check.txt`).
5. Sanity only, no gate: imported each touched core module with its patch applied alone; parsed
   the patched Python, JSON and YAML of the other repositories; ran `javac` alone on the four
   patched Java files to separate syntax errors from unresolved project symbols.

Tools: git 2.43.0, GNU grep 3.11, Python 3.11.15 (core's virtual environment) and 3.13.18,
javac 25.0.5, Gradle wrapper of each Java repository.

## Deviations

1. **Blindness, file names.** One `find` over the charter repository was meant to list main
   source folders and also printed the names of files under `src/test`, among them fixture
   classes whose names describe forbidden dependencies. I read no content of any of them and
   excluded `src/test` from every later command. The names told me that the charter build checks
   domain-to-outer and slice-crossing dependencies, which charter ADR-0006 also states.
2. **Blindness, allowed sources that name gates.** ADRs, architecture documents and production
   docstrings name gate test files and ArchUnit rule names; events
   `docs/architecture/services/overview.md` lists the read service's fourteen rules in prose. The
   project instructions injected into this session also name gates. I opened none of the named
   files. Two subtle Java mutations use what these documents say about the method (ArchUnit works
   on compiled classes): M-PI-6 depends on another slice only through a compile-time constant,
   and M-RD-6 names the outer class without an import statement.
3. **"Without a version change" for unreleased contracts.** The charter contract is
   `0.2.0-SNAPSHOT` and the mission-status contract `1.0.0-SNAPSHOT`. I defined the violation as
   "no changelog fragment and `info.version` untouched" (F-E2-004), and carry it on M-IC-2 and
   M-IC-3.
4. **Build sections.** While reading dependency blocks of two `build.gradle.kts` files I also saw
   test task configuration lines. Nothing from them was used.
5. **Pack tree for the import check.** The scratch clone of core has no built-in pack tree. I
   copied the fetched tree from `/home/user/spec-kitty/packs/built-in` into the scratch clone,
   untracked, for the import check only.
