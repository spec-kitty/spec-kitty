# Workstream B2: observed structure of the Java services, the events Python package, doc-kitty and open-packs

## Profile and directives applied

Profile `architect-alphonso` (role architect; scope here: evaluate and measure). Charter context for action `review` was loaded. Applied: the profile's avoidance boundary (no implementation, no fixes), DIRECTIVE_001 and DIRECTIVE_003 (architectural integrity and decision traceability: every claim names its revision and evidence), DIRECTIVE_032 (conceptual alignment: ecosystem terms), `NO_FULL_HEAVY_SUITES_IN_MISSION` (named test classes only) and the tactic `dependency-hygiene`. The profile's verbs "design" and "decide" conflict with the envelope; the envelope won, and nothing here decides or proposes.

## Method and tools

Python 3.13.18 (stdlib `ast`, `re`, `csv`; PyYAML 6.0.3), git 2.43.0, OpenJDK Temurin 25.0.5, Gradle 9.8.1 (wrapper), jdeps 25.0.5. All builds ran in shared clones under the scratch folder with a private `GRADLE_USER_HOME`. Scripts are in `evidence/B2/script-*.txt`; `MANIFEST.csv` gives the command, revision and SHA-256 per artefact.

- Lines of code: tracked files at head, non-blank lines by module, language and scope (no comment stripping).
- Java graphs: Gradle `project(...)` declarations; import statements of main sources; for charter also `jdeps -verbose:class` over compiled classes.
- Enforced model: inventory of ArchUnit rule sources and build-time allowlists; charter's nine architecture test classes were run; events' were not (build blocked) and a subset was checked statically.
- Python: `ast` import graph of `spec_kitty_events`, `__all__`, third-party imports.
- doc-kitty: import specifiers of tracked sources, checked against the toolkit's `exports` map.
- Cross-repository: token scan of build, pin, CI, script and source files of the five repositories, then a hand-verified list (purposive); pin ancestry from git.
- Duplicated schemas: 2,228 schema and contract files matched by SHA-256, canonical JSON and basename.

## Covered and not covered

Covered: charter, events, doc-kitty and open-packs at head; core only as the other end of cross-repository references. Not covered: third-party Java library graphs, generated sources as tracked code, historical revisions, released artefacts (no jar or wheel was downloaded), and run-time composition (Spring scanning, reflection).

## Deviations

1. **Events build.** Three attempts failed before any compilation: one on dependency verification of a plugin marker served by the environment's Central mirror, two on HTTP 429 from Maven Central. The brief allowed one retry; a second retry followed the coordinator's resume instruction. Events Java measures are static and are marked so in F-B2-009, 010, 011 and 013. No jdeps and no ArchUnit run for events.
2. **Private access.** Neither Java repository has a package named `internal` or `impl`. I report the strict count (0) and, beside it, the share of cross-module imports by target ring (domain, application, infra or adapter, config).
3. **Charter test run was wider than asked.** The `--tests` class filter on `:deployable:test` did not exclude the Cucumber engine, so 1,557 scenario tests also ran (0 failures). Only the five named classes are used as evidence.
4. **Charter jdeps scope.** 15 service modules; `contracts` and `client-java` are covered by the import scan only.
5. **M03a for doc-kitty and open-packs.** No enforced structural model exists to count violations against; I report that fact instead (F-B2-020, F-B2-023).
6. **Unit for Python.** `spec_kitty_events` is one top-level package, so the graph is at module and first-level-unit level.

## Blocked

- Events Gradle build (dependency retrieval), as above. A coverage limit, not an observation about the repository.
- Two charter builds were killed by the shared memory limit before the third succeeded; no measure was lost.
