## Development architecture and supported distribution

A working source checkout needs three things the wheel does not: a synced environment from `uv.lock`, the built-in and internal pack trees fetched from the pinned open-packs commits, and (for conformance tests, not exercised here) the pinned service extras. The wheel carries the built-in tree and the pin files, no lock, no internal pack and no binary. The lock's hashes therefore protect development and CI installs, not an end-user install, which resolves from the ranges.

## Unsupported by design versus defect

Recorded as by design, on the basis of text in the repository at head: the CLI never launches the read service (`pins/README.md`); no default status handler is registered (`status/adapters.py` docstring); `charter.offering.api` is not a door for consumers (its docstring); core's tests refuse an installed wheel (`tests/_support/import_origin.py`); open-packs no longer treats core's pack validator as a requirement (`scripts/ci/validate-packs.sh`). Each of these is a `document-claim` that explains an observation; none was verified as a recorded decision in an ADR by this workstream.

No observation in this report is classified as a defect. Two items look like plain breakage and are left open: the doc-kitty toolkit typecheck (exit 2 at head in this environment) and the `emit_status_transition(feature_slug=...)` example in core's `CLAUDE.md`, which raises `TypeError` at head.

## Deviations

1. **M04d version boundary.** The ranges admit one published version each, so "lowest and highest" is one combination per core build. Run as such; an unreleased events build inside the range was added as exploratory (F-D1-030).
2. **M04d rc8 wheel.** Core's tests cannot import an installed wheel. The named checks ran from the `v4.0.0rc8` source export inside the rc8 dependency set. The refusal itself is F-D1-014.
3. **M04e stubs.** A stub was tried for the status produce seam and the packs resolver. None was tried behind `charter.offering.api` or the tracker adapter; those cells say "not assessable" or rest on static counts.
4. **M04c.** The file-literal census is a proxy; its regex for the packs tree over-matches. Counts are reported with a hand-classified seeded sample.
5. **Latest mission type.** The latest addition predates the move of mission definitions into packs, so it does not measure the present layout.

## Blocked items

None blocked. Two environment artefacts were met and worked around, both recorded in the logs: a placeholder `GITHUB_TOKEN` injected by the sandbox made open-packs' schema fetch return 404 (passes with the variable unset), and a first test run was killed for memory on the shared host (re-run one file per process).

- The built-in tree is verified at build, sync and pin bump, not at CLI run time; a modified tree was accepted by two commands (F-D1-019).
- 19 of 36 `runtime` files and 6 of 16 `mission_runtime` files import `specify_cli`; the layer gate passes with them (F-D1-027).
- doc-kitty is referenced four different ways by four sites (F-D1-028).
- PyPI holds two yanked CLI versions above the current line; project stamps name six different CLI versions (F-D1-029).
- `agent status validate` reports a materialization drift for one probed Mission of the core repository (F-D1-020).
