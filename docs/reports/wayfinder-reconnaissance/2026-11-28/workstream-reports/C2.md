# Workstream C2: evolution and change coupling (independent run)

Audience: the commissioning architect and the synthesis team. They know the ecosystem's vocabulary and need measures with their denominators, not conclusions.

## Profile and directives applied

Profile `analyst-annie`, with charter context for action `review`. Directives applied:

- DIRECTIVE_003 (decision documentation). Every rule, sample and deviation is written down in `evidence/C2/`. The classification rules were saved before any commit was classified.
- DIRECTIVE_047 (audience-oriented writing). The audience is named above.
- DIRECTIVE_032 (conceptual alignment). Its "confirm with the requester" step conflicts with the read-only, no-interaction envelope, and the envelope wins. Instead I state my interpretations. "Code commit" means any file under `src/`, including YAML and templates. "Merge" means a git merge commit. "Line" means a line of history (public, EXPERIMENTAL, post-convergence). "Fix" is defined in F-C2-017.
- The terminology canon applies: Mission, never feature.
- The profile's boundary against architecture decisions matches the envelope: no recommendations are made.

## Method and tools

- Tools: git 2.43.0, Python 3.13.18 (`ast`, `csv`, `random`), gh 2.89.0 (read-only GET calls only).
- All work ran in `git clone --shared` copies under the scratch folder. No state in `/home/user/*` was changed.
- Population: the 20,963 commits reachable from core head `5c4fc5a` with a committer date from 2025-12-31 onward, by UTC month.
- Lines are tagged by reachability:
  - EXPERIMENTAL is `38090b64..f57b06dd`. Its fork base is `38090b64` (2026-08-19).
  - Public is everything else before the merge.
  - Post-convergence is `2554bd13..head`.
- Merge commits are excluded from per-commit measures and counted separately. A sensitivity run counts first-parent change units instead (F-C2-011).
- Bulk commits (more than 500 files, 22 of them) are excluded and listed.
- Components:
  - 6 top-level packages plus the second-level subpackages of `specify_cli` and `charter`.
  - A rename map (`rename-map.txt`) maps old paths to today's components: doctrine to `charter/offering`, constitution to `charter`, `merge` to `consolidation`, `specify_cli/next` to `runtime`, and others.
  - Subpackages that are absent at head are kept as `[retired]` components.
- Classes come from fixed rules (`classification-rules.txt`). They were validated on a seeded sample of 50 commits: 38/50 agreement, kappa 0.62 (F-C2-005).
- Seed 20261128 is used for every sample.

## Deviations

1. **Period assignment by line.** All post-convergence commits are in T3, including 7 dated 2026-09-05. Public and EXPERIMENTAL commits are assigned by committer date.
2. **Retired subpackages.** These have no component at head, so they are kept as `[retired]` components.
3. **M01g data source.** The MCP tools have no commit-to-PR lookup, so read-only `gh api` GET calls were used. Merged-by and issue-comment columns were added as context.
4. **M02 detection.** The (a)/(b)/(c) categories are kept. A "not determinable" bucket was added for fixes that name no detection mechanism. The introducer is the most-blamed commit, which is a heuristic. Untraceable cases stay in the denominator.
5. **"Same files" for refix chains.** The brief leaves this undefined, so three overlap rules are reported.
6. **"Contract file" for M02a.** The path rule was fixed before sampling. It includes Mission contract documents under `kitty-specs/`.
7. **Events components.** A component is a first-level module or subpackage of `spec_kitty_events`. This is finer than core's subpackages, so values are not comparable in absolute terms.
8. **M01f method.** Edges are taken at file level within the changed files. The run also checks whether a component pair is new to the whole `src/` tree at the parent. Limits are in F-C2-014.
9. **M01f runtime.** The first M01f run was stopped and rerun with per-blob parse caching. The method was unchanged.
10. **Oversized evidence file.** `fix-refixed-within-14d.csv` exceeds 500 KB. A compact copy is committed. The full file's sha256 is `07408c9ebcc8a00287d32a619a857b0bec4c7c52be4b678a3a2ccecc3440eedb`; regenerate it with `script-analyze.txt`.
