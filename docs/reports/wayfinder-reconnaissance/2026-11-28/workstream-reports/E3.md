# Workstream E3: gate runner for controlled mutations

## Profile and directives applied

Profile `reviewer-renata` (role reviewer), loaded with `spec-kitty agent profile show`; charter context for action `review` loaded. Applied: the profile's avoidance boundary (no implementation, no fix proposals), directives 001, 024, 030, 032, 041 and 051 as far as they bear on a read-only run, and from the charter context `NO_FULL_HEAVY_SUITES_IN_MISSION` (named files only) and `USE_MUTATION_TESTING_TO_VALIDATE_TEST_QUALITY` (as the method this workstream executes). No conflict with the envelope arose: the profile forbids rewriting the work, and the envelope forbids the same.

## Method and tools

24 patches from workstream E2 were applied with `git apply`, each in a disposable `git clone --shared` of its repository at `head`, and reverted with `git apply -R`. The gate set was frozen in `evidence/E3/gate-set.txt` (2026-11-28T09:42Z) after reading `evidence/E2/mutations.csv` and before opening any patch body.

## Coverage

Covered: all 24 mutations applied cleanly (24 of 24). 23 were assessed. Not covered: 244 of the 310 architectural test files, although the selection authority selects the whole battery for each of the 15 core diffs; module shards beyond the mirror files; nightly lanes; every Gradle task of the events repository; Checkstyle and the non-ArchUnit `verifyAll` tasks in charter; the charter-service job of open-packs.

## Deviations

1. **Batching.** The machine was under heavy load from other workstreams (one architectural run took 20 minutes), so 13 file-disjoint core mutations were applied together for the architectural set, the layer rules and the mirror tests. Failures were attributed by the file each message names. The three batch members with no failure (M-PI-3, M-PI-5, M-OB-4) were re-run alone on the full set, as were the mirror tests of M-IC-4, M-IC-6 and M-RD-3. M-PI-1 and M-OB-2 ran alone throughout. Lint and types ran per mutation in fresh state. Consequence: for the 8 batch members with a detection, no single-mutation run of the 66 files exists.
2. **Worker count.** `-n 4` instead of the frozen `-n 2` after the resume.
3. **Layer rules alone.** `test_layer_rules.py` was also run by itself, on the coordinator's instruction.
4. **Size of the architectural set.** 66 files, more than "a few dozen", chosen by one regular expression over file names.
5. **Open-packs.** `validate-packs.sh` could not fetch the charter contract (HTTP 404); it ran against the same files taken from the local charter clone at the pinned commit.
6. **Mirror rule.** The name rule picked unrelated files for some patches (for M-OB-3, five `test_finalize_*` files of other modules). They were run as frozen.

Details: `evidence/E3/gate-set-addendum.txt`.

## Blocked items

- Events Gradle build: one attempt, HTTP 429 from `repo.maven.apache.org` at plugin resolution. M-OB-5 is not assessable; the Gradle side of M-IC-3 is not assessed. This is a coverage limit.
- Core service extras were not synced, which gives two identical setup errors in every core run.

## Exploratory observations

These are not answers to a measure and are not in the counts above.

- A battery gate outside the frozen set, `test_charter_path_literal_authority.py`, fails on M-OB-2 and names the file and the literal. With it, 17 of 24 would be flagged by some executed check (F-E3-011, F-E3-017).
- `test_no_dead_symbols.py`, also outside the set, fails on all four core mutations the frozen set missed, each time because the new function has no caller; the message does not name the violation (F-E3-016).
- Both contract breaking-change checks (charter, events) ran with no baseline to compare against; no IC mutation was detected by a compatibility or version check (F-E3-015).
- mypy on touched files raised a new error for 3 of 15 core mutations, all three also caught by an architectural gate; no workflow file names mypy (F-E3-018).
- The open-packs detection of M-IC-5 comes from digest and generated-page drift checks; after regenerating both, three tests still fail on a digest constant held in the test file (F-E3-019).
- Of 52 mirror test files, 16 sit in a shard the patch's own diff selects per change, and 26 sit in directories outside the per-change matrix (F-E3-017).
- Three time-budget tests failed intermittently under load in mutated runs; they were not counted.

Mutated clones, virtual environments and Gradle homes were deleted from scratch; full logs remain under the scratch folder, with their hashes in the `runs-*.txt` headers.
