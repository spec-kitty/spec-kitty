## Method and tools

- One extractor of my own for every revision (`evidence/B1/script-extract.txt`): Python `ast` over `git archive` extracts, CPython 3.13.18, git 2.43.0. It records every import with its position (module level, function body, `if TYPE_CHECKING:`).
- Cross-check: grimp 3.20 and networkx 3.7 in a scratch venv. At head the module set, the edge set and the cycle sizes are identical (1,490 modules, 8,332 edges).
- Lines: physical lines of non-test `.py` files under `src/`. Code lines (non-blank, non-comment) are also in the series.
- Component: each top-level package; for `specify_cli` and `charter` each second-level subpackage, plus one component for the modules in the package root.
- Rename map: `evidence/B1/rename-map.csv`, derived from `git diff -M50%` between consecutive points.
- Executed evidence: a disposable `git clone --shared` at head, uv 0.11.32, CPython 3.11.15 in the clone, `HOME` and XDG directories in scratch.

## Deviations

1. **Gate run (M03a).** The permitted run of `tests/architectural/test_layer_rules.py` was killed by the sandbox memory limit (exit 137, about 2.0 GB resident) while other workstreams held most of the memory. One retry and a run limited to the tests without the pytestarch graph were killed too. Instead I imported the gate's own collector and matcher functions from the test module and executed them in the clone (`boot-33-gate-helper-functions.txt`). They agree with my counts. The five pytestarch `LayerRule` assertions were not executed; my graph, which equals grimp's, shows no edge they would reject.
2. **2026-09 monthly point, both lines.** Both lines end before the month does. The 2026-09 rows for the public and EXPERIMENTAL lines are P3a and P3b; a third row carries the month end of the merged line.
3. **Component unit.** The brief names second-level subpackages. Modules that sit directly in the root of `specify_cli` (25 modules, 9,327 lines) or `charter` (20 modules) belong to no subpackage; they form the components `specify_cli` and `charter`.
4. **Test exclusion.** Files under a `tests/` directory and `conftest.py` are excluded. `specify_cli/review/test_timeout.py` is product code and is kept.
5. **All-imports variant.** It counts import statements only. String-literal dynamic imports (6 at head) are listed separately and are not edges.

## Blocked items

- The pytestarch part of the layer gate: blocked by memory in the shared sandbox. This is a coverage limit.
- `packs/internal` and the service assets were never fetched, so nothing is said about them.

## Limits worth knowing before reuse

- The read or write label in the shared-path measure is co-occurrence inside one function. In a seeded sample of 12 of the 139 write-labelled sites, 6 were writes at the path, 1 probable, 2 ambiguous and 3 not. The construction counts do not depend on that label.
- The import sweep without the pack ran in one process, so a module counts as failing when anything it imports fails.
- Exception use is resolved by name through import statements; a catch of a base class that also catches a foreign subclass is not counted.

## Exploratory observations

These answer no measure from the brief.

- **F-B1-005.** The largest all-imports cycle jumps to about 500 modules at 2026-07, P5 and 2026-09 month end, and back to under 200 at the next point. At those points single function-level imports of the `specify_cli` root package from a lower layer carry the jump.
- **F-B1-025.** Read-style CLI commands wrote agent skill directories into the (scratch) home directory. Which command did so was not isolated.
- **F-B1-026 (interpretation).** For `runtime` and `mission_runtime`, the layer order holds at load time largely because upward imports are deferred: 29 of 30 and 48 of 98 module edges into `specify_cli` exist only inside functions or `TYPE_CHECKING` blocks.
- **F-B1-027 (interpretation).** The built-in pack is a load-time dependency of the Python package in a source checkout.
- With parent-package execution added to load-time edges, cyclic modules stay under 2% at every point (columns `expl_loadpkg_*`).
