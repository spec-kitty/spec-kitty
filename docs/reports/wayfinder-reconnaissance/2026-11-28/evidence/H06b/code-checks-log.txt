def _order_transitions(events: list[StatusEvent]) -> list[StatusEvent]:
    """Sort by ``(at, event_id)``, except that a real ``approved -> X`` follows its approval.

    A non-seed event leaving ``approved`` causally follows the ``-> approved``
    approval it departed, so it must never sort before that approval -- not when
    they share an ``at`` (its ``event_id`` could be smaller), and not when the
    approval carries a LATER ``at`` than the departure (a clock-ahead reviewer, or
    a teammate's approval arriving through ``git pull`` + the union merge driver).
    Otherwise arm (ii) would drop the departure for arriving while the WP is still
    ``in_review`` (spec-kitty-events#87 for the equal-``at`` case,
    spec-kitty-events#101 / spec-kitty/spec-kitty#4941 for the later-``at`` case).
    The later-``at`` case lifts only the departure's SORT ``at`` to its approval's
    (:func:`_approved_departure_sort_at`) and carries it to the same-WP events stamped
    below it (:func:`_carry_lifted_sort_at`); the stored ``at`` is untouched, and the
    un-skewed case is a no-op, so the equal-``at`` behaviour is unchanged.
    """
    approvals = {
        (ev.wp_id, ev.at)
        for ev in events
        if ev.to_lane == Lane.APPROVED
        and ev.from_lane != Lane.APPROVED
        and not _is_reconstruction_seed(ev)
    }
    effective, seq = _carry_lifted_sort_at(events, _approved_departure_sort_at(events))
    return sorted(
        events,
        key=lambda e: (
            effective.get(e.event_id, e.at),
            e.event_id in seq
            or (
                e.from_lane == Lane.APPROVED
                and not _is_reconstruction_seed(e)
                and (e.wp_id, e.at) in approvals
            ),
            seq.get(e.event_id, 0),
            e.event_id,
        ),
    )

**The artefact rule** (open; it ties to [#7266](https://github.com/spec-kitty/spec-kitty/issues/7266), artefact placement):

- **(a) The service gains an artefact operation on the same surface.** A `coordination_ref_commit` unit may carry artefact blobs (path, bytes) beside its rows, committed in the same compare-and-swap commit. - **(b) The non-status kinds move to the PRIMARY partition** (#7266). The coordination branch then carries only the event log, and the kinds are written where PRIMARY artefacts are written today.
- **(c) The CLI commits the non-status kinds itself**, by plumbing, onto the same ref. Rejected: two writers on one ref race; the compare-and-swap detects it, but every race becomes a refusal on one side, and it breaks "one writer" (ADR 2026-10-22-1 D-1).

**Recommendation:** (a) as the default for every kind, so step 4a does not wait on #7266; #7266 may later move a kind to PRIMARY under (b), and that kind then leaves this surface. Whatever is chosen, it is chosen per kind, before step 4a, and no kind is left without a rule.

===== Authority rules =====
## Boundary rule (single source of truth)

Two surfaces, two jobs. They never duplicate each other:

| Surface | Holds | Authority |
|---|---|---|
| `docs/architecture/` + `docs/adr/` | **Decisions & models**: ADRs, C4 diagrams, vision, audits, calibration | Authoritative; changes are deliberate and reviewed |
| The rest of `docs/` | **Consumption**: tutorials, how-tos, reference, context | Reader-facing; narrates and links *up* to architecture |

- **Architecture = decisions & models.** ADRs (under `docs/adr/`), the C4 model, vision,
  audits and calibration are the deliberately changed source of truth.
- **Reader-facing docs link up; they never duplicate architecture narrative.** When the
  two overlap, architecture wins.
- **Vision is an architecture concern.** There is no `docs/vision/`; forward intent lives
  in `docs/architecture/vision/`.
- **Terminology canon lives in the glossary context pages** (see
  [glossary conventions](../context/glossary-conventions.md)). Architecture docs
  *reference* glossary terms; they do not host a second glossary.
- **Module boundaries are owned by code, not prose.** The enforced pair (the
Older era folders remain authoritative for the decisions made in those eras; a later
ADR supersedes an earlier one explicitly, never by silence.
- **Single canonical authority.** Every rule, surface, and identity has ONE owning
  source. Reconcile (extend/reference) existing doctrine rather than add a second
  authority; prefer require-canonical + migration over no-canonical-field fallback
The durable, governing contracts live in [`contracts/`](contracts/README.md);
[`COMPATIBILITY.md`](COMPATIBILITY.md) is the public compatibility policy and the
authoritative version-and-compatibility reference.
- The committed JSON Schemas and conformance fixtures are the single source of truth for the event contract. A language binding is generated from, or tested against, them; no binding is itself the specification.
