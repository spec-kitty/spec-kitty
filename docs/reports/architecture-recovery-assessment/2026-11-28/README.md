# Architecture recovery assessment (2026-11-28)

An assessment and design exercise: which mechanisms of Spec Kitty deserve to remain, what a simpler coherent architecture could look like, what obstructs it, and how to get there in steps. It changes no code, test, rule, CI configuration or existing document, and it starts no remediation.

**Status: complete as a draft for the human architect (2026-11-28).** Nothing is approved; 27 decisions are open. Start with the consolidated report, [report/wtf-should-spec-kitty-4-keep.md](report/wtf-should-spec-kitty-4-keep.md), then [09-open-decisions.md](09-open-decisions.md). The mandate, the architect's rulings, the vehicle and the list of the nine deliverables are in [00-mandate-and-rulings.md](00-mandate-and-rulings.md).

Working material: `needs/`, `mechanisms/` (eight assessments with evidence tables), `duplication/`, `candidates/` (two independent designs), `challenge/` (steelman and challenge), `dispatch/` (every brief as given).

Everything here is a draft for the human architect, who decides.
